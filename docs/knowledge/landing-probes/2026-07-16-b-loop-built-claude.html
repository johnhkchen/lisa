lisa 0.3.0 · captured from a real session

Lisa schedules your ticket DAG so Claude Code agents can work concurrently, in order.

Lisa turns a directory of markdown tickets into a dependency graph, then drives Claude Code agents through a fixed six-phase workflow (Research → Design → Structure → Plan → Implement → Review) for each ticket — scheduling multiple threads at once wherever the DAG allows.

What Lisa does

lisa init

Scaffolds a project: ticket/story/work directories, CLAUDE.md, the RDSPI workflow doc, hooks, and Lisa's own config file.

lisa validate

Checks the ticket DAG before anything runs — catches missing tickets, bad dependency edges, and cycles up front.

lisa status

Shows the DAG as execution waves: what's done, in progress, ready, or blocked, and who blocks whom.

lisa loop

Launches a Zellij session running Lisa's scheduling plugin, which spawns concurrent agent threads for ready tickets.

lisa doctor

Checks that runtime dependencies (Zellij, Claude Code, the wasm build target) are installed before you rely on them.

Rough edges

  1. The wasm target is silently skipped, not failed. lisa doctor reports "skipped (rustup not found)" rather than erroring, and the overall summary still reads "All dependencies satisfied." It's easy to miss that a dependency is incomplete — check for rustup explicitly if you'll need the Zellij plugin built from source.
  2. lisa validate fails hard on an empty project. Running lisa init alone doesn't get you to a working state — validate immediately errors with "no tickets found" until at least one ticket file exists. The error message is precise and actionable, but the two-step ("init, then oh — I also need a ticket") is a small surprise on a first run.
