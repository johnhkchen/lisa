**Scope:** Tier 2 made real. When the resolved seal is `journal`, completion gates on the review disposition plus a journal row that carries **SHA-256 content-hashes** of the ticket file and every work artifact under the ticket's work directory — fail-closed (a hash that cannot be computed blocks completion), tamper-evident (recorded hashes bind the sealed content), and clearly labeled (`seal: journal` on the row, per S-049-01's field). The ticket file's status flip and work-trail retention follow the same atomic-publication discipline the commit path uses, minus the commit. Second half: the honesty rules around the ladder — explicit `[guards] completion = "commit"` hard-fails at preflight when unsatisfiable (never downgrades); `auto` never switches tiers mid-run (a run that resolved commit-sealed and later cannot commit parks via S-049-04 rather than quietly journal-sealing); and the Chromebook-test runbook gains a **no-git fixture leg** so "a bare folder finishes its tickets" becomes a scored sentence.

**Story acceptance:** Fixture tests: journal-sealed completion succeeds in a repo-less project with correct hashes verifiable against the artifacts; corrupting an artifact after sealing makes the recorded hash detectably stale (audit demonstration test); completion with an uncomputable hash blocks with a named reason. Enforce-mode tests: explicit commit + no identity → hard preflight failure naming the remedy; auto + mid-run git breakage → parked completion, not a journal fallback. The runbook diff adds the no-git leg with pass criteria; executing it stays manual and metered per the Chromebook-test discipline.

**Honest boundary:** Journal-sealed is a lesser seal and every surface says so — this story never describes it as equivalent to commit-sealing, and the landing/README copy is untouched here (positioning language belongs to a copy ticket if John wants one). No hash-chaining of the journal itself (a possible future hardening, named not built). Provenance/journal schema changes are additive.
