**Scope:** The completion transaction's Review gate end to end: the Review section of docs/knowledge/rdspi-workflow.md plus the injected agent contract (crates/lisa-cli/src/templates.rs) that must now instruct emission of a structured disposition file alongside review.md; a new disposition parse model in lisa-core (sibling to provenance.rs); and the completion-gating seam in lisa-plugin/src/lib.rs — the review->Done edge in check_artifact_advances (~3104) and auto_complete_review (~3669), both of which currently call request_completion unconditionally on review.md existence.

**Story acceptance:** Given a review.md accompanied by a `block` disposition with a reason, the scheduler leaves the ticket assigned, visible, and operator-actionable, never calls request_completion, never prepares Done provenance, and leaves dependents blocked; given a `pass` disposition the ticket still completes atomically exactly as today; and a missing, malformed, or contradictory (block-reason-with-pass) disposition is refused safely — the ticket does NOT default to Done — with a named operator-visible reason. A deterministic test drives all three cases through the gate.

**Honest boundary:** Everything here is fixture/unit-proven and requires no live provider-behavior harness. The implementation tickets still run on their assigned Codex seats, but that agent execution is not acceptance evidence for the new Review gate. The metered live proof that a real blocking Review is honored end to end is deferred to S-040-03's authorized field report, named there, not hidden in a ticket here.
