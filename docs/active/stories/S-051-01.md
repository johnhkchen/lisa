**Scope:** The two local signals that lied during the 0.4.4 rc train. (1) **De-flake the bounded-runner timeout test.** `bounded_runner_kills_timeout_near_the_configured_deadline` (crates/lisa-cli/src/triage_agent.rs) asserts the runner kills a `sleep 30` child within 3 wall-clock seconds of a 1-second deadline. Under parallel `cargo test --workspace` load that bound blows on scheduling pressure alone — it failed three separate gate runs while the code under test was correct each time, and the humans watching CI learned to retry once. Rework the test so it fails only when the kill path is actually broken (assert the child's observed lifetime, widen deliberately with a written rationale, or isolate from load — research decides), keeping a negative fixture that proves a broken kill path still turns it red. (2) **`just check` runs what CI runs.** The recipe is WASM `cargo check` + workspace tests; CI additionally fails on clippy warnings, so an agent's green `just check` bounced commit 53481ac on an unused import. Add the same clippy invocation CI uses (workspace, all targets, warnings denied) so the one command agents are taught is the whole local bar.

**Story acceptance:** Twenty consecutive full-parallel `cargo test --workspace` runs pass with no bounded-runner failure (demonstrated in progress notes); a deliberately broken kill path (timeout not enforced) still fails the test. `just check` fails on a tree with an introduced clippy warning and passes on the current tree; CLAUDE.md's description of `just check` stays accurate.

**Honest boundary:** No auto-retry anywhere (N2) — the flake fix makes the assertion load-immune, not self-forgiving. No production changes to the triage runner unless research shows the runner itself contributes to the timing spread. The justfile gains a line, not a framework.
