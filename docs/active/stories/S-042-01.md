**Scope:** The completion effect-adapter seam in lisa-plugin: the scattered edge-triggered completion callers (lib.rs:1106 boolean request_completion, check_artifact_advances ~3046, auto_complete_review ~3669, mark_ticket_done ~5093) plus the poll and plugin-load paths, completion-command path normalization, Review-timeout behavior, and the activity/dashboard rendering in ui.rs. Owns feeding typed events into E-041's lisa-core reducer, executing its returned effect commands as the sole launcher of `complete-ticket`, retaining Lisa-project-root versus Git-root identity, deriving eligibility level-triggered, suppressing false finish-up prompts, and surfacing rejection/correlation state. E-041's reducer is consumed read-only.

**Story acceptance:** Every production completion entry point — artifact/poll, stopped, idle, timeout/reload reconciliation, externally-observed Done, manual UI — dispatches a typed event into the reducer, and the adapter is the only code that executes a returned effect (launches `complete-ticket`); the old boolean request_completion path is gone/quarantined and a test fails if a second boolean completion path resurfaces. The generated command uses the discovered Git root for `--path` and Git-root-relative ticket/work paths even when Lisa runs from a nested project; an Arcade-shaped two-level fixture asserts `games/midsummer/docs/...` and fails against the old root-level `docs/...` argv. On every poll and plugin load, an eligible passing Review (current-attempt artifact admission + E-040 pass disposition) with neither pending nor confirmed aggregate state yields exactly one completion request; a blocked or already-pending one yields none. Each named rejection variant and its correlation id renders in the activity/dashboard state. Review timeout emits no finish-up prompt when review already exists and completion is pending or rejected with a visible actionable reason.

**Honest boundary:** Wiring and rendering only, proven by plugin-native unit tests over a stubbed effect executor — zero tokens, no live seat, no real `complete-ticket` process. Durable journalling/idempotency so replay converges on the prior commit is Story B (named there); the `[d]one` operator-authority rework is Story C; the recorded hostile-order regression against the real adapter and the live Codex-seat field run are Story D. E-041's merged reducer is a prerequisite consumed read-only, not modified here.
