**Scope:** A desk has grown around lisa that arranges itself. `rail up` shipped
on 2026-08-13 — one word that puts a station beside every project that should
have one, *"and a strip beside any loop that has lost one"*. `rail desk` reads 26
boards across hosts. A phone over SSH can drive all of it.

Two things lisa does not provide make that harder than it needs to be, and both
are one addition each.

## The board does not say where its run is

`lisa status --json` describes a board completely and says nothing about **where
the run is happening**. The whole envelope:

```
attempts  completion_seal  config  counts  critical_path_length  edge_count
notes  ready  run_summary  ticket_dir  tickets  token_usage  waiting_on_you  waves
```

`run_summary` carries `evidence`, `failed`, `manual_interventions` and three
ticket counts. No session, no pane, no host.

**Lisa knows.** `second_scheduler_refusal` computes `running_here` and
`current_session` and prints them — but only inside a refusal, as prose:

```
look at it with: zellij attach fascinating-drum
```

So the one consumer that most needs it — a bring-up command deciding whether a
loop already has a strip beside it — has to find out by inspecting panes, and a
phone that wants to look at a running board has to guess a session name.

That is the same shape as `T-064-01-01`, which added the client and model to
`config` for the same reason: a fact lisa held, that a consumer had to go around
the envelope to get.

## A board with no GUI cannot be run at all

`lisa loop` needs a controlling terminal — measured, and recorded in
`screen-design`'s `T-014-03`:

```
$ lisa loop --path ~/swe/repos/steer
could not enable raw mode: Os { code: 6, message: "Device not configured" }
Error: zellij exited with status: exit status: 101
```

Every consumer works around it by owning a pane. That is fine on a Mac with
WezTerm running, and impossible on a host that has no GUI at all.

`screen-design`'s `S-016` named that host explicitly: a GitHub Codespace, reached
by `gh codespace ssh`, where the desk can read a board and start nothing. **One
of the six projects the operator described lives there.** The reach exists, the
board is readable, and the run has nowhere to happen.

**Non-goals.** Not attaching. `loop_cmd.rs:65` decided that deliberately and in
writing — *"silently handing the caller somebody else's running board instead is
a different thing than it asked for"* — and that reasoning stands. Not a daemon.
Not restoring processes after a reboot; the desk's own bring-up is explicit that
loops are started deliberately.
