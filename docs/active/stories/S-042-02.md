**Scope:** The durability layer for completion: a completion-generation/idempotency newtype in lisa-core bound to ticket+attempt, threaded through lisa-plugin's Story-A adapter into lisa-cli's `complete-ticket` (commit_transaction.rs CompleteTicketRequest); an append-only completion intent/result journal persisted with publication.rs's atomic sibling-temporary patterns and reconstructed on plugin load; and the bounded CommandInFlight reconciliation deadline. Consumes Story A's adapter seam; does not touch `[d]one` authority or the live harness.

**Story acceptance:** `complete-ticket` carries a ticket+attempt+completion-generation idempotency key and, replayed for the same key after plugin reload, lost command result, duplicate stop, or timeout, discovers/converges on the prior completion commit instead of producing a second — proven by a reload/lost-result/duplicate-stop test asserting exactly one commit and one authoritative Done. The completion aggregate is durably persisted (or unambiguously reconstructed from ticket/artifact/command-result/provenance state) across a simulated plugin restart, and a CommandInFlight state carries a correlation id and a bounded deadline ending in a named retryable/action-required state — never an infinite retry. Exact-path isolated commits, attempt fencing, and backward-compatible provenance are preserved.

**Honest boundary:** Durability and idempotency proven with native tests and simulated reload/loss fixtures — no live provider, zero tokens. The adapter that emits the events feeding this journal is Story A (prerequisite); driving this durability through the real recorded hostile ordering and a live seat is Story D. Reconstruction correctness is proven against fixture durable state, not a live scheduler crash.
