**Scope:** The review-boundary twin of S-049-04, from the 2026-07-17 field incident (T-046-06-03). A reviewer wrote a block disposition in a session's dying moments; the park policy — edge-triggered on a live Running thread holding the current lease — never fired, so the block was **orphaned**: durable disk state said "blocked, operator must decide," but the ticket stayed `phase: review, status: open` — invisible to Waiting-on-you (which requires `status: blocked`), yet still schedulable, so the next loop re-seated a reviewer to re-derive a verdict already on disk, burning one of two seats while a ready ticket waited. Compounding it, the disposition was legacy-format engineering prose ("provide conforming reruns or explicitly amend both acceptance requirements") — an esoteric demand a nontechnical operator can hardly parse, and the exact backlash dynamic Lisa must never create: telling people to build with Lisa and then handing them a jargon wall the first time a guard fires. Two fixes. (1) **Level-triggered parking:** a Block disposition on disk for a review-phase ticket parks it at plugin load and at every poll, regardless of lease currency — the same durable-state re-derivation the completion (pass) path already does — releasing the seat and surfacing the ask; a re-seat never spawns a review thread for a ticket whose current-generation block verdict is already durable. (2) **Plain-ask floor:** every operator surface leads with one plain sentence a bystander can act on ("This ticket needs a decision from you — the full note is below; you can paste it to your coding agent") before any technical prose, structured or not; the review workflow's instructions require asks written for that bystander.

**Story acceptance:** Fixture tests: block disposition written, session dies before the park poll, plugin restarts → ticket parks at load, seat free, Waiting-on-you row present, provenance park row landed; a schedulable pass over a durably-blocked verdict spawns no review thread; an unparked ticket re-reviews normally. Rendering tests pin the plain lead sentence first and the raw reason demoted below the forward affordance, for structured and legacy blocks alike. The preserved T-046-06-03 field disposition text is the regression fixture's source.

**Honest boundary:** No reviewer-quality enforcement beyond the floor — a reviewer can still write a wrong or overly strict verdict; that stays operator-appealable (amend-and-rereview or override, both recorded), exactly how T-046-06-03 was resolved. No change to pass-path completion or unpark flows. The deeper stance question (whether review guards should fire this often at all) belongs to the guard-stance direction recorded outside this epic, not to these two tickets.
