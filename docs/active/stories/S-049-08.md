**Scope:** The stable-0.4.4 hotfix: three defects the release audit confirmed at HEAD, each a promise E-049 makes that its own code breaks. (1) **The identity remedy must cure the state that triggers it.** Doctor's `IdentityMissing` advice ends "rerun `lisa init` and accept the history offer" — but init offers nothing in a born repo and writes only env-scoped identity when birthing an unborn one, so the advertised cure works only where the symptom can't occur. Fix at both ends: accepting the offer on an unborn repo writes the project-local identity (the same explicit acceptance that sanctions the initial commit sanctions this — born repos stay constitutionally untouched), and every remedy string matches its failure variant — `RepositoryMissing` gets the init remedy, `IdentityMissing` gets the two config lines (plus the init line only where init would actually cure), `TransactionUnavailable` gets the dependency remedy, never a blanket paste of all of them. One string source, reconciled with the plugin's `HISTORY_IDENTITY_ASK` copy by sync test. (2) **Applying a proposal is always a recorded operator action — including when it fails.** `lisa proposal apply` currently mutates before it writes provenance; a mid-list failure leaves real changes with no ledger row. Record first (an attempt row before any step), record the outcome (which steps landed, which failed), echo the steps being run at apply time, and correlate Pending proposals to their park generation so a stale proposal neither renders against a newer park nor suppresses fresh triage. (3) **`lisa notes ack` always has a move.** Two active notes on one ticket currently dead-end with "acknowledgment requires an exact generation" and no way to supply one. Bare ack acknowledges the oldest and says so ("Marked the oldest note read — 1 more remains."); `--generation` targets exactly; the jargon error is gone.

**Story acceptance:** Fixture tests: unborn + accepted offer → `git config user.email` resolves locally, doctor goes silent, and the full stall-to-cure path (doctor names gap → operator runs the printed remedy → completion succeeds) passes end-to-end for each variant's printed remedy; a mid-list proposal-apply failure leaves an attempt row, an outcome row naming the failed step, and the sidecar not stuck Pending; stale-park proposal neither renders nor suppresses; double-noted ticket acks oldest with the remaining-count line, `--generation` acks exactly, provenance rows land for each. All remedy/announcement strings pinned; the plugin/CLI remedy copy proven single-source or byte-synced.

**Honest boundary:** Hotfix scope only — no new surfaces, no seal or scheduling changes, and the `lisa status` torn-journal hard-exit stays out (it is a policy question about fail-closed diagnostics, tracked for E-050's audit, not a quiet hotfix). Born repos gain no writes of any kind; the identity fix applies only where the operator's explicit acceptance already sanctions mutation.
