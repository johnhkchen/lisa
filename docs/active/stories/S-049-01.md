**Scope:** The ladder itself. lisa-core gains a `CompletionSeal` concept with two tiers — `commit` (today's atomic-commit gate, unchanged) and `journal` (defined here, implemented in S-049-03) — plus a resolution: `[guards] completion = "auto" | "commit" | "journal"` in `.lisa.toml`, default `auto`. Auto probes the environment at loop start — is there a repo, does `git config user.email` resolve, can the transaction path commit — and selects the strongest satisfiable tier; the resolved tier is pinned for the run and recorded. Explicit `commit` never degrades: an unsatisfiable environment is a hard, named preflight failure stating the missing requirement and the two-line remedy. Explicit `journal` is honored even where git exists. The resolved tier is surfaced everywhere state is read: doctor ("completion seal: commit-sealed (git history)" / "journal-only — finished work is recorded but not undoable"), `lisa status`, and every provenance and journal row gains a `seal` field so an auditor can never mistake one tier for the other.

**Story acceptance:** Unit tests cover resolution across environments (repo+identity → commit; no repo → journal; repo without identity → journal under auto, hard fail under explicit commit, with the remedy string asserted); the tier is pinned per run and appears in doctor/status output and in ledger/journal rows (schema-additive — existing rows without `seal` parse unchanged). A mid-run probe change never silently switches tiers: the mismatch surfaces as a parked completion with an ask (mechanics in S-049-04; the invariant is asserted here at the resolution layer).

**Honest boundary:** This story defines and routes; it does not implement journal-sealed completion (S-049-03), the init history offer (S-049-02), or the park-and-ask failure path (S-049-04). Tier 1 semantics are byte-for-byte today's completion contract. Config parsing follows existing `.lisa.toml` conventions (unknown values are validation errors with actionable text).
