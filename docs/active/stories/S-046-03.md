**Scope:** Make the Linux artifact run on *unknown* Debian. Add `x86_64-unknown-linux-musl` and `aarch64-unknown-linux-musl` to dist-workspace.toml targets and make musl the artifact the shell installer serves on Linux (glibc builds may remain for gnu-specific consumers or be dropped — decided in-ticket by what cargo-dist's installer selection supports cleanly). Move `install-path` from `CARGO_HOME` to `~/.local/bin` so a machine with no Rust stops growing a `~/.cargo`, with the installer printing plain PATH guidance. Bake the managed-runtime sha256 manifest (S-046-02) into the release build. Then repair the stable channel: prepare the checklist and pipeline verification so a stable v0.4.0 can be cut from the E-045-fixed line, ending the skew where `releases/latest` (shell installer) serves v0.3.0 while the brew tap serves rc.8.

**Story acceptance:** `dist plan` lists both musl targets; a built musl `lisa` runs on a Debian bullseye (glibc 2.31) container and `ldd` reports it not a dynamic executable; the CI build-setup still embeds the WASM plugin (non-empty, checked) in musl builds. The installer places the binary in `~/.local/bin` and its PATH note reads in brand voice. After the stable cut, `gh api repos/johnhkchen/lisa/releases/latest` resolves to a version containing the E-045 claim path, and the README one-liner installs it.

**Honest boundary:** Publishing the stable release is John's decision and action — this story delivers the pipeline, the bullseye proof, and the release checklist, and stops there. musl + fat LTO link behavior on CI runners is verified in-ticket, not assumed. No apt/deb work here.
