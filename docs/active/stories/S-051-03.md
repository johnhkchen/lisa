**Scope:** Make the provenance ledger's token columns true. Usage capture is now durable — the Stop hook records to `.lisa/<client>/captures.jsonl` before the stop signal exists (rc.9), and finished sessions rest before retirement so no exit can destroy a capture in flight (rc.9 for Claude, rc.10 for Codex). But the provenance row for a completed ticket is written at completion time, and with rest-before-retire the capture *always* lands after that row — so `tokens_in`/`tokens_out` are now guaranteed null at write time, where they used to be intermittently null (the 2026-07-09 incident's "intermittent join"; both 0718 field legs show all-null columns despite healthy capture files). Build the late join: when a capture appears for a pane and provider session, attribute it to the ticket whose attempt held that pane at that time (the scheduler owns the pane×time history the hook lacks), and record the tokens against the completed ticket — as an append-only correction record alongside the original row, never a mutation of published history. Unattributable captures keep quarantining by session id; define when quarantine drains (attribution evidence arriving late) and when it is terminal.

**Story acceptance:** A fixture that completes a ticket, then lands its capture afterward, ends with the ledger reporting that ticket's tokens (correction record present, original row untouched); a capture with no owning attempt quarantines; a late-attributable quarantined capture drains. Both 0718 field-leg shapes are pinned as regression fixtures: capture-after-completion (the now-normal case) and capture-never (columns stay null, loudly countable, never fabricated). `lisa status` or the dashboard surfaces per-ticket token totals from the corrected view, not the raw first-write.

**Honest boundary:** Never fabricate: a missing capture stays visibly missing — zero is not a substitute for unknown. No mutation of already-published ledger rows (append-only corrections). Cache-split capture for Claude and cost columns stay out of scope; this story is attribution and join, not new measurement.
