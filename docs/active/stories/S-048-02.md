**Scope:** The human side of a parked ticket. `lisa status` (and the dashboard) opens with a **Waiting on you** section when operator-owned parks exist: one line per ticket — the ask, verbatim, brand-voiced — and a one-line hint for world-owned parks ("waiting for the release to appear — Lisa checks on its own"). `lisa unblock <id>` resumes a parked ticket: when a `check` exists it runs first (read-only, with a timeout) and on failure declines in plain words quoting what it saw, never a stack trace; on success (or no check) it flips the ticket back to schedulable. Auto-recheck: at loop start and on the existing timer cadence, world-owned parked tickets run their checks and self-clear on pass — no human touch. Review-phase instructions (crates/lisa-cli/src/templates.rs) teach block-writing agents to author the structured fields, with the language rule stated: one sentence, addressed to a person who didn't do the work, naming the action rather than the subsystem — the 2026-07-16 block reasons quoted as counter-examples.

**Story acceptance:** Fixture tests: a board with one operator park shows the Waiting-on-you line with the ask verbatim and nothing else jargon-bearing; `lisa unblock` with a failing check declines with the plain-words message and leaves the ticket parked; with a passing check it unparks and the next loop seats the ticket; a world-owned park with a passing check self-clears at loop start with zero operator commands. Template tests assert the Review-phase instructions include the ask-authoring rule and schema. Checks run with a timeout and never mutate (asserted via a check that attempts a write in a read-only fixture).

**Honest boundary:** Whether real agents *write* good asks can't be unit-tested — the language rule ships in their instructions, string tests pin the schema, and the field judgment belongs to the next stuck-experience in the field (record it in the landing-probes spirit: quote the first real ask a nontechnical reader sees). No new TUI panes — the dashboard line reuses existing rendering. `lisa unblock` performs no remediation itself; it only verifies and resumes.
