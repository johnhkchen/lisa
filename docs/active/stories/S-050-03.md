**Scope:** The remaining questions Lisa asks that its environment already answers, and the standing bar that stops new ones. (1) **Client autodetect.** An unconfigured `[agent]` resolves by detection: only Codex installed → Codex; only Claude → Claude; both → Claude (the stated default), with doctor and the loop-start line saying which client was chosen and why in one sentence ("Driving Codex — it's the agent installed here."). Today a Codex-only machine defaults to Claude and fails doctor with a missing-binary remedy for a tool the user never chose. Explicit config and `--client` override detection unchanged; N1 holds — detection picks a provider, it never flattens provider differences. (2) **The flag audit.** A knowledge doc inventories every CLI flag, interactive prompt, and config key against the epic's bar: each either documents its working default for the expected user, or carries a one-line written justification for asking (destructive/irreversible per P1, or fintech-grade override). Anything failing the bar gets a follow-up ticket minted, never a silent keep. Fixtures pin the defaults the audit blesses, so the audit is executable evidence, not an essay — and future flags inherit the bar by CI, not by memory.

**Story acceptance:** Fixture tests: PATH with only a codex stub → loop and doctor resolve Codex with the announcement line; only claude → Claude; both → Claude with the line; neither → doctor's existing remedy unchanged; explicit config beats detection. The audit doc lands in docs/knowledge/ with every current flag/prompt/key present (a test enumerates clap definitions and config keys and fails on any row missing from the doc); each blessed default has a pinning fixture cited by name; each justified ask names its justification category.

**Honest boundary:** Detection reads PATH presence only — no version probing, no account state, no network. The audit is a bar and an inventory, not a purge: removals it recommends become their own tickets with their own review. Provider parity work stays at the contract boundary (N1); this story never edits provider adapters.
