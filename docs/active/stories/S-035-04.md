**Scope:** Complete S-035-01's startup foundation with two-stage native assignment. The attempt atomically stores its full assignment text; the shell launcher starts bare Codex or Claude with lifecycle environment and provider flags but no positional ticket prompt. A matching process-start signal moves the seat to `ReadyForAssignment`, then lisa injects a bounded, attempt-tagged chat instruction referencing the assignment file. Provider-specific positive prompt evidence moves `Delivering` to Owned. The second ticket covers a launch truncated into zsh `dquote>`: recover the same physical pane by interrupting incomplete shell input, positively verifying shell readiness, rotating attempt identity, and retrying once. Preserve E-033 graceful provider recycling and E-034 terminal fencing for an unresponsive owned process or failed bounded reset.

**Story acceptance:** Fresh Codex and Claude launch without an inline assignment, surface `Starting`, and move to `ReadyForAssignment` only on matching process start. Lisa then submits a bounded chat reference to the complete attempt-scoped assignment and surfaces `Delivering`; only matching prompt acceptance publishes Owned. Missing chat acknowledgement never produces ownership and resolves boundedly. A deterministic native test and real-Zellij stub harness also force `dquote>`, observe no provider start or ownership, then prove one bounded same-pane reset and two-stage relaunch under a strictly newer attempt lease. No spare is consumed, stale signals/artifacts cannot advance the replacement, and failure terminates visibly without looping.

**Honest boundary:** SessionStart proves only provider readiness; prompt submission/acceptance proves assignment ownership. Shell readiness must be positively observed through a bounded shell-side acknowledgement or equivalent deterministic contract; a timer or blind Ctrl-C plus sleep is not proof. Provider-specific hook payloads may differ (N1), but both must feed the same scheduler states. This slice does not make a truly unresponsive owned provider reusable and does not weaken permanent fencing after bounded recovery fails.
