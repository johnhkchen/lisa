**Scope:** Give feed entries a real age. Entries are logged with no capture of when (`log_activity`, crates/lisa-plugin/src/lib.rs ~3327) and converted to UI with a hardcoded `Duration::ZERO` (lib.rs ~9066), so `format_time_since` subtracts zero from true wall-clock and prints seconds-since-1970 as an age — the field screenshots' `495696h 11m` on every line. Capture wall-clock at the moment of logging (the same `SystemTime::now()` WASI pattern the plugin already uses throughout), carry it to the existing `ActivityEntry.timestamp` field (ui.rs ~299), and render coarse human buckets — "just now", "Nm ago", "Nh ago", "Nd ago" — in place of the `NNNNh MMm` composite. The five-second timer render (lib.rs ~80, ~8637) already recomputes `current_time`, so ages tick with zero new plumbing.

**Story acceptance:** A fresh event renders "just now" and reads "1m ago" once an injected clock passes a minute (unit tests, no sleeps); the feed renders only the four bucket shapes; an entry that somehow carries the epoch-zero timestamp renders a bounded fallback, never a six-digit hour count (pinned negative fixture).

**Honest boundary:** No new time source, and no per-variant surgery on the core `ActivityEvent` enum unless research finds a consumer that needs time inside it — the pairing can live at the log site (N4). No timezone or absolute-clock display; the feed speaks in ages only.
