**Scope:** A native, signed apt channel — the update motion Debian and Crostini users already understand. nfpm (zero-dependency, repackages the tarballs cargo-dist already builds; wired via dist `extra-artifacts` + a custom publish job) produces two debs per release for amd64 and arm64: `lisa` (the CLI, `/usr/bin/lisa`) and the companion `lisa-runtime-zellij` (the pinned no-web static-musl Zellij at `/usr/libexec/lisa/zellij` — the Jellyfin `jellyfin-ffmpeg` model), with `lisa` Recommends-ing the companion. The S-046-02 resolver learns to prefer `/usr/libexec/lisa/zellij` when present, making an apt install fully offline-complete at runtime. Repo hosting on Cloudsmith's OSS tier (default; GPG-signed Pages/reprepro is the zero-cost fallback), with the sources.list + keyring snippet documented in the README's Debian/Ubuntu section.

**Story acceptance:** On a clean bookworm container, adding the repo per the README and `apt install lisa lisa-runtime-zellij` yields `lisa doctor` exit 0 with the runtime resolved from `/usr/libexec/lisa/` and zero network fetches at loop time. Both arches' debs are produced in CI from the same release tag as the tarballs. Repo metadata is GPG-signed and the client instruction uses `signed-by` keyring pinning. `apt upgrade` moves an installed older version forward cleanly.

**Honest boundary:** This is a vendor repo, not the Debian archive — Debian Policy on embedded copies makes archive inclusion a non-goal, and the bundled runtime is precisely the point. Hosting choice (Cloudsmith attribution requirements vs Pages bandwidth limits) is presented with a default but decided by John in-ticket. The stale aur/PKGBUILD and flake.nix are out of scope — noted for a future sweep, not silently blessed.
