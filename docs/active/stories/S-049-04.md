**Scope:** The incident fix, deliberately dependency-light so it lands first. On 2026-07-16 a demo ticket with a valid pass disposition was rejected **35 consecutive times** because the folder had no git identity; the dashboard showed an inscrutable REV stall, the rejection reason read `authority Attempt(AttemptLease { … }) (Artifact, exit Some(1))`, and the failed transaction leaked `.lisa-commit.lock`. Three fixes. (1) **Bounded park-and-ask:** a completion-commit failure whose reason is operator-owned (identity missing, repo unwritable, lock held by a dead process) retries a small fixed number of times, then parks the ticket through E-048's existing machinery with a plain, forwardable ask — "Lisa needs a name for recording finished work; run: `git config user.name … / user.email …` — or rerun `lisa init` to let Lisa keep history itself." (2) **Legible reasons:** the journal's rejection rows keep the full technical detail, but the reason shown on any operator surface leads with the plain sentence. (3) **Lock hygiene:** the commit transaction releases `.lisa-commit.lock` on every failure path, and a stale lock from a dead process is detected and named rather than compounding the stall.

**Story acceptance:** A replay regression built from the preserved field journal (docs/active/work/T-046-06-03/cbt-0716-211915-variant-xdg/demo-completion-journal.jsonl): under the new policy the same environment produces exactly one bounded retry sequence, one park with the identity ask, zero further attempts, and no lock left behind. Fixture tests cover each failure classification (identity, permissions, stale lock) mapping to the right ask; an agent-transient git failure (e.g. index contention) still retries within bounds without parking. Park/unpark rows land in provenance per E-048's schema.

**Honest boundary:** Reuses E-048's parking, ask, and unblock surfaces — no new state machinery. Failure classification is conservative: unrecognized git errors stay technical-but-bounded (park with the raw reason as the ask, flagged unstructured) rather than guessing. This story does not change what a successful completion does on either seal tier.
