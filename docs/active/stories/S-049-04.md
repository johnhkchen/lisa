**Scope:** The incident fix, deliberately dependency-light so it lands first. On 2026-07-16 a demo ticket with a valid pass disposition was rejected **35 consecutive times at diagnosis — 80 by journal preservation** in a folder with an unborn branch and no git identity; the dashboard showed an inscrutable REV stall, the rejection reason read `authority Attempt(AttemptLease { … }) (Artifact, exit Some(1))`, and the failed transaction leaked `.lisa-commit.lock`. The 2026-07-17 forensic pass corrected the diagnosis: every journal row carries the same fatal step — the prior-completion-key lookup (`git log --grep`) exits 128 on a branch with no commits and is treated as fatal, firing before identity is ever consulted. Three fixes. (1) **Bounded park-and-ask:** a completion-commit failure whose reason is operator-owned (unborn branch, identity missing, repo unwritable, lock held by a dead process) retries a small fixed number of times, then parks the ticket through E-048's existing machinery with a plain, forwardable ask — "Lisa needs a name for recording finished work; run: `git config user.name … / user.email …` — or rerun `lisa init` to let Lisa keep history itself." The same rule closes the one completion state with no exit today: a reconciliation-deadline expiry (`Rejected{ActionRequired}`) parks with an ask instead of masking Done, refusing operator MarkDone, and leaving no reset path. (2) **Legible reasons:** the journal's rejection rows keep the full technical detail, but the reason shown on any operator surface leads with the plain sentence. (3) **Transaction hygiene:** the commit transaction releases `.lisa-commit.lock` on every failure path, a stale lock from a dead process is detected and named rather than compounding the stall, and the prior-completion-key lookup treats empty history as "no prior completion" (`Ok(None)`), not a fatal error.

**Story acceptance:** A replay regression built from the preserved field journal (docs/active/work/T-046-06-03/cbt-0716-211915-variant-xdg/demo-completion-journal.jsonl): under the new policy the same environment — unborn branch, no identity — produces exactly one bounded retry sequence, one park with a plain history/identity ask, zero further attempts, and no lock left behind. Fixture tests cover each failure classification (unborn branch, identity, permissions, stale lock, deadline expiry) mapping to the right ask; an agent-transient git failure (e.g. index contention) still retries within bounds without parking; a deadline-expired completion is recoverable by an operator through the ordinary unpark path. Park/unpark rows land in provenance per E-048's schema.

**Honest boundary:** Reuses E-048's parking, ask, and unblock surfaces — no new state machinery. Failure classification is conservative: unrecognized git errors stay technical-but-bounded (park with the raw reason as the ask, flagged unstructured) rather than guessing. This story does not change what a successful completion does on either seal tier.
