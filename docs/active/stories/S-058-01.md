**Scope:** Of the three lease-bearing hooks Lisa writes into a project, one does not check who is
calling it. `ON_HEARTBEAT_HOOK` (`crates/lisa-cli/src/templates.rs` ~222–238) copies
`.lisa/signals/pane-<id>.lease` into `pane-<id>.heartbeat` on the strength of two tests: that
`LISA_PANE_ID` is set, and that the marker is readable. It never compares the marker against the
calling process's own `LISA_TICKET_ID` / `LISA_ATTEMPT_ID`. `ON_START_HOOK` twelve lines above it
does exactly that comparison, and refuses when it fails.

So any process that can run a tool call in a Lisa pane can publish a heartbeat naming whatever
attempt the marker currently holds — including an attempt that is not its own. The scheduler
admits that heartbeat on the lease it carries, because the lease is the only identity the signal
has.

**Why this is a story and not a footnote.** Two independent reviews found this while judging the
0.5.0-rc.2 scheduler work, from opposite directions, and both recommended fixing it *separately*
from that change so the two are independently revertable. rc.2 also made the exposure longer: the
same-pane reset now retains the pane lease marker for the whole reset window so a slow provider can
still announce itself, and on 0.5.0-rc.1 and earlier that window had no marker at all. rc.2
contains the consequence in the scheduler — a heartbeat inside the reset window proves residency
and nothing else; it moves no clock and lifts no `AskUserQuestion` guard
(`check_heartbeat_signals`, `crates/lisa-plugin/src/lib.rs`). That is containment, not a fix. The
signal is still forgeable; the scheduler has simply stopped believing the forgeable part of it in
the one window where forging is easiest.

**The tension that makes this non-trivial, and the reason it was deferred rather than bundled.**
Hardening the hook the obvious way — copy the ON_START_HOOK guard verbatim — would darken the
densest evidence source the new exit policy depends on. rc.2 holds a pane past the exit grace while
it is still emitting provider hooks, because a hook is the one thing only a running process can
produce. But during a recycle, once the *successor's* marker is published, a still-resident
*predecessor* no longer matches it, so a hardened hook would fall silent exactly when the scheduler
most needs to know that the old TUI is still sitting there. The naive fix trades a forgery surface
for a regression in the fix that shipped alongside it.

That is the shape of the problem: residency and authority are two different questions, and this
hook currently answers both with one file. A heartbeat should be able to say *someone is here*
without also being able to say *and I am attempt 4*.

_Advances P2 — state means what it says: a lease-bearing signal should mean the process that wrote
it holds that lease. And P5 — the two field runs that produced this were on `tabular-recipes`,
where the forged surface sat behind a real fenced pane._
