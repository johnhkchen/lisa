**Scope:** Spend node width on information. (1) **Paint the status.** `render_dag` computes a status color per ticket (ui.rs ~816–828) and the post-processor throws it away (`(phase_color, _status_color)`, ~833), so `BLK`/`WRK`/`RDY` render unpainted. Apply it. This is also condensed mode's prerequisite: color is the only place status survives once the token goes. (2) **Condense when it counts.** Thread the true pane `cols` through to the DAG path (the dispatch at ~1253 passes none today, and what renderers do see is pre-clamped to 100, ~1669 — the clamp must not gate the DAG); render full labels, measure the widest raw line, and when it exceeds the pane re-render once with condensed labels — `T-` prefix and status token shed, `[T-015-04-02 RDY]` → `[15-04-02]`, status carried by the freshly painted color (recolor vs a one-glyph marker is design's call; pinned: blocked/working/ready distinguishable at a glance). A board that fits keeps today's full labels — no premature condensing. When even condensed spills, emit one plain indicator line naming the overflow (and, once S-054-02 lands, the pan keys); never clip silently.

**Story acceptance:** Status tokens render in their mapped colors on the full view (unit test on post-processed lines). Forced-width tests: a wide pane keeps full labels; a narrow pane flips to condensed and the same graph fits or shows the indicator; measurement counts visible columns only (colored fixtures measure identical to uncolored twins). Condensed labels contain neither `T-` nor a status token, and design.md records how status classes stay distinguishable.

**Honest boundary:** ascii-dag stays the layout owner — labels, measurement, and an indicator line are the whole surface (N4). No config knob for the threshold: the pane width is the threshold. Full mode's information is never reduced — condensing only ever triggers on overflow.
