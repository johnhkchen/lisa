**Scope:** The severity dial. Today the disposition is binary — `pass` or `block`, fail-closed — so a reviewer with any doubt has exactly one move: pull the cord and summon the human. The E-046 closing incident showed the cost: a 75 MiB gap between acceptance text and recorded measurement — paperwork drift, not defective work — stopped the epic's final ticket and context-shifted the operator into jargon. This story adds the third class, **done-with-a-note**: valid *only* when the reviewer's dispute is with the criteria text versus the recorded evidence, never with the work itself. A note disposition seals the completion exactly like a pass — status flips, dependents flow, the seal tier applies unchanged — and files one structured note (the disputed criterion quoted, the evidence cited, a plain one-sentence summary) into a batched **Notes for you** queue. Notes gate nothing. The queue is a calm surface: `lisa status` shows a count and the plain summaries under their own heading, clearly separate from Waiting on you ("the line kept moving — here's what it wants you to know" vs "the line needs you"); notes are settled by an operator acknowledgment that lands in provenance, or graduate into ordinary tickets if the operator decides the dispute is real work. Fail-closed integrity holds: bare `pass` stays strict, a note missing its citations is Invalid, and any doubt about the work itself remains a block — the note class is a severity level, never a hedge.

**Story acceptance:** Fixture tests: a note disposition completes and seals identically to a pass (same journal/ledger rows plus a `note` record with citations), dependents schedule immediately, and the note appears batched in status under Notes for you with the plain summary first; a note without the criterion quote or evidence citation parses Invalid (fail-closed, existing behavior for the ticket); a work-quality complaint written as a note is not expressible in the schema (no free-form "the work is wrong" field to abuse — the schema forces criterion + evidence). Acknowledgment writes a provenance row and clears the queue entry. The T-046-06-03 field block, re-expressed as a note, is the fixture: under this story that incident is one sealed ticket and one queue line, zero stalls.

**Honest boundary:** The reviewer still chooses the class — a reviewer that wrongly blocks instead of noting is corrected by S-049-07's triage and the workflow's authoring guidance, not by this schema. Notes do not modify acceptance text or any board file; deciding the dispute stays human (or graduates to a ticket). No change to pass or block semantics.
