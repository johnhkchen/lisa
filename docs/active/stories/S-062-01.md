**Scope:** `lisa loop` lays the agent panes out as a zellij **stack**, so exactly
one of them is expanded and the rest are collapsed title bars:

```kdl
tab name="lisa" {
    pane stacked=true size="70%" {
        pane
        pane
        pane
        pane
    }
    pane size="30%" { plugin location="…lisa-plugin.wasm" { … } }
}
```

Four panes because `pane_count = config.max_threads * 2` — *"extra idle panes
absorb new tickets while finishing panes wind down"* — which is a good reason and
is not what this story wants changed.

**What the operator does, and what they get.** They focus the plugin pane at the
bottom and press `v` to reach the DAG view. That leaves the stack expanded on the
**fourth** pane, which with `max_threads = 2` is a spare that has almost never
held a ticket. Seventy percent of the tab is showing an idle shell, and the two
conversations that are actually working are collapsed to title bars behind it.

In their words:

> *"I would like lisa to put active conversations on the top of the stacked view
> of claude code panes within zellij."*

**Why it is worth a ticket rather than a keystroke.** It is not that the operator
cannot cycle the stack — it is that the default view of a running loop is the one
pane guaranteed to have nothing in it. The 70% pane is the loop's whole face, and
it faces away.

**The trap already recorded, two lines above the pane count.** A previous attempt
pinned expansion in the layout:

> *"No `expanded=true`: zellij expands the focused (first) pane by default, and a
> hardcoded expanded attribute gets re-applied on every terminal resize, snapping
> focus back to the first pane."*

So a layout-level answer has been tried and it made the operator's focus jump on
every resize. Whatever fixes this cannot be a static attribute.

**What the operator asked for, decided rather than assumed.** Two questions were
put to them and these are their answers:

- **Focus is never moved.** The expanded member may change only while the
  operator's focus is *outside* the stack. If they are inside it — reading a
  conversation, scrolled back — lisa leaves the stack alone entirely.
- **Most recently active wins.** Whichever pane last produced output is the one to
  show. It flips often with two agents running, and that is acceptable
  *because* of the rule above: the churn happens while nobody is looking, and the
  stack is correct the moment they look back.

**Non-goals.** Not changing the pane count or the `2 × max_threads` reasoning.
Not a static `expanded=true`. Not moving focus, ever — that is the failure this
story must not reintroduce.
