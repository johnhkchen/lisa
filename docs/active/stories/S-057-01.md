**Scope:** Lisa's ticket lifecycle asks a coding agent for six artifacts. Five of them are
written before the work exists, and nothing ever reads them. This story deletes the four that are
pure speculation, retires the practice of Lisa scaffolding a project's agent context file, and
renames the workflow document to match what it now describes.

Two premises, both about what frontier coding models became during 0.4.x.

**(1) Pre-work artifacts stopped buying scope and started buying noise.** Research, Design,
Structure and Plan each demand ~200 lines of prose *before* a line of code exists
(`crates/lisa-cli/data/rdspi-workflow.md` ~7–37). When planning phases were what expanded how
much work a model would undertake in one pass, that was a trade worth making. It is not the trade
any more: the models plan inside the turn, and the artifacts persist as a work surface that no
mechanism can check. A reviewer, a CI job, or a tool like Greptile can grade a diff, a commit, or
an exit code. None of them can grade `design.md`. Every one of those files that lands in
`docs/active/work/` is unfalsifiable text competing for a human reviewer's attention with the
diff that actually shipped.

The code already agrees, which is the discovery that makes this cheap. `progress.md` is admitted
for durability and then explicitly excluded from phase advancement —
`crates/lisa-plugin/src/lib.rs` ~5999 says so in a comment ("never use it as a phase edge"), and
~6000–6008 routes Implement's edge through `review.md` instead. Trace the rest and the same
picture holds: the only artifact whose appearance carries a scheduling decision anyone depends on
is `review.md`, and the only artifact anything *parses* is `review-disposition.json`. The four
phases being deleted are edges on files that exist to be written, not to be read.

**(2) Scaffolding a project's context file is not Lisa's business.** `lisa init` writes
`CLAUDE.md` and `AGENTS.md` into the repository root (`crates/lisa-cli/src/init.rs` ~356–384),
`lisa loop` refuses to start without `CLAUDE.md` (`crates/lisa-cli/src/loop_cmd.rs` ~59–60), and
the assignment prompt instructs every agent to read it (`crates/lisa-plugin/src/lib.rs` ~146,
via `AgentClient::context_file()` in `crates/lisa-core/src/client.rs` ~62–68).

The prompt instruction is redundant on its face — Claude Code loads `CLAUDE.md` natively, and
Codex loads `AGENTS.md` natively; naming the file in the prompt adds no information the client
did not already have. What it does add is the impression that Lisa owns the file. That is the
part worth removing on principle rather than on redundancy: a context file is where a project
states its own standing intentions to every model that will ever read it, and a scheduling tool
that seeds it with generated boilerplate is putting a thumb on a scale it has no business
touching. Lisa's job is to get a capable model to the work at low friction, not to pre-load it
with opinions the operator did not write. Lisa keeps exactly one document of its own — its
operating contract, under `docs/knowledge/` — and writes nothing else into a project it did not
create.

**Story acceptance:** A ticket board runs `ready → implement → review → done`. A ticket whose
frontmatter still says `research`, `design`, `structure` or `plan` loads and resolves to
`implement`, so an existing board survives the upgrade without hand-editing. The only artifacts a
ticket produces are `review.md` and `review-disposition.json`. `lisa init` creates no file in the
repository root but `.lisa.toml`, and `lisa loop` starts in a project that has no `CLAUDE.md`.
The assignment prompt names no context file. Lisa's own contract lives at
`docs/knowledge/lisa-workflow.md`, and a project holding an unmodified `rdspi-workflow.md` is
migrated to it.

**Honest boundary — what this costs.** Phase Rule 5 of the outgoing workflow document calls the
artifacts insurance, and it is telling the truth: a session that dies mid-ticket is reseeded at
the correct phase because the artifacts are on disk. Collapsing to one working phase gives that
up. The replacement is commits — `lisa commit-ticket` is already per-ticket, already serialized,
already exact-`--include`, and unlike `plan.md` a commit is a surface a machine can read. That
replacement is real in commit-sealed projects and **absent in journal-sealed ones**, which have
no commits to resume from. A journal-sealed ticket that dies mid-work now restarts from the
beginning. This is a known, accepted regression for this cut; it is named here so it is found in
the release notes rather than in the field, and closing it is out of this slice.

**Out of this slice:** the version bump and release mechanics (`docs/knowledge/release-checklist.md`
owns those). Any change to the disposition schema, the check-execution contract, or the
`remedy_owner` vocabulary — S-056-01 just pinned those and they are the half of the workflow that
was always checkable. Any change to the scheduler, the DAG, the seal, the commit transaction, or
the parking system. Restoring resume for journal-sealed projects. Whether *this* repository keeps
a hand-written `CLAUDE.md` — it may; the change is that Lisa stops generating one.

describe a settled system: it is the file an operator reads to understand what Lisa now does, and
writing it before its subject exists is exactly the failure mode this story is about.

touch `docs/knowledge/` files that are field notes or runbooks.
