**Scope:** The epic's acceptance instrument — a manual, human-operated protocol proving that a *low-end* coding agent (Haiku-class via claude CLI, mini-class via codex CLI) on a hostile stock Debian container can install a working Lisa driven only by the README. Deliverables: the fixture Dockerfile approximating stock Crostini bookworm (curl, ca-certificates, sudo, node + the two agent CLIs; deliberately **no** git, no Rust, no build tools), the runbook at docs/knowledge/chromebook-install-test.md (protocol, agent matrix, verbatim instructions, pass criteria with negative assertions, seeded-failure variants, results template), and two recorded runs: the **baseline** against today's README (expected to fail — that failing record is the preserved field evidence) and the **closing** run after S-046-01…04 land (must pass, and gates epic close). John operates the runs; agents get no human help between instruction and outcome.

**Story acceptance:** The runbook is followable end-to-end by John without asking anything of this repo's authorship context. The baseline run is recorded with full findings (what the agent tried, where our text sent it, wall time, artifacts left behind). The closing run passes on the primary matrix: `lisa doctor` exit 0 and `lisa loop --dry-run` clean in a scaffolded project, ≤ 10 minutes, disk delta within the runbook's calibrated bound (300 MiB with recorded composition — recalibrated 2026-07-16 from the real closing legs), and every negative assertion holds — no rustc/cargo/rustup present afterward, no compiler invoked, sudo/apt actions recorded and boring. At least one seeded-failure variant (ancient Zellij 0.40 on PATH) shows either the agent recovering using only Lisa's own error strings or the hazard unreachable by default (managed-runtime resolution leaves the old binary unconsulted — the 2026-07-16 recorded variant shows the latter, the stronger outcome).

**Honest boundary:** Manual and metered — real agent tokens, real installs, a human at the wheel; results are evidence documents in docs/knowledge/, never a default cargo test (same posture as the live Codex boundary harness). The fixture approximates Crostini (no ChromeOS VM, no sommelier, package set unverified against a real device — flagged in the runbook); it is a stand-in until someone runs the protocol on real hardware. The runbook was seeded 2026-07-16 in this working session; T-046-06-01 hardens it against whatever the first real spin-up teaches. Headless automation of the protocol is explicitly deferred — worth its own story only after the manual loop has taught us what to assert.
