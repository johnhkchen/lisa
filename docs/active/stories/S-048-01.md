**Scope:** The block itself becomes structured and the scheduler starts believing it. The review-disposition contract (crates/lisa-core/src/disposition.rs) gains optional fields on `block`: `remedy_owner` ("agent" | "operator" | "world"), `ask` (one plain-language sentence addressed to a person who didn't do the work), `steps` (optional short list of concrete actions/commands), and `check` (optional read-only shell probe that exits 0 when the remedy has happened). Parsing stays fail-closed and gains a churn-safe default: a block missing structure is treated as operator-owned with the raw reason as its ask, flagged `unstructured` — never dropped, never unboundedly retried. Scheduler policy (crates/lisa-plugin/src/scheduler.rs): agent-owned blocks get bounded re-attempts (small fixed count per loop) then park; operator- and world-owned blocks park immediately — `status: blocked` (the dag.rs:197 exclusion, formalized) with the structured block carried alongside; world-owned parked tickets are recheck-eligible. Provenance records park/unpark transitions with timestamps so stranded-time is queryable.

**Story acceptance:** Unit tests over the extended disposition: all three owners parse; malformed/missing structure → operator-owned + unstructured flag; `check` content is never executed at parse time. Scheduler tests replay the 2026-07-16 shape — a two-seat board with one operator-owned and one world-owned block plus ready tickets — and assert: both blocks park, neither is ever re-seated, the ready tickets get both seats, and the agent-owned case retries exactly its bound then parks. Provenance rows for park/unpark appear with durations.

**Honest boundary:** No CLI or dashboard surface here (S-048-02), no auto-recheck execution (also S-048-02 — this story only marks recheck-eligibility), no changes to completion, leases, or Done-writing. Parking is scheduling visibility, not a state-machine rewrite. Schema is additive — existing plain `{disposition, reason}` blocks keep parsing exactly as today, plus the churn-safe default.
