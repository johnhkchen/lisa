**Scope:** The epic's principle applied where it hurts most: first contact. (1) **Init decides the history question.** A fresh-folder `lisa init` with no flag no longer errors: when the machine can keep history, it does (the recommended choice), announcing "Keeping project history — finished work will be undoable."; when it can't, it falls to the journal, announcing the consequence line. The interactive prompt keeps its offer, but accepting on a machine without git falls to the journal with the same line instead of hard-failing (the trap the 0.4.4 release audit found: empty input defaults to yes, then dies). `--with-history` / `--no-history` remain as pure overrides — `--with-history` on a git-less machine is the one case that still errors, because the user explicitly asked for something the machine cannot do (N2: named, actionable, no silent downgrade of an explicit request). README and the Chromebook runbook simplify back to teaching bare `lisa init`. (2) **No dead-end surfaces.** Any Lisa command run before init tells the user the one thing to do ("This folder isn't set up yet. Run: lisa init"); `lisa notes` on an empty queue says "Nothing to read."; the Waiting-on-you section's absence is itself legible in status; `lisa validate` on a board with no tickets explains what a ticket is and where it goes rather than bare-erroring (the Chromebook grader had to seed a smoke ticket to get a scorable exit — that workaround becomes unnecessary).

**Story acceptance:** Fixture tests: fresh folder + git present + no flag → repo, identity, initial commit, commit seal, the announcement line verbatim; fresh folder + no git + no flag → journal seal, consequence line, exit 0; explicit `--with-history` without git → named error with remedy; interactive accept without git → journal fallback line, exit 0; existing repos byte-untouched in all paths (T-049-02-01's snapshot fixtures extended, not weakened). Pre-init commands and empty surfaces string-pinned. README Quick Start and runbook prose show bare `lisa init` again, with flags documented as overrides.

**Honest boundary:** The safety rules do not move — everything auto-decided is new-to-this-folder; born repos, existing identities, and existing configs stay constitutionally untouchable. The interactive prompt's wording stays within T-049-02-01's no-"git"-on-the-offer-path rule. This story does not touch the seal ladder's semantics, only the path into them.
