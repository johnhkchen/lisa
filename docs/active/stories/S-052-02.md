**Scope:** Make one fact cost one line. (1) **Stop the noise at the source.** "Skipping {}: thread already exists" is an Info logged inside `schedule_ready_tickets` (lib.rs ~4934), which runs on nearly every event (permission grant, PaneUpdate, timer poll, three RunCommandResult arms) — so a healthy in-flight thread re-reports once per pass, indefinitely: the "successfully underway thread doesn't need to get reported over and over" complaint verbatim. A recurring no-op is not operator news — demote it out of the feed and give it its own berth in the Shift+D dump, whose event record today is this same 100-entry ring (~8098). Likewise one phase transition currently emits both `PhaseCompleted` and `TicketPhaseChanged`, and the UI projection maps *both* to a "completed" line (lib.rs ~9080–9091), from any of three detectors — after this story, one transition is exactly one line no matter who observed it. (2) **Fold what legitimately recurs.** When an incoming event renders identical to the newest entry, bump a count and refresh its stamp instead of appending; the line carries an (x2)/(x3) tag. The 100-entry ring (lib.rs ~960) then holds 100 distinct facts instead of fourteen facts times seven.

**Story acceptance:** A scheduling pass over a board whose candidates all have live threads appends zero feed entries; each of the three transition paths (artifact, idle, completion) yields exactly one line per transition (counted in unit tests); three identical consecutive events render one line tagged (x3) carrying the latest age, and a different event between them breaks the fold.

**Honest boundary:** Demotion is not erasure (P2): skip decisions remain reachable in the state dump via their own berth. No severity/logging framework (N4). Folding is append-time bookkeeping, not a render-time rescan — the UI projection stays pure.
