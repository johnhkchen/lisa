**Scope:** In TPS the andon cord works because a pull summons a team lead in seconds — someone whose job is triage — and the line stops only when they can't resolve it. Lisa's solo operator is currently line worker, team lead, and customer at once. This story gives the cord its first responder, and hardens dispositions at the source. (1) **Triage before the human:** when a review block parks operator-owned, a bounded agent triage pass runs before (or as) the park surfaces: it reads the block, the ticket, and the cited evidence, and attaches a **proposal** to the parked state — a plain one-sentence summary of what happened, a recommended action, and the prepared commands or file edits the operator would approve — so Waiting on you leads with "The checker found the paperwork says 200 MiB and the measurement says 225 MiB. Suggested: update the paperwork to the measured bound," followed by ready-to-paste steps, not an excavation. The 2026-07-17 manual resolution of T-046-06-03 (agent reads jargon → checks evidence → discovers the remedy is a two-sentence amendment → operator says "go ahead") is precisely the ritual made built-in. Triage is fail-open: if it errors, times out, or is disabled, the park proceeds with the plain raw ask exactly as S-049-05 ships it — triage may never delay or gate a park. Triage proposes; only the operator disposes. (2) **Valid at the source:** the review phase validates its own disposition before the reviewer finishes — a CLI check (schema, class rules, ask floor) the workflow instructs the reviewer to run, so malformed or legacy output is caught in the reviewer's pane where it is cheap to fix, and the coercion fallback becomes a rarity instead of the norm.

**Story acceptance:** Fixture tests: an operator-owned park gains a proposal record (summary, recommendation, prepared steps) rendered ahead of the raw reason in status and dashboard; a triage failure produces the unmodified S-049-05 park (asserted: no delay, no gate, plain ask intact); proposal provenance rows land, and applying a proposal is always an explicit operator action recorded as such. Disposition validation: the CLI check rejects malformed schema, a note without citations, and an ask-floor violation, each with a pane-visible message naming the fix; the workflow doc instructs the check in the Review phase; the bundled-copy sync test passes. The T-046-06-03 field block is the triage regression fixture: fed to triage, the produced proposal must name the criteria-vs-evidence gap and recommend the amendment — the incident's manual resolution, reproduced mechanically.

**Honest boundary:** Triage runs on the operator's configured agent seats and budget — bounded attempts, visible in provenance like any attempt; no hidden background spend. Proposals are advice with prepared steps, never auto-applied; a wrong proposal costs the operator one dismissal. Reviewer-quality itself (choosing block vs note wisely) is guidance plus this validation floor, not enforcement. No new disposition classes beyond S-049-06's.
