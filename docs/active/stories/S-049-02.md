**Scope:** The Zellij play applied to git: Lisa brings history instead of demanding it, and the word "git" never appears in copy aimed at someone who didn't choose git. Two surfaces. (1) `lisa init` in a folder with no repository offers project history in kitchen-table terms — undo for finished work, plus a record of what the agents did — and on acceptance (or via `--with-history` / `--no-history` for non-interactive runs) creates the repository and a **project-local** identity, `Lisa (project history) <lisa@project>`, itself. Folders already inside a repository are left exactly as found; existing identities are never modified; declining leaves the project on the journal seal with that consequence stated. (2) `lisa doctor` gains the identity preflight the 2026-07-16 stall proved missing: when a repo exists but `git config user.email` doesn't resolve, doctor names it before any ticket runs, with both remedies — the two `git config` lines for people who have an identity, or the project-local offer for people who don't.

**Story acceptance:** Fixture tests: init in a bare folder with acceptance → repo exists, local identity set, first commit possible, tier resolves to commit-sealed; with decline → no `.git`, tier resolves to journal with the consequence line in output; init inside an existing repo (with and without identity) → repository and global config untouched, doctor reporting the identity gap in the latter case with both remedies asserted as strings. All new copy passes the brand-voice rule: action-first, no "git" jargon on the offer path (the word may appear in the parenthetical remedy for users who already have git).

**Honest boundary:** The offer creates history for Lisa's bookkeeping — it does not configure the user's global git, push anywhere, or claim authorship of the user's own edits beyond what commit identity implies (the identity string says "Lisa (project history)" precisely so an auditor reads it correctly). Interactive-prompt plumbing reuses whatever init already has; if init is non-interactive today, the flags are the contract and the prompt is a fast-follow noted in the ticket, not silently absorbed.
