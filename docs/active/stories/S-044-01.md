**Scope:** crates/lisa-cli/src/main.rs only: the top-level `#[command]` on the `Cli` struct (help template / before-help / after-help), the display_order/hide knobs and `about` doc-comments on the `Commands` enum's operator commands (Init, Validate, Status, Doctor, Loop) and the four visible plumbing commands (AgentExec, CaptureUsage, CommitTicket, CommitTicket, CompleteTicket), plus a new help-surface snapshot test under lisa-cli. The `match cli.command` dispatch and every command's runtime behavior are untouched — only Clap help metadata and copy change.

**Story acceptance:** `lisa --help` opens with a short orientation naming the everyday path (init → validate → status → loop) and no longer interleaves the four agent/hook-invoked plumbing commands with the five operator commands; `lisa <cmd> --help` for each operator command prints a plain, verb-forward purpose plus a concrete usage example; and `cargo test -p lisa-cli` includes a snapshot assertion that fails if a plumbing command re-enters the operator list or an orientation/example line is dropped.

**Honest boundary:** Copy is curated against exactly the five operator and four plumbing commands present in main.rs today — no new subcommands, flags, man-pages, or shell-completions are added (the `--version`/Clap wiring already emits). The final wording is settled during implementation against the brand voice, not frozen in this plan. Verification is a deterministic snapshot of help output: FREE, no tokens, no live run.

## DAG

```
T-044-01-01  orient-and-separate-help
T-044-01-02  verb-forward-command-help-and-examples  ← T-044-01-01
```

Wave rationale: The two tickets run as a linear chain, not in parallel, because both edit the same `Cli`/`Commands` definition in the single file main.rs and concurrent edits would collide on shared struct attributes. T-044-01-01 settles the help structure first — the orientation template and the operator/plumbing separation — because the per-command copy and examples in T-044-01-02 layer onto that settled shape and extend the same snapshot harness it introduces.

**Out of this slice:** No changes to command behavior, argument parsing, dispatch, or scheduler transitions (respects N3 — help orients, it does not substitute for correct transitions); no new subcommands or flags; no man-page or shell-completion generation; no reshaping of the already-hidden guides (SetupGuide/HooksGuide/Version) beyond leaving them hidden; and nothing in the WASM plugin dashboard/UI.
