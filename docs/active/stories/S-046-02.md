**Scope:** Lisa owns its Zellij. A runtime resolver with three modes — explicit path pin in `.lisa.toml` (`[runtime] zellij = "/path"`), `"system"` opt-in (must pass the S-046-01 range check), and the default `"managed"` — decides which Zellij binary `lisa loop` execs. Managed mode fetches the pinned **no-web static-musl** Zellij matching the compiled zellij-tile minor from Zellij's GitHub releases, verifies it against a sha256 **baked into the Lisa binary at release time** (never fetched), and unpacks it atomically (temp + rename) into `$XDG_DATA_HOME/lisa/runtime/zellij-<version>/` (`~/.local/share/lisa/...` fallback), per-version so upgrades never clobber. Alongside: the permissions pre-grant and plugin-cache cleanup in doctor.rs start honoring `XDG_CACHE_HOME` the way Zellij's own directories resolution does, and both operate on whichever runtime the resolver chose. Doctor reports which Zellij is in effect: mode, version, path, and (for managed) checksum provenance.

**Story acceptance:** Resolver unit tests cover all three modes plus precedence. Fetch path is integration-tested against a local fixture server: checksum mismatch → named error and **no** partial install; interrupted download leaves no half-written runtime; offline with no cached runtime → one bounded, named error printing the exact tarball URL and expected sha256 (no retry loop, no silent fallback to an unvetted system binary). With `XDG_CACHE_HOME` set, the pre-grant writes where Zellij will actually read. A second `lisa loop` with the runtime already cached performs zero network calls.

**Honest boundary:** CI never touches the real network — the live download against a real Zellij release is proven manually in the Chromebook test (S-046-06). The ~50MB unpacked runtime is an accepted cost; the no-web variant is chosen deliberately (smaller, less surface, Lisa needs none of Zellij's web features). Aged-cache eviction of superseded runtime versions is a nice-to-have, not acceptance.
