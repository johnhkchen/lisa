**Scope:** Operator recovery as a first-class command in lisa-plugin: the `[d]one` key handler (lib.rs ~4992), open_mark_done_modal (~5039), and mark_ticket_done (~5093). Owns emitting explicit OperatorRequested authority as a typed event through Story A's adapter, keeping the modal open / showing durable confirmation, and rendering named rejection + correlation. The reducer's block/pass and dependency enforcement is consumed unchanged.

**Story acceptance:** `[d]one` always emits an explicit OperatorRequested authority event — never silently borrowing the active attempt's lease, and firing whether or not a live thread exists — and the reducer still refuses it against a blocked Review or unmet dependencies (operator authority cannot bypass E-040's disposition). The modal stays open (or shows durable, visible confirmation) until the request is accepted or rejected, and an already-pending request and every rejection surface the named reason and correlation id. A test matrix covers active Review, orphaned Review, blocked disposition, stale attempt, already-pending, launch failure, and successful operator recovery.

**Honest boundary:** Operator-authority behavior proven with native UI/adapter tests over the stubbed executor — zero tokens, no live seat. The durable persistence that makes an operator request survive reload is Story B; exercising `[d]one` recovery on a real disposable Codex seat is Story D (named there). This story reworks authority and modal semantics only, not the reducer's disposition gate (E-040, consumed unchanged).
