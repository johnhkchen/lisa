- **Why it matters:** The board is empty and S-043-01 is already decomposed and cheap (help copy, no live run), so it need not compete with a real epic. But the two heavy P2 candidates trade off differently: usage-attribution silently falsifies cost/provenance state EVERY run and is the only signal with repeated hard field evidence; recovery hardens the core scheduler mission but has no recent incident. Picking wrong spends an epic's budget on the less-bleeding wound.
- **Options:**
  1. Pull the usage/provenance attribution correctness epic (P2, field-proven active corruption)
  2. Pull the bounded failure-recovery epic (P2/N2, core scheduler reliability)
  3. Hold: finish only the already-materialized S-043-01 help surface (P4, free/no-token) and re-steer after
  4. Author the vision.md stub first to re-anchor planning before pulling any epic
- **Vend recommends:** Usage/provenance attribution correctness. It's the only demand with six confirmed field overwrites and a written incident report, and it violates P2 on every loop; S-043-01 is free and ready, so let it proceed in parallel rather than treating it as an alternative.

### Fork — How wide is the usage-attribution epic — correctness only, or correctness plus Claude/Codex cache-split parity?
- **Why it matters:** Bundling parity widens the change surface and delays stopping active data loss; splitting keeps the P2 fix to the smallest contract that removes the failure mode (N4) but leaves the P3 asymmetry open. Both touch capture_usage.rs, so the temptation to bundle is real — but the corruption is a bleeding wound and parity is an enhancement.
- **Options:**
  1. Correctness-only: append-only per-run records, attribute by pane×time, quarantine unattributable usage, unmask the silent no-write mode
  2. One epic covering both correctness AND preserving the 4-dimension cache split for Claude (P3 parity)
  3. Correctness now; pull the cache-split parity signal separately later
- **Vend recommends:** Correctness now, parity separately (option 3). Land the tight P2 contract that stops overwrites and silent no-writes first; the P3 cache-split gap is already listed as its own board signal and can follow without holding the corruption fix hostage.
