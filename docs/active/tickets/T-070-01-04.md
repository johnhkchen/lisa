## Context

**Read `S-070-01` first.** That story is about recovery commands pointing at
things that are not there. This is the end of that road: a ticket that **no
command can finish**, on a board that reports it ready to schedule and a run
that will not take it.

`renderer` `T-004-01`, on the Mac mini. Its completion journal, in full:

```
requested          commit
command-in-flight  commit
failure-observed   commit   Completion commit failed for T-004-01
                            authority Attempt(AttemptLease { attempt_id: 1 })
failure-observed   commit   (again)
rejected           commit   completion reconciliation deadline 1786653398173
                            exceeded — retryability: action-required
```

It has been stuck since **2026-08-13**. The board says:

```
Status: 36 done, 0 in progress, 1 ready, 0 blocked
Ready to schedule: T-004-01
```

and a live run sits beside it with **four idle slots**, for ten minutes, taking
nothing.

## The work is finished and every artifact is in place

This is not a ticket that needs doing. Verified on the machine, 2026-08-15:

- **Five commits in history**, all present: `218f622` anchor math core, `f162d1a`
  panel controller, `c3a73cc` ViewerBridge world transform, `14b7543` panel shell,
  `fe1841c` review artifacts.
- **`docs/active/work/T-004-01/review-disposition.json`** reads
  `{"disposition":"pass","reason":null}` — the same shape every sealed ticket on
  that board has.
- **`review.md` is there**, beside it.
- **The tree is green**: `tsc --noEmit` clean, `vitest run` 134 files / 1279
  tests, all passing.

The ticket's own first line is `**VERIFY-AND-CLOSE ONLY — the implementation is
already committed.**` Everything it asks for exists. **Only lisa's seal is
missing**, and the seal is the thing that failed.

## Five documented recoveries, none of which apply

Every one of these is a command lisa offers, run on the machine:

```
lisa already-done T-004-01
  I can't find T-004-01's finished work in this repository's history.
  Nothing changed.

lisa reset-ticket T-004-01
  T-004-01  already on the board.  Nothing to reset.

lisa clean
  skip  .lisa/attempts/T-004-01 (preserved: your board records T-004-01 as
        open, so this is live work)

lisa release-seats --release
  released .lisa/signals/pane-0.lease   ← a real 9h-stale lease, cleared,
                                          and the board still would not move

lisa loop  (three fresh runs, sessions renderer-4, -5, -6)
  idle, 0/4 slots, ticket still ready
```

**`already-done` is the one that should have worked** and its refusal is the
sharpest evidence: it is documented as *"Finish a ticket whose work is already
recorded in history"*, the work is demonstrably in history under five named
commits, and it cannot see it.

## Acceptance Criteria

- **A ticket whose completion was rejected can be finished by a documented
  command.** Say which one. `already-done` is the obvious home and its own help
  text already promises this case.
- **`already-done` finds work that is in history.** Say what it actually looks
  for — a sealing commit, a ticket phase, a journal state — because it is not
  finding five commits that name the ticket in their subject lines.
- **A run says why it will not take a ready ticket.** Four idle slots and
  `Ready to schedule: T-004-01` for ten minutes is the desk's own
  `refuse-rather-than-guess` in reverse: it is refusing silently. One line in
  the dashboard's Activity pane would have ended this in seconds instead of an
  hour.
- **`retryability: action-required` names the action.** It is the field that
  decides a person must intervene, and it does not say what the person should
  do. Whatever command this ticket lands on, that string should point at it.
- **The board's own words agree.** `0 blocked` and `Ready to schedule` are both
  false about a ticket nothing can schedule. Either it is blocked and says so,
  or it is schedulable and gets scheduled.
- Reproduce it: fail a completion commit, let its reconciliation deadline pass,
  and then finish the ticket without editing a file by hand.

## Notes

- **Found while clearing the last open work from a night**, which is the moment
  this costs most: everything else on four boards was finished and this one
  ticket could not be closed by any means short of editing the ledger.
- The mini runs lisa `0.5.0` from the `lisa-nightly` formula. `T-070-01-01`'s fix
  for the sibling deadlock is **not on that machine** — it is in this repository
  and has not been released — so `lisa schedulers --stop` still fails there and
  the orphaned `.alive` records had to be moved by hand, twice in twelve hours.
  Worth weighing when this fix ships.
- The stale `pane-0.lease` that `release-seats` cleared was real and worth
  clearing — it was placed for `T-008-03` attempt 5 and outlived its run by nine
  hours. It was simply not what was holding this ticket.
