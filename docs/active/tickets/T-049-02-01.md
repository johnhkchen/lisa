## Context

Lisa brings history instead of demanding it. When `lisa init` runs in a folder with no repository, it offers project history in kitchen-table terms — undo for finished work, plus a record of what the agents did — and on acceptance creates the repository and a **project-local** identity, `Lisa (project history) <lisa@project>`, itself (crates/lisa-cli/src/init.rs). Non-interactive contract: `--with-history` / `--no-history` flags. Hard safety rules: a folder already inside a repository is left exactly as found; existing identities (local or global) are never modified; declining is respected and the consequence stated plainly ("finished work will be recorded in Lisa's journal but won't be undoable"). The identity string deliberately reads "Lisa (project history)" so an auditor attributes those commits correctly. The word "git" does not appear on the offer path — only in the parenthetical remedy aimed at users who already chose git.

_Advances: Tier 1 becomes the common case without the user ever configuring or naming git — the Zellij play applied to history; existing repos and identities are never touched._

## Acceptance Criteria

- [ ] Fixture tests: bare folder + acceptance → repo exists, local identity set, a commit succeeds, seal resolves commit; bare folder + decline → no `.git`, seal resolves journal, consequence line asserted; folder inside an existing repo → repository and all git config byte-identical before/after init.
- [ ] Flags work non-interactively; offer copy is asserted in tests and follows the brand voice with no "git" on the offer path.
