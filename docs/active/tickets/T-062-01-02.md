## Context

**Read `S-062-01` first.** Same subject as `T-062-01-01` — what a running loop
looks like from outside — and a much smaller fix.

`lisa loop` starts zellij without `--session`, so zellij invents one:
`auspicious-panda`, `polished-rustacean`, `verdant-diplodocus`. Three loops
running on one desk today produced three animals, and nothing about any of them
says which repository it is.

That name then leaks upward. It is what `zellij list-sessions` prints, what the
zellij status bar shows, and what the terminal emulator puts in its tab — a tab
on this desk read `1: auspicious-p`, truncated, for a session that will not exist
tomorrow.

**A session is a run of one project and the project is the stable fact about it.**

## Acceptance Criteria

- The session is named after the project. `lisa loop --path ~/swe/repos/steer`
  produces a session a person can recognise in `zellij list-sessions`.
- **A second run of the same project does not collide.** zellij refuses a
  duplicate session name, and the same project being started twice is a real
  case — `lisa loop` already guards against a second loop, but a crashed run can
  leave an `EXITED` session holding the name. Say what happens and make it not be
  a failure to start.
- Names are valid zellij session names whatever the directory is called.
  Something with a space, a dot, or a leading dash must not produce an unusable
  session.
- `zellij list-sessions` after a crash is still legible: an `EXITED` session named
  for its project is *more* useful than an animal, and is the state an operator
  actually meets.
- Nothing else changes. This is a flag on one spawn.

## Notes

- Measured on a desk running three loops at once, where the animals were
  indistinguishable and the wezterm tab showed a cut-off one. The consuming side
  has stopped displaying the session name at all and shows the repository
  instead; this makes the underlying name worth showing again.
- Worth checking whether `lisa clean` or the duplicate-loop guard match on
  session names anywhere. If they do, this changes their input and that is part
  of the ticket rather than a surprise afterwards.
