## Context

The type change the rest of the story rests on. `Phase` (`crates/lisa-core/src/types.rs` ~121–139)
carries eight variants:

```rust
Ready, Research, Design, Structure, Plan, Implement, Review, Done
```

Four of them — Research, Design, Structure, Plan — exist to demand an artifact that nothing reads.
They collapse into `Implement`, leaving `Ready → Implement → Review → Done`.

Keep the name `Implement` rather than minting a new one. A board upgrading mid-flight most often
has tickets sitting at `phase: implement`, and reusing the identifier means those rows need no
migration at all — only the four deleted values do.

Three surfaces in this crate move together:

- **The enum and its neighbours** — `next()` (~150–169), `artifact_filename()` (~172–182),
  `all()` (~185–196), and the `Display` impl (~141–149).
- **`artifact_filename()` specifically.** After the collapse it returns `Some("review.md")` for
  `Review` and `None` for everything else, including `Implement`. `Implement` returning `None` is
  not a regression: `crates/lisa-plugin/src/lib.rs` ~5999 already documents that `progress.md` is
  "never used as a phase edge", and ~6000–6008 already routes Implement's advancement through
  `review.md`. This ticket makes the type say what the scheduler already does. T-057-01-02 removes
  the now-unreachable branch.
- **Two independent phase parsers,** which must not drift. `parse_phase` in
  `crates/lisa-core/src/ticket.rs` ~333–335 reads ticket frontmatter; a second string match lives
  at `crates/lisa-core/src/types.rs` ~229–230. Both accept the four retired spellings today and
  both must map them forward. `phase_to_string` (`ticket.rs` ~606–608) loses its four arms.

**Forward mapping (the decision, already made).** `research`, `design`, `structure` and `plan` all
parse to `Phase::Implement`. They are accepted, not rejected — an operator upgrading a live board
should not have to hand-edit frontmatter to keep working. They are *not* re-emitted:
`phase_to_string` never writes them again, so a board self-heals to the new vocabulary the first
time Lisa updates any row.

`auto_advance` goes with them. It is declared (`types.rs` ~644), defaulted (~764), parsed (~811),
threaded into the generated layout (`crates/lisa-cli/src/loop_cmd.rs` ~441–464), and printed in a
debug dump (`crates/lisa-plugin/src/lib.rs` ~8461) — and it is never read to make a scheduling
decision anywhere. `crates/lisa-cli/src/setup_guide.rs` ~75 advertises it as "skips review pauses
between RDSPI phases", a behaviour no code implements and which has no referent at all once there
are no inter-phase pauses left. Remove the field and every plumbing site, including the
`scheduling.auto_advance` key in `crates/lisa-cli/src/config.rs` (~112–114, ~240, ~271, ~298,
~435–438, ~738). A `.lisa.toml` that still sets it must load without error — an unknown key is not
a reason to refuse a project.

_Advances: P2 — published phase state means what it says, because every remaining phase value
corresponds to a transition the scheduler actually makes. And N4 — the smallest contract that
removes the failure mode: the enum shrinks, the phase machinery does not get rewritten._

## Acceptance Criteria

- [ ] `Phase` is `Ready | Implement | Review | Done`. `next()`, `all()`, and `Display` agree, and
      a test walks the full chain `Ready → Implement → Review → Done → None`.
- [ ] `artifact_filename()` returns `Some("review.md")` for `Review` and `None` for `Ready`,
      `Implement`, and `Done`. The existing `test_phase_artifact_filename`
      (`types.rs` ~1177–1186) is rewritten to assert exactly this, not deleted.
- [ ] **The migration test this ticket exists for:** a ticket file whose frontmatter reads
      `phase: research` (and separately `design`, `structure`, `plan`) parses to
      `Phase::Implement` through `parse_phase`, and through the `types.rs` ~229 matcher, with one
      test covering both entry points so they cannot drift.
- [ ] `phase_to_string` never emits `research`, `design`, `structure`, or `plan`. A round-trip
      test shows a ticket loaded at `phase: plan` is rewritten as `phase: implement`.
- [ ] An unrecognised phase string still fails the way it does today — the mapping widens what is
      accepted, it does not make parsing permissive.
- [ ] `auto_advance` is gone from `types.rs`, `config.rs`, and the generated layout. A `.lisa.toml`
      containing `auto_advance = true` under `[scheduling]` still loads and is ignored; a test
      pins that.
- [ ] `just check` green (fmt, clippy, WASM check, workspace tests).
