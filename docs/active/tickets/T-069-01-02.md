## Context

**Read `S-069-01` first.**

The apt repository is built with one suite, hardcoded:

```
scripts/build-apt-repository.sh:116   index_dir="$stage/dists/stable/main/binary-$architecture"
scripts/build-apt-repository.sh:134   -o APT::FTPArchive::Release::Suite=stable
scripts/build-apt-repository.sh:135   -o APT::FTPArchive::Release::Codename=stable
```

Debian has said "which line do you want" with the suite name since before any of
this existed. `stable`, `testing`, `unstable` — a Linux box joins the fleet by
changing one word in one file, and that is already the most commonplace fleet
management there is: put the sources line in your provisioning and every box is on
the channel you meant.

The `publish-apt-repository` job in `release.yml` builds and signs the repo onto
GitHub Pages, so there is already a place for this to happen.

## Acceptance Criteria

- **Three suites — `stable`, `nightly`, `canary`** — under the same signed repo and
  the same archive key. Changing channel is editing the suite in
  `/etc/apt/sources.list.d/lisa.list` and running `apt-get update`, and nothing
  else.
- **`stable` keeps meaning non-prerelease.** A release candidate reaches `canary`
  and never `stable`, matching what `T-069-01-01` does to the tap.
- **Old versions stay in the pool.** This is what makes `apt-get install
  lisa=<version>` a real rollback with no extra machinery, and `S-069-01` names it
  as the thing apt does better than Homebrew. A pool pruned to the newest version
  would silently take that away.
- **The archive is signed exactly as it is now**, one key, one keyring, all three
  suites — a channel change must never mean trusting a second key.
- **`lisa-runtime-zellij` gets a stated answer.** Either it is published to all
  three suites or it stays a single stable package that all three depend on. Both
  can be right; an unstated one means a `nightly` box resolving a runtime from a
  suite nobody decided about.
- **`scripts/verify-apt-repository.sh` covers all three**, including the case that
  matters: a box pinned to `stable` does not see an rc that is sitting in `canary`.
- **The README's apt instructions name the channel choice** rather than presenting
  one suite as the only option.

## Notes

- `nightly`'s contents are written by the promotion in `T-069-01-03`; this ticket
  only has to give it a suite to be promoted into.
- Worth checking during the work: apt pinning. A box that has ever had `nightly`
  configured and then moves to `stable` will see a *downgrade*, which apt will not
  perform without being told. Say what the operator runs, and put it in the runbook
  next to Homebrew's version of the same problem.
