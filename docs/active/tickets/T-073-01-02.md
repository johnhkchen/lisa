## Context

**Read `S-073-01` first.**

A run started from a GUI terminal and a run started over `ssh` are not the same
run. They differ in what the panes can do, and the difference is invisible
afterwards:

- a GUI session can open the login keychain; an ssh session **cannot**, and gets
  `User interaction is not allowed` — which is how `gh` came to report *"the
  token in default is invalid"* on a token that was fine;
- a GUI session usually has an `ssh-agent`; an ssh session usually has none, so a
  passphrase-protected key is unusable however well it is installed on the far
  side;
- `PATH` and shell startup differ, which is separately how the mini's toolchain
  went missing for a day.

Lisa already drops seven inherited `CLAUDE_*` markers so an agent never inherits
another one's identity — it is *already reasoning about what the pane's
environment carries*. This is the same reasoning applied to the thing above the
pane.

## Why record it rather than act on it

`S-070-01` is the story of a scheduler record that held the answer — `zellij_pid`
— and was never asked. The lesson there is that **a record is only worth writing
if something later reads it**, so this ticket has to name the reader.

The readers are two, and both are after the fact: an operator asking *why did
that run fail to push when the identical run yesterday did not*, and
`T-073-01-01`'s check, which cannot claim to have measured the pane's shell
unless it knows what kind of shell that was.

## Acceptance Criteria

- **The scheduler record carries how the session was started** — enough to tell
  a GUI session from a remote one. `SSH_CONNECTION` present, `SSH_AUTH_SOCK`
  present, whether a tty was attached; three booleans, not a guess at a category.
- **It is observed, not asked for.** No flag on `lisa loop` that the caller has
  to remember and will get wrong.
- **Something reads it.** Name it: `lisa schedulers` shows it, or a failed run's
  report includes it. A field nothing reads is the `zellij_pid` mistake with a
  new name.
- **It carries no secrets.** The presence of `SSH_AUTH_SOCK` is a fact about the
  shell; its value is a path to a socket and does not belong in a record that
  gets read aloud or pasted into a ticket.
- **Absence is recorded as absence**, not omitted — a record without the field
  and a record saying *no agent* must be distinguishable, or old records silently
  read as the new default.
- Reproduce it: start the same board twice, once from a GUI terminal and once
  over `ssh`, and have the two records differ in the expected way.
