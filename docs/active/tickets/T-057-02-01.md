## Context

`lisa doctor` (`crates/lisa-cli/src/doctor.rs`, ~1699 lines) answers one question well — *are the
tools Lisa needs installed?* — and its own help string says exactly that: "Check that the tools
Lisa needs are installed." Zellij's version, the client binary, PATH, hooks. It has no opinion
about the project it is standing in, because nothing in Lisa computes one.

Give it that opinion, and give the other two commands in this story something to share.

**Build a project-currency inventory first, as a module, not as printing code.** One function that
takes a project root and returns a structured account of how this project differs from what the
running binary would create. `lisa doctor` renders it; T-057-02-02 (`init`) and T-057-02-03
(`clean`) act on it. If instead each command re-derives staleness from its own conditionals, the
three will disagree the first time any of them changes, and an operator will be told to run a
command that then reports nothing to do — which is worse than no diagnosis at all.

The inventory has to distinguish three categories, because the rest of the story is built on the
distinction:

- **Behind** — a Lisa-owned thing that exists, is byte-recognisable as a Lisa generation, and has
  a newer form. `plan_owned_template` (`crates/lisa-cli/src/init.rs` ~257–283) already computes
  exactly this judgment for documents; the inventory should reuse that comparison rather than
  invent a second one.
- **Retired** — a Lisa-owned thing that exists and has no newer form because Lisa stopped
  producing it. As of 0.5.0: `docs/knowledge/rdspi-workflow.md`, the `scheduling.auto_advance` key,
  and any `CLAUDE.md`/`AGENTS.md` that byte-matches a Lisa generator's output. That last one is the
  sharp case — a *hand-written* `CLAUDE.md` is not retired, it is simply the operator's, and the
  only thing that separates the two is whether its bytes match something Lisa once emitted.
  T-057-01-03 removes those generators; their historical output has to be retained as comparison
  data for precisely this reason, the same way `LEGACY_RDSPI_WORKFLOWS` retains old documents.
- **Stale content inside files Lisa does not own** — tickets whose `phase:` is a retired value.
  Lisa owns the vocabulary, not the file. Report these; do not treat them as Lisa's to rewrite
  silently.

Source the project's recorded version from `.lisa.toml` (`version_is_stale` /
`config::LISA_VERSION`, `crates/lisa-cli/src/config.rs`), and treat its absence as "initialised
before Lisa recorded a version" rather than as an error.

**How it reads.** Doctor's existing output is the model: one line per check, a verdict, and when
something is wrong, the command that fixes it. Project currency is one more section with the same
shape. The rule that matters is that every finding names its remedy — `lisa init` for anything
init can carry forward, `lisa clean` for anything only removal fixes — because a diagnosis whose
remedy the reader has to infer is the failure mode S-056-01 spent three tickets closing. A current
project gets one line saying so, not a silent section.

_Advances: P4 — operable at a glance, extended from the run to the project: an operator can see
that their project is behind without reverse-engineering a diff against a fresh `lisa init`. And
P2 — the reported state corresponds to durable reality on disk, computed once so three commands
cannot contradict each other._

## Acceptance Criteria

- [ ] A project-currency inventory exists as a single function returning structured data, with no
      printing in it. `doctor.rs` renders that data and derives no staleness judgment of its own.
- [ ] The inventory distinguishes **behind**, **retired**, and **stale content in files Lisa does
      not own**, and a test covers one of each against a 0.4.4-shaped fixture.
- [ ] **The distinction this ticket turns on:** a `CLAUDE.md` whose bytes match a 0.4.x
      `generate_claude_md` output is reported as retired; a hand-written `CLAUDE.md` is not
      reported at all. Both asserted. The historical generator outputs are retained as comparison
      data.
- [ ] A `.lisa.toml` with no `version` key is reported as pre-versioning, not as an error, and
      `lisa doctor` still exits successfully.
- [ ] Every project-currency finding names the exact command that resolves it.
- [ ] A project created by a fresh `lisa init` reports one line confirming it is current, and
      `lisa doctor`'s existing tool checks are unchanged — a test pins that the tool section's
      output is byte-identical to today's.
- [ ] `just check` green (fmt, clippy, WASM check, workspace tests).
