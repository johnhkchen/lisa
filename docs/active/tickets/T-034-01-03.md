## Context

On timeout, revoke the prior attempt's lease and fence (terminate/disqualify) its pane before the ticket is released for rescheduling, so a timed-out attempt can never re-own the ticket.

_Advances: P1 — Preserve the repository; P2 — State means what it says; E-034_

## Acceptance Criteria

- [ ] A scheduler test asserts that on hard-silence timeout the old pane is fenced and its lease invalidated strictly before release_slot_for_ticket runs, ending in a named bounded state; no code path reschedules the ticket while the prior attempt's lease is still valid.
