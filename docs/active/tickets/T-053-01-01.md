## Context

[d] is a dead lever on exactly the tickets it's advertised for. The chain: `open_mark_done_modal` (crates/lisa-plugin/src/lib.rs ~8253) lists candidates → `mark_ticket_done` (~8308) → `dispatch_completion_at`, whose operator guard (~2422) calls `passing_review_disposition` (~1944); that reads `docs/active/work/<id>/review-disposition.json` fail-closed (crates/lisa-core/src/disposition.rs ~103 — missing, unreadable, and malformed all come back Invalid), so Block and Invalid both end in `log_completion_rejection` (~2021) and a rejection modal. Meanwhile the machinery for a sanctioned exception already exists: `ReviewDisposition::Note` authorizes completion (disposition.rs ~98), and `finish_successful_completion` (~3109) seals, rebuilds the DAG so dependents flow, emits the provenance note, and releases the seat — indifferent to completion source. Build the missing branch: `dispatch_completion_at` accepts an operator override carrying an operator-authored `DispositionNote` built from a small canned catalog (research enumerates it against the 0.4.4 field cases — roughly: evidence-satisfies-the-criterion, can't-be-verified-from-this-machine, beyond-the-ticket's-reach, and a no-review-on-file shape for Invalid). Citations stay real per S-049-06 — the note cites what the operator actually looked at (the block's own disposition, review.md, progress.md) — with defined semantics for the fail-closed shapes, where there is no block to quote: `criterion_quote` records the literal state being overridden ("no agent review on file for T-…", or the malformed file's parse error), `evidence_citation` names the path the operator inspected (the ticket's work directory or the unreadable disposition file), and `summary` carries the canned reason; the schema's three fields hold in every shape without growing new ones. No catalog entry reads as a quality hedge, because doubting the work is send-back's job, not a note's. The override is a recorded authority, not a bypass: ledger and journal carry operator authority, the chosen reason, and the ask it overrode.

_Advances: the andon cord keeps its integrity and gains a handle — a person resolves a parked ticket in seconds, and the record shows exactly who decided what (P2, P4)._

## Acceptance Criteria

- [ ] A ticket parked on a Block seals through the override: Done, dependents startable on the next pass, seat released — all through the existing `finish_successful_completion` path, no parallel completion code (N4).
- [ ] The same override works on the fail-closed shapes (missing and malformed disposition files) using the catalog's no-review-on-file reason, with the defined field semantics — the quote holds the overridden state, the citation the inspected path, nothing fabricated, no empty fields — and the receipt states plainly that no agent review existed (P2).
- [ ] Receipts end-to-end: the provenance ledger and completion journal both record operator authority, the canned reason chosen, and the overridden ask; the note surfaces in Notes-for-you like an agent note would — shown in progress notes.
- [ ] Negative fixture: with no reason selected, a Blocked ticket still refuses to seal exactly as today — the guard is widened for a recorded operator choice, never weakened (demonstrated red, fixture kept).
- [ ] Catalog copy passes the kitchen-table read, recorded in review.md: no frontmatter, disposition, DAG, or seal vocabulary in any operator-facing reason string.
- [ ] `just check` green (fmt, clippy, WASM check, workspace tests).
