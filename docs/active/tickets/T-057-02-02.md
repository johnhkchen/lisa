## Context

`lisa init` can add and it can refresh. It cannot retire. Every action it plans is a
`CreateFile`, an `UpdateFile`, a `NoOp`, or a `SafetySkip` (`crates/lisa-cli/src/init.rs`
~257–283) — there is no verb for *this used to be mine and is not any more*. Teach it one, and
use the inventory T-057-02-01 built rather than a second set of conditionals.

Three retirements, each with a different consent rule, and the differences are the ticket:

**The retired workflow document.** T-057-01-05 already handles `rdspi-workflow.md` under
`plan_owned_template`'s existing safety rule: removed on byte-match with a known generation,
`SafetySkip`ped otherwise. That is the pattern the other two follow. Nothing new here except that
the removal becomes an inventory-driven action rather than a special case inside the rename.

**The generated context files.** `CLAUDE.md` and `AGENTS.md` are the sharp case. A byte-match
against a historical `generate_claude_md` / `generate_agents_md` output proves Lisa wrote it and
the operator never touched it — that one init may retire. Anything else is the operator's writing
and init must leave it and say nothing. Get this backwards in either direction and it is a P1
violation on one side or a permanently confusing repository on the other. The generated `AGENTS.md`
is a pointer *at* `CLAUDE.md`, so retiring one and preserving the other leaves a dangling pointer;
decide and record what happens in that mixed case rather than letting the file order decide it.

**The dead config key.** `scheduling.auto_advance` in `.lisa.toml`. T-057-01-01 makes Lisa ignore
it; this makes init remove it. `.lisa.toml` is a file the operator edits — it holds their
concurrency, model routing, and client choices — so a rewrite has to preserve everything else
exactly: comments, key order, formatting, and any key Lisa does not recognise. `upsert_missing_config_keys`
already demonstrates the surgical-edit approach for the additive direction; removal follows it.
If a surgical removal cannot be done without reformatting the operator's file, **do not do it** —
report it through the inventory and let `lisa clean` or the operator handle it. A config file that
comes back with its comments stripped is a worse outcome than a dead key sitting inert.

**Retired phase values are not init's to fix.** A ticket at `phase: structure` loads correctly
after T-057-01-01 (it maps to `implement`) and self-heals the next time Lisa writes that row.
`docs/active/tickets/` is the operator's board, not a Lisa-owned template, and init rewriting
frontmatter in bulk is a much larger claim on the repository than anything init does today. Report
them; leave them.

**`--dry-run` is the load-bearing flag now.** It exists already (`main.rs` ~61–63) and until this
ticket it previewed only additions. Once init can remove files, the preview is what an operator
reads before letting it touch a repository they have work in. Every retirement must appear there,
named, with its reason.

_Advances: P1 — preserve the repository: init removes only what it can prove it wrote, and a file
the operator has touched is never destroyed by an upgrade. And N4 — the smallest contract:
retirement is one new action verb driven by an inventory that already exists, not a migration
framework._

## Acceptance Criteria

- [ ] `lisa init` plans retirements from the T-057-02-01 inventory, expressed as a distinct action
      the plan can report, and does not re-derive staleness on its own.
- [ ] **The consent rule this ticket turns on:** a `CLAUDE.md` matching a historical Lisa generator
      output is removed; a `CLAUDE.md` with one edited line is preserved byte-identical and
      reported as preserved with a reason. Both asserted, and the same pair for `AGENTS.md`.
- [ ] The mixed case — one generated, one hand-written — is handled by a rule stated in the design
      and covered by a test. No run leaves an `AGENTS.md` pointing at a `CLAUDE.md` that init just
      removed.
- [ ] `scheduling.auto_advance` is removed from `.lisa.toml` with every comment, every unrelated
      key, and the key order preserved exactly. A fixture with interleaved comments proves it.
- [ ] A `.lisa.toml` that cannot be edited surgically is left untouched and reported, not
      reformatted.
- [ ] Tickets at retired phase values are reported and **not** rewritten by init. Asserted.
- [ ] `lisa init --dry-run` names every retirement and its reason, and changes nothing on disk. A
      test runs `--dry-run` against the 0.4.4 fixture and asserts the tree is byte-identical
      afterward.
- [ ] **End to end:** a fixture project initialised by 0.4.4 becomes a current project through one
      `lisa init`, with no hand edits, and `lisa doctor` afterward reports it current apart from
      what T-057-02-03 owns.
- [ ] `lisa init` on an already-current project is all `NoOp` — no retirement fires twice, and a
      second consecutive run changes nothing.
- [ ] `just check` green (fmt, clippy, WASM check, workspace tests).
