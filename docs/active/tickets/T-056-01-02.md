## Context

The root cause. `run_check` (`crates/lisa-cli/src/unblock.rs` ~177–192) does not run the recorded
check in the project. It builds a `ReadOnlySnapshot` — a fresh `tempfile::tempdir()` (~317–318)
populated by `snapshot_project`, which takes the git branch whenever git succeeds (~336–341) and
fills the tree from:

```rust
git -C <root> ls-files -z --cached --others --exclude-standard   // ~348-358
```

`--exclude-standard` honours `.gitignore`. So `dist/`, `node_modules/`, `.astro/`, `.lisa/` — every
build output and every fetched dependency — are absent from the snapshot **by construction**, not
by accident and not by timing. The tree is then chmod'd read-only (~319), fingerprinted (~178),
and the check is spawned as `/bin/sh -c "<check>"` with `.current_dir(snapshot.path())` (~192).

That is the only spawn in Lisa that redirects cwd away from the project root — `proposal.rs`
~249, `triage_agent.rs` ~44 and `loop_cmd.rs` ~487 all use `.current_dir(root)`. And nothing tells
the author of a check that it will happen. `disposition.rs` ~402 parses `check` as an opaque
non-empty string with no cwd contract, and `docs/knowledge/rdspi-workflow.md` ~59 asks reviewers
only for "a read-only verification command".

So a competent reviewer wrote `node scripts/check-touch.mjs` — a relative path, no `--root` —
which in the real tree passes, and in the snapshot resolves `dist/` against a directory that has
no `dist/` and never will. The reproduction is deterministic, which is why seven-plus retries
across stale and fresh builds, busy and idle trees, and sandboxed and unsandboxed shells all
failed identically:

```sh
cd /Users/johnchen/swe/repos/tabular-recipes
S=$(mktemp -d)
git ls-files -z --cached --others --exclude-standard | while IFS= read -r -d '' f; do
  mkdir -p "$S/$(dirname "$f")"; cp "$f" "$S/$f"
done
ls "$S"                                     # scripts/ present, dist/ ABSENT
(cd "$S" && node scripts/check-touch.mjs; echo "exit=$?")
# -> No build at dist/. Run: npm run build
# -> exit=2

# contrast, in the real tree:
cd /Users/johnchen/swe/repos/tabular-recipes && node scripts/check-touch.mjs   # passes

# and the exclusion is structural, not incidental:
git ls-files --cached --others --exclude-standard | grep -c '^dist/'   # -> 0
git check-ignore -v dist                                               # -> .gitignore:2:dist/  dist
```

Honest about the limit of the trace: `ps` captured exactly one spawn during the failing run —
`node scripts/check-touch.mjs`, relative, no `--root`, parented straight to Lisa with no `sh`
frame (a single simple command, so `sh` tail-execs). The child's own cwd was never captured; it
exits too fast for `lsof`. The parent's cwd was read directly and was the project root, so Lisa's
root resolution (`main.rs` ~783) is not at fault and stray worktrees elsewhere on the machine are
not at fault. The cwd claim rests on the code path plus the reproduction above.

Close the gap between what a check is promised and what it gets. The options, for design to
choose and record:

- **(a)** Run the check with `.current_dir(root)` and drop the snapshot, resting on the contract's
  read-only promise. Simplest, matches every other spawn in Lisa, loses hermeticity.
- **(b)** Keep the snapshot and make it honest — after `git_visible_paths`, also materialise
  gitignored-but-present paths the check needs, by declared list. Note that adding `--ignored` to
  the `ls-files` call is not sufficient on its own: `node_modules/` would make the copy
  unusable.
- **(c)** Let the disposition declare its execution context — an optional `check_cwd`
  (`project` | `snapshot`) and/or a declared list of paths that must be present — so the
  reviewer states what the check needs and Lisa either provides it or refuses the check at
  record time.

Whichever is chosen, the `check` field stops being a string with an unstated environment. And the
hermetic guarantee that is being kept or traded must be named in the design, not dropped
silently — the snapshot exists for a reason (N4: the smallest contract that removes the failure
mode, not a rewrite of the parking system).

_Advances: P5 — the field failure is closed at the boundary that failed, with a deterministic
reproduction, rather than by a plausible patch. And P2 — the gate's verdict corresponds to
durable reality in the project, which is the only reality the operator can act on._

## Acceptance Criteria

- [ ] **The regression fixture this story is named for:** a git repository whose `.gitignore`
      ignores `out/`, with a real `out/marker` on disk, and a blocked ticket whose recorded check
      is `test -f out/marker`. `lisa unblock` on it returns `UnblockOutcome::Reopened` and exits
      0. Asserted to decline today, so the test fails before the fix and passes after.
- [ ] A check given a relative path resolves it against the same tree the operator would — a
      fixture check that reads a gitignored build output and a tracked source file in one run
      sees both.
- [ ] The chosen option is recorded in the ticket's design artifact with the hermeticity tradeoff
      stated explicitly, and if the snapshot is kept, what is and is not materialised is a
      declared rule, not an emergent property of `--exclude-standard`.
- [ ] Whatever cwd the check runs in is the cwd T-056-01-01 reports. A test asserts the reported
      directory equals the directory the check observed (e.g. via a check that prints `pwd`).
- [ ] `run_world_rechecks` (~120–129) goes through the same path — a world-owned remedy with the
      same shape is verified against the same tree as an operator-owned one. A test covers both
      entry points against the `out/marker` fixture.
- [ ] Non-git projects still work: the `copy_small_tree` fallback path keeps a passing test, and
      the fixture above is repeated in a non-git project to prove the two paths agree.
- [ ] `just check` green (fmt, clippy, WASM check, workspace tests).
