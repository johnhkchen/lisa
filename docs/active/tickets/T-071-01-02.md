## Context

**Read `S-071-01` first.** This is a gap that is harmless today and becomes a
counting error the moment `T-071-01-01` lands.

`capture_usage.rs` writes one record per turn, per pane, from the Stop hook. A
record from this desk, 2026-08-15:

```json
{"pane_id": 0,
 "session_id": "766da7c6-17cb-40fe-8047-fa2829ba60cf",
 "captured_at": 1786805530,
 "input_tokens": 20893938,
 "output_tokens": 141109}
```

**Nothing in it says which model spent them.** Today that is fine, because
`[agent].model` is one value for the board and every token on it came from the
same place. The moment two panes run two models, the ledger records twenty
million tokens with no way to say whose they were.

## Why this matters more than an accounting nicety

A weekly budget is not counted in tokens, it is counted in **what those tokens
cost**, and Sonnet and Opus are not the same price against it. The whole point of
`S-071-01` — the operator's reason for asking — is to spend less by putting the
grinding work on a cheaper model. **A ledger that cannot tell them apart cannot
show that the change worked**, and `S-072-01` is going to try to read exactly
this file to decide when to stop.

It also fails in the direction that hides. An unlabelled record does not look
wrong; it looks like a number. Whoever reads it will assume one model, and be
wrong by whatever ratio the board happened to run.

## Acceptance Criteria

- **A capture record names the model and the effort the turn ran with**, and the
  client it came from.
- **A record written before this lands is not retroactively labelled.** An old
  record's model is genuinely unknown; guessing it from today's config would
  invent a fact. Say `unknown` or leave the field out, and let a reader see the
  boundary.
- **The hook still cannot fabricate.** `capture_usage`'s own rule —
  *"write-after and never-fabricate"* — holds: if the model cannot be read from
  the transcript or the environment the pane was started with, that is a record
  saying so, not a guess.
- **It works for both clients.** Codex rollouts are parsed by a different branch
  of the same file and carry their own model naming; say what each one is read
  from.
- **`no-captures.jsonl` keeps its job.** A turn whose transcript is missing or
  empty still lands there with a reason, unchanged.
- Reproduce it: run two panes on two models in one run, and have the ledger
  attribute each turn's tokens to the right one.

## Notes

- The pane is already in the record and the scheduler already owns pane history —
  `capture_usage`'s docstring says ticket attribution is *"deliberately deferred
  to the scheduler, which has the pane-ownership history the hook process
  lacks."* Model attribution may be the same shape: the hook records the pane,
  and whoever configured the pane knows the model. **Worth deciding in review**
  whether the hook reads it or the scheduler joins it, and the deciding argument
  is which one can still be right when a pane is reconfigured mid-run.
- Do this **before or with** `T-071-01-01` rather than after. Landing per-pane
  models first means a window of runs whose ledger cannot be read.
