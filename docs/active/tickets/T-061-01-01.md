## Context

**Read `S-061-01` first.**

`on-ack.sh`, `on-heartbeat.sh` and `on-stop.sh` all open with:

```sh
SIGNAL_DIR=".lisa/signals"
mkdir -p "$SIGNAL_DIR"
```

Relative. The hook runs in the agent's working directory, so an agent that has
stepped into another repository writes `pane-N.ack` — and `mkdir -p` creates
`.lisa/signals/` there if it does not exist, in a directory Lisa does not manage.

The pane is known: every one of these is guarded on `$LISA_PANE_ID`. The project
is not passed. `$LISA_PROJECT` already appears in the `Notification` hook command
that `lisa init` writes, so a value of this shape is already being produced
somewhere.

### The two failures, and the second is worse

**The true project loses a heartbeat**, which is the one this desk noticed second.

**Another project gains a seat**, which is the one that hurt. Its launcher reads
fresh signals and refuses to start a run — the exact behaviour a launcher should
have, on evidence that is not its own. Nothing in that repository can tell that
the file is a stranger's: the filename carries a pane id from a numbering it does
not share, and the payload is not read by anything downstream.

## Acceptance Criteria

- An agent in a Lisa pane writes its signals to the project its pane was leased
  from, wherever it is standing. Reproduce it — a loop on project A, an agent
  that `cd`s into project B, a tool call — and show the file landing in A.
- The mechanism is stated. An environment variable alongside `LISA_PANE_ID` is
  the obvious answer; if the hooks should resolve it some other way, say why.
- **`mkdir -p` no longer creates a signals directory in an unrelated repository.**
  That is what makes this silent: the hook succeeds and leaves a plausible file
  behind. Consider whether a hook that cannot find its lease should write nothing
  and say so.
- An operator's own session still writes nothing, which `on-stop.sh` already
  states as deliberate: *"An operator's own session has no Lisa pane: nothing to
  attribute, so stay silent."*
- Existing single-project behaviour is unchanged, including the case where the
  agent's cwd and the project are the same — which is every desk that runs one
  loop at a time, and is why this has not been seen before.
- Say what happens to signal directories already written into innocent
  repositories. They are stale by construction and nothing will clear them;
  whether `lisa clean` should is a judgement, not an assumption.
- Documented where an operator will meet it. `hooks-guide` describes what these
  files are for and is the natural home.
