## Context

Found during T-051-01-01's load tally (the epic's own bar working as designed — a real failure becomes a ticket, not a retry habit): `runtime::tests::checksum_mismatch_is_named_and_leaves_no_partial_install` (crates/lisa-cli/src/runtime.rs, ~line 1059) failed 4 of 32 parallel `cargo test -p lisa-cli` runs while the code under test was correct — the assertion `error.contains("Managed Zellij checksum mismatch")` came back with a different error under contention, and the captured runs show every other test green. The exact contention mechanism is research's first job (shared tempdir? port? env var? a racing partial-install path that changes which error surfaces first?). Rework the test so it fails only when the checksum guard is actually broken, with the same discipline T-051-01-01 set: assert semantics rather than incidental strings where possible, keep a negative fixture proving a broken guard still turns it red, and write the load-immunity rationale into the test. No production changes to the runtime installer unless research shows the installer itself races — if it does, that is a finding to surface, not to quietly patch around.

_Advances: the second known gate-distrust trainer dies the same way the first did — zero flaky reds left in the workspace suite._
