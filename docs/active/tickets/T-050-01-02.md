## Context

Empty is always a sentence. Three field-observed blanks and one bare error. (1) Any Lisa command run in an uninitialized folder (loop, status, validate, doctor where it presumes a project) leads its failure with "This folder isn't set up yet. Run: lisa init" before any technical detail (crates/lisa-cli/src/main.rs and the per-command project-discovery paths). (2) `lisa notes` on an empty queue prints "Nothing to read." instead of empty stdout that reads as a malfunction (crates/lisa-cli/src/notes.rs — the release audit's finding). (3) `lisa status` with nothing parked renders its sections so their absence is legible rather than silently missing. (4) `lisa validate` on a board with zero tickets explains what a ticket is and where it goes — one short paragraph with the tickets directory path — instead of the bare "no tickets found" error that forced the Chromebook grader to seed a smoke ticket for a scorable exit (docker/chromebook-test/bin/grade seeding block becomes unnecessary; leave the grader change to the runbook's next amendment, this ticket only fixes the CLI). All lines brand-voice, string-pinned.

_Advances: no first contact with Lisa ends in a blank or a bare error — every surface either shows the thing or says the one sentence that gets you to it._
