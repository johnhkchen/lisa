## Context

**Read `S-074-01` first.** Same family as `T-074-01-01`: lisa says something
about a board that the board's own data contradicts.

Measured on the Mac mini's `renderer` board, 2026-08-16, in one command's output:

```
1 scheduler is running on this board.

  renderer (renderer-4cd787ad)  — not running
    started 41h ago, stopped stamping 41h ago, zellij server pid 62793
    stop it with: zellij kill-session renderer

  renderer (renderer-0933474d)  — not running
    started 41h ago, stopped stamping 41h ago, zellij server pid 62793
```

**The header says one is running. Every record printed underneath says
`— not running`.** Both come from the same call, four lines apart.

## Why this one is worth more than its size

The header is the line an operator reads, and it is the line a person reads
*when they are deciding whether it is safe to do something*. This was found while
preparing that machine for a restart, where the question being asked was exactly
*"is anything running on the mini that I should stop cleanly first?"* The header
said yes. The truth was no. Acting on the header means stopping a session that
does not exist — which is `S-070-01`'s whole story, arrived at from the opposite
direction.

Note also that both records name **the same `zellij_pid`, 62793**, and both
stopped stamping 41 hours ago. Whatever the counter is counting, it is not
"records whose process exists" and it is not "records that stamped recently".

## Acceptance Criteria

- **The count and the records agree**, because they are derived from one
  judgement rather than computed twice. If the header says one is running, one
  record says running.
- **The rule the count uses is the rule the records use.** `S-070-01` established
  that liveness is a question you ask about a pid, not a property you infer from
  a stamp; whichever this is, both halves of the output use it.
- **Stale records are still shown**, and still labelled. This is not a request to
  hide them — a record of a run that ended is useful and `lisa schedulers`
  showing it is right. It just must not be counted as alive.
- **Zero running says so plainly.** A board with only ended records should open
  with a sentence a person can act on, not a number that contradicts what
  follows.
- Reproduce it: on a board whose scheduler records have all stopped stamping,
  the header says none is running.

## Notes

- Found while preparing the mini for a restart, when the answer decided whether
  to stop something first. That is the context where this misleads most, and it
  is worth a line in the write-up: **the header is what a person reads before
  acting.**
- Two records shared one `zellij_pid` here. Whether that is expected — two
  schedulers, one zellij server — or is itself a bug is worth a look while in the
  code; it is not this ticket's claim either way.
