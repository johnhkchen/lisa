## Context

`schedule_ready_tickets()`, `release_slot_for_ticket()`, and `find_idle_slot()`
operate silently — no ActivityEvents are logged for scheduling decisions. When
a ready ticket fails to get assigned, operators have no visibility into why.
The slot discovery log is also misleadingly emitted as an `Error` event.

## Acceptance Criteria

- `schedule_ready_tickets()` logs an ActivityEvent for each scheduling decision:
  - "Scheduling {ticket_id} to pane #{pane_id}" on success
  - "Skipping {ticket_id}: thread already exists" when filtered at line 219
  - "No idle slots available, {N} ready tickets waiting" when slots exhausted
- `release_slot_for_ticket()` logs "Released slot #{pane_id} for {ticket_id}"
  (or "No slot found for {ticket_id}" if ticket wasn't in any slot)
- Slot discovery log changed from `ActivityEvent::Error` to a new
  `ActivityEvent::Info` variant (or reuse an existing non-error variant)
- `poll_tick()` logs a summary each cycle: "Poll: {N} ready, {M} running,
  {K} idle slots" (at debug level — use `ActivityEvent::DagRecomputed` or
  similar to avoid log spam)
- All new log messages visible in the dashboard activity log
- Existing tests updated, new tests for each logging path

## Files to Modify

- `crates/lisa-plugin/src/lib.rs` — scheduling, release, poll_tick methods
- `crates/lisa-core/src/types.rs` — possibly add Info variant to ActivityEvent
- `crates/lisa-plugin/src/ui.rs` — render new activity types if needed
