## Context

The third command in the trio, and the only one that does not exist yet. `lisa doctor` reports;
`lisa init` carries forward what it can prove is safe; `lisa clean` is where an operator says *yes,
remove it* to the things init deliberately would not.

Init's caution leaves a real residue. After T-057-02-02 an upgraded 0.4 project can still be
carrying:

- `docs/active/work/{ticket}/research.md`, `design.md`, `structure.md`, `plan.md`, `progress.md` —
  artifacts of a workflow that no longer runs, for tickets that are already done. Init will never
  touch these: they are published work product, not templates.
- Work directories for tickets that no longer exist on the board at all.
- Runtime debris under `.lisa/` — signal files, attempt directories whose panes are long gone.
- A Lisa-owned document the operator lightly edited, which init `SafetySkip`ped and will keep
  skipping forever.

**The scope decision, for design to make and record.** There are two coherent commands here and
they should not be conflated:

- **(a) Currency only.** `lisa clean` removes exactly what the T-057-02-01 inventory reports as
  retired-but-preserved — the residue of upgrading. It has no opinion about anything else, and it
  finds nothing on a project that was never upgraded. Narrow, obviously safe, and it completes the
  trio the story is named for.
- **(b) Currency plus litter.** The above, plus Lisa's own runtime debris and orphaned work
  directories, which are worth removing whether or not a version changed. Broader, useful
  independently of 0.5.0, and it needs a defensible line between "Lisa's litter" and "the
  project's files" that (a) never has to draw.

Recommend (b) if and only if that line can be stated as a rule in one sentence; take (a) otherwise.
A cleaner that needs a paragraph to explain what it might delete is a cleaner nobody will run.

**Whichever is chosen, the consent shape is fixed.** P1 is the constraint: Lisa must not silently
destroy user-owned content.

- Default output is the plan, not the deletion. Follow `lisa init --dry-run`'s precedent rather
  than inventing a second preview vocabulary — an operator who knows one should recognise the
  other.
- Every entry names the file and why Lisa believes it is removable.
- Nothing under `docs/active/tickets/` or `docs/active/stories/` is ever a candidate. Those are the
  board. Even an orphaned one is the operator's.
- Nothing outside paths Lisa created is a candidate, ever, under any flag.
- Work artifacts belonging to a ticket that is **not** `done` are never candidates — an in-flight
  ticket's attempt directory is live state.

**Voice.** This is a command someone runs when they are already slightly nervous. Say what will go
and what will stay, in files-and-reasons, with no reassurance that is not a fact. The one-line
summary should let a reader decide without reading the list.

Register it in `crates/lisa-cli/src/main.rs` alongside the everyday commands — `init`, `doctor`,
`clean` belong together in help, since the trio is the answer to one question. `crates/lisa-cli/tests/help_surface.rs`
pins the help surface and moves with it.

_Advances: P1 — the destructive command in Lisa is the one that shows its work first and never
reaches outside what Lisa itself created. And P4 — an operator can bring a project current and
know exactly what that cost them._

## Acceptance Criteria

- [ ] The scope decision between (a) and (b) is recorded in the ticket's review artifact with the
      "Lisa's litter" line stated as a rule if (b) is chosen.
- [ ] `lisa clean` exists, is registered in help beside `init` and `doctor`, and
      `crates/lisa-cli/tests/help_surface.rs` covers it.
- [ ] **The default this ticket turns on:** a bare `lisa clean` on a project with removable files
      changes nothing on disk and prints the plan. A test asserts the tree is byte-identical after
      it runs.
- [ ] Removal happens only under an explicit flag, and every removed path was named in the plan
      first.
- [ ] **The refusals, each asserted:** nothing under `docs/active/tickets/` or
      `docs/active/stories/`; nothing outside paths Lisa created; no work artifact for a ticket
      that is not `done`; no path reachable by symlink out of the project root.
- [ ] `lisa clean` on a project created by a fresh `lisa init` reports nothing to remove.
- [ ] **End to end, closing the story:** the 0.4.4 fixture, after `lisa init` and then `lisa clean`,
      is reported fully current by `lisa doctor`, and every file a person wrote in that fixture is
      still there byte-identical.
- [ ] `just check` green (fmt, clippy, WASM check, workspace tests).
