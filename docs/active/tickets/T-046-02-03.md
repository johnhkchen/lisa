## Context

The permission pre-grant and plugin-cache cleanup hardcode the Zellij cache dir from `$HOME` (crates/lisa-cli/src/doctor.rs:286-390: `~/.cache/zellij` on Linux, `~/Library/Caches/org.Zellij-Contributors.Zellij` on macOS), but Zellij resolves its cache through the directories crate, which honors `XDG_CACHE_HOME`. On any Linux box where that variable is set, Lisa pre-grants permissions into a file Zellij never reads, and the user gets an inscrutable permission prompt inside the TUI. Match Zellij's resolution exactly, and make both the pre-grant and the cache cleanup operate on whichever runtime the resolver selected.

_Advances: state means what it says — a "pre-granted" permission is actually granted where Zellij looks; a field-class bug on exactly the target hardware._

## Acceptance Criteria

- [ ] With `XDG_CACHE_HOME` set, the pre-grant writes the permissions file Zellij (0.43 semantics) actually reads; with it unset, current macOS and Linux paths are unchanged.
- [ ] Regression tests cover both environment states for pre-grant and cache-cleanup path resolution.
