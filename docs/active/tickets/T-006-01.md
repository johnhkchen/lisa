## Context

When debugging scheduling issues, the only way to see the DAG and ticket states is
to launch the full zellij plugin. There's no quick offline tool to answer: "What does
lisa see? What's ready? What's blocked? Are there dependency cycles?"

`lisa validate` checks for errors but doesn't show the positive case — the actual
dependency graph and scheduling order.

## Objective

Add a `lisa status` subcommand that reads tickets, builds the DAG, and prints a
human-readable summary of the current scheduling state. This is a read-only
diagnostic — no state mutation, no zellij dependency.

## Acceptance Criteria

- [ ] `lisa status` subcommand added to clap CLI
- [ ] Reads tickets from configured directory (default: `docs/active/tickets/`)
- [ ] Builds DAG and prints: ticket count, edge count, any cycles
- [ ] For each ticket: ID, title, phase, status, depends_on, blocked_by (computed)
- [ ] Shows scheduling readiness: which tickets are ready (all deps done, phase=ready)
- [ ] Shows topological order (execution waves)
- [ ] Exit code 0 on success, 1 if DAG has errors (cycles, missing deps)
- [ ] Works without zellij installed (pure CLI)
- [ ] Tests for output with various ticket configurations
