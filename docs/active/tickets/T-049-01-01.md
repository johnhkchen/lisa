## Context

lisa-core gains the seal ladder: a `CompletionSeal` type with tiers `commit` (today's atomic-commit gate, semantics untouched) and `journal` (defined as a contract here; implemented by T-049-03-01), plus resolution from `.lisa.toml` `[guards] completion = "auto" | "commit" | "journal"`, default `auto`. Auto probes at loop start — repository present, `git config user.email` resolves, the transaction path can commit — and pins the strongest satisfiable tier for the run. Explicit `commit` in an unsatisfiable environment is a hard, named preflight failure carrying the two-line identity remedy; explicit `journal` is honored anywhere. The governing rule, proven twice on 2026-07-16 (managed Zellij on Linux, system mode on macOS): an unconfigured default must never resolve to a requirement the environment cannot satisfy. Config parsing follows existing conventions — unknown values are validation errors with actionable text.

_Advances: the guard stance becomes a declared, environment-aware choice instead of an invisible prerequisite; Tier 1 is not weakened — it is selected or enforced, never assumed._

## Acceptance Criteria

- [ ] Unit tests cover resolution across environments: repo+identity → commit; no repo → journal; repo without identity → journal under auto and hard failure under explicit commit, with the remedy string asserted; explicit journal honored with git present; unknown config values → actionable validation error.
- [ ] The resolved tier is pinned once per run and exposed to callers (doctor, status, ledger writers consume it in T-049-01-02); no code path re-probes mid-run.
