## Context

The 0.4.4-rc.8 flip gave native Claude the same per-ticket fresh-process boundary Codex has always used (`ResetStrategy::ExitThenFresh`), because in-place `/clear` reuse kept the launch line's `LISA_TICKET_ID`/`LISA_ATTEMPT_ID` environment alive for the pane's whole life — every ticket after the first ran under a stale identity. That leaves the scheduler's in-place reuse machinery unreachable by any shipped adapter: `TransitionState::WaitingForStop` and `WaitingForClear`, the stop/clear timeout fallbacks in `check_transition_timeouts`, the `ClearHandshake` reuse arm in `schedule_ready_tickets`, and `handle_cleared_signal`'s prompt delivery (all in crates/lisa-plugin/src/lib.rs; the strategy enum lives in adapter.rs). Machinery that reads as live but never runs is P2's exact complaint — a test once asserted "Claude must retain its clear handshake" and everyone believed it.

**Evidence before deletion.** Research must cite at least one ExitThenFresh field leg — 0.4.4-rc.8 or later, multiple consecutive Claude tickets on one pane, journal-sealed clean (the emulated-leg journals or this repo's own loop provenance). If that evidence does not exist yet, park early with a plain note naming the one thing to run: a `just loop-rc` leg on the current candidate. Never a jargon wall. Design decides whether `ResetStrategy::ClearHandshake` survives as a documented seam for future in-place-reset integrations (adapters whose identity does not live in process environment) or goes entirely.

_Advances: nobody reading the scheduler finds a state no code path can reach; the reuse seam that remains is a decision, not leftovers._

## Acceptance Criteria

- [ ] research.md cites the ExitThenFresh field evidence by run (leg date/version and journal outcome) before any code is removed.
- [ ] No scheduler path can send `/clear` as a scheduling transport; `WaitingForStop`/`WaitingForClear` and their timeout fallbacks are removed, or the design records why a remnant stays and marks it unreachable.
- [ ] Every deleted test maps in writing (progress notes) to its successor or to the removed path it covered — no coverage lost silently.
- [ ] `.cleared` emission survives wherever a shipped adapter still consumes it; Codex behavior unchanged by one byte (N4).
- [ ] WASM check, workspace tests, and clippy all green.
