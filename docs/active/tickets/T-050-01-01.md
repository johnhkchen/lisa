## Context

The default decides the history question. Today a fresh-folder `lisa init` with non-interactive input errors until the caller picks `--with-history` or `--no-history` — the install path's first command became a flag question, forcing the 0.4.4 docs and the Chromebook runbook to teach flags (crates/lisa-cli/src/init.rs, the flag-demand at the Missing/Unborn arms). Replace the demand with a decision: no flag + machine can keep history → keep it (repo, project-local identity, initial commit — T-049-02-01's mechanics unchanged) and announce "Keeping project history — finished work will be undoable."; no flag + machine cannot → journal path with the existing consequence line, exit 0. The interactive prompt keeps offering, but accepting on a git-less machine falls to the journal with the same line instead of hard-failing (the empty-input-defaults-to-yes trap from the release audit). The one remaining error: explicit `--with-history` on a machine that cannot honor it — an explicit request is never silently downgraded (N2). Docs simplify back: README Quick Start and the runbook prose teach bare `lisa init` again, flags as overrides. Safety unmoved: born repos, existing identities, existing configs byte-untouched; the offer copy keeps the no-"git" rule.

_Advances: the install path's first command works again with zero flags on every machine, chooses the strongest setup available, and says what it chose in one sentence._
