## Context

The incident fix. On 2026-07-16 a ticket with a valid pass disposition was rejected 35 consecutive times — the folder had no git identity, so every completion commit exited 1, and the scheduler retried into the void while the dashboard showed an unexplained REV stall (field journal preserved at docs/active/work/T-046-06-03/cbt-0716-211915-variant-xdg/demo-completion-journal.jsonl). Classify completion-commit failures conservatively: operator-owned causes (identity missing, repository unwritable, stale lock) retry a small fixed number of times, then park the ticket through E-048's existing machinery with a plain, forwardable ask — for the identity case: "Lisa needs a name for recording finished work. Run: `git config user.name \"You\"` and `git config user.email you@example.com` — or rerun `lisa init` and accept the history offer." Transient causes (index contention and the like) keep bounded retries without parking. Unrecognized git errors park with the raw reason as the ask, flagged unstructured — never guessed. Operator surfaces lead with the plain sentence; the journal keeps full technical detail.

_Advances: recovery is bounded across attempts at the completion boundary, exactly as E-048 made it at the review boundary — 35 silent rejections become one park and one sentence a human can act on._

## Acceptance Criteria

- [ ] Fixture tests map each failure class to its behavior: identity-missing → bounded retries then park with the identity ask; transient → retries within bounds, no park; unrecognized → park with raw-reason ask flagged unstructured; park/unpark provenance rows land per E-048's schema.
- [ ] The retry bound and each attempt are visible in the journal; no code path can reject the same completion more times than the bound without a park.
