## Context

The incident fix. On 2026-07-16 a ticket with a valid pass disposition was rejected 80 times (35 at diagnosis) — the folder had an unborn branch and no git identity, every completion commit exited 1, and the scheduler retried into the void while the dashboard showed an unexplained REV stall (field journal preserved at docs/active/work/T-046-06-03/cbt-0716-211915-variant-xdg/demo-completion-journal.jsonl; every rejected row carries the same unborn-branch failure, fired before identity was consulted). Classify completion-commit failures conservatively: operator-owned causes (unborn branch, identity missing, repository unwritable, stale lock) retry a small fixed number of times, then park the ticket through E-048's existing machinery with a plain, forwardable ask — for the unborn/identity cases: "Lisa needs a name for recording finished work. Run: `git config user.name \"You\"` and `git config user.email you@example.com` — or rerun `lisa init` and accept the history offer." Transient causes (index contention and the like) keep bounded retries without parking. Unrecognized git errors park with the raw reason as the ask, flagged unstructured — never guessed. Operator surfaces lead with the plain sentence; the journal keeps full technical detail. Same policy for the state with no exit: today a completion whose 60-second reconciliation deadline expires becomes `Rejected{ActionRequired}` (crates/lisa-core/src/completion.rs), which masks Done, refuses even operator MarkDone with a hex-laden correlation reason, and has no reset path in any CLI or UI surface — `lisa unblock` only handles `status: blocked`. Deadline expiry routes through the same park-with-ask instead of dead-ending; no completion state may be unrecoverable by an operator.

_Advances: recovery is bounded across attempts at the completion boundary, exactly as E-048 made it at the review boundary — 35 silent rejections become one park and one sentence a human can act on._

## Acceptance Criteria

- [ ] Fixture tests map each failure class to its behavior: unborn-branch and identity-missing → bounded retries then park with the history/identity ask; transient → retries within bounds, no park; unrecognized → park with raw-reason ask flagged unstructured; park/unpark provenance rows land per E-048's schema.
- [ ] Deadline expiry parks with an ask instead of dead-ending: a `Rejected{ActionRequired}` completion is reachable back to schedulable through the ordinary unpark path, and a fixture test proves the operator can recover it without editing journal files.
- [ ] The retry bound and each attempt are visible in the journal; no code path can reject the same completion more times than the bound without a park.
