## Context

`lisa init` writes two files into the repository root that are not Lisa's to write.

```rust
// crates/lisa-cli/src/init.rs ~356-368
let claude_md_path = root.join("CLAUDE.md");
if claude_md_path.exists() { /* NoOp */ } else {
    actions.push(InitAction::CreateFile {
        path: claude_md_path,
        content: templates::generate_claude_md(project),
    });
}
```

and immediately after (~370–384) the same for `AGENTS.md`, generated as a pointer at `CLAUDE.md`
so Codex and Claude share one source of truth. The scaffolding is careful — it never overwrites,
it detects the project type first (`crates/lisa-cli/src/detect.rs`) — and that is beside the
point. A context file is where a project states its standing intentions to every model that will
ever read it. Lisa seeding it with generated boilerplate biases a codebase toward whatever Lisa
guessed, in a document whose whole purpose is to be believed. Drop the practice: remove both
writes and both generators (`generate_claude_md`, `generate_agents_md` in
`crates/lisa-cli/src/templates.rs`). `lisa init` writes nothing to the repository root but
`.lisa.toml`; everything else it creates lives under `docs/` or `.lisa/`.

**The sentinel is the part that will bite.** `CLAUDE.md` is doing a second, unrelated job:

```rust
// crates/lisa-cli/src/loop_cmd.rs ~59-60
if !root.join("CLAUDE.md").exists() {
    return Err("No CLAUDE.md found. Run `lisa init` first.".to_string());
}
```

That is not a context-file check, it is an *is-this-project-initialised* check wearing a context
file's clothes. Once init stops writing `CLAUDE.md`, a correctly initialised project fails this
test and `lisa loop` refuses to start — the loudest possible regression. Swap it to `.lisa.toml`,
which init already writes (~394 onward) and which actually means what the error message claims.
Four existing tests in `loop_cmd.rs` (~765–816) construct their fixtures by writing a stub
`CLAUDE.md`; they move to `.lisa.toml`, and the same substitution applies to fixtures across the
CLI test suite — `crates/lisa-cli/tests/already_done.rs` ~21,
`crates/lisa-cli/tests/seal_visibility.rs` ~49/~132/~308, `crates/lisa-cli/src/status.rs` ~363,
and the two assertions in `crates/lisa-cli/tests/init_history.rs` ~239/~265 that pin the file
being created. Those two invert: they now pin that it is *not*.

`crates/lisa-cli/src/setup_guide.rs` is the operator-facing account of all of this and is wrong in
five places once the writes are gone: the initialised-project probe (~26), the "safe to re-run …
never overwrites CLAUDE.md" line (~35), both rows of the generated-files table (~45–46), the
"After running, edit CLAUDE.md" instruction (~56), the `auto_advance` bullet (~75, removed by
T-057-01-01), the generator explanation (~100–107), the "Edit CLAUDE.md" step (~116), and the
doctor summary line (~220). Rewrite the guide to describe what `lisa init` now does. Voice: plain,
host-side, addressed to someone setting up — say what Lisa creates and what it deliberately leaves
to them, and say the second part on purpose. An operator who used 0.4 will look for the missing
step; the guide should answer them before they ask.

Do not touch `AgentClient::context_file()` (`crates/lisa-core/src/client.rs` ~62–68) or the
assignment prompt here — T-057-01-04 retires those together.

_Advances: P1 — preserve the repository, in its widest reading: Lisa does not author content in a
project's root that the operator did not ask for. And N4 — the sentinel swap is the smallest
change that keeps `lisa loop` working, not a redesign of init's preflight._

## Acceptance Criteria

- [ ] `lisa init` on an empty project creates no `CLAUDE.md` and no `AGENTS.md`. Existing
      assertions in `crates/lisa-cli/tests/init_history.rs` ~239/~265 are inverted to pin this.
- [ ] `lisa init` on a project that already has a hand-written `CLAUDE.md` or `AGENTS.md` leaves
      both byte-identical and reports neither as an action. Tested — the common upgrade path is a
      project that has one.
- [ ] `generate_claude_md` and `generate_agents_md` are removed from `templates.rs`, along with any
      project-type template data that no other caller uses.
- [ ] **The regression this ticket is named for:** `lisa loop` starts in a project that has
      `.lisa.toml` and no `CLAUDE.md`. A test asserts it, and a second asserts the refusal still
      fires — with a message naming `.lisa.toml` — when the project is genuinely uninitialised.
- [ ] No fixture in the CLI test suite writes `CLAUDE.md` to satisfy an initialisation check.
- [ ] `lisa setup-guide` and `lisa doctor` describe the files Lisa now creates, name none it
      does not, and state plainly that the project's own agent context file is the operator's to
      write. No output string mentions `auto_advance`.
- [ ] `just check` green (fmt, clippy, WASM check, workspace tests).
