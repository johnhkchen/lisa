## Context

**Read `S-069-01` first.**

`johnhkchen/homebrew-lisa` carries one formula. Verified on the Mac mini,
2026-08-14:

```
Library/Taps/johnhkchen/homebrew-lisa/Formula/
  lisa.rb
```

One formula cannot carry three channels, so today a Mac joins the fleet by leaving
Homebrew. Homebrew's own answer to this is a second formula — `python@3.11` and
`postgresql@16` are the same idea — and it needs no explaining to anyone who has
installed anything.

`dist-workspace.toml` pins `tap = "johnhkchen/homebrew-lisa"`, `formula = "lisa"`,
`publish-jobs = ["homebrew"]` and `publish-prereleases = true`. cargo-dist emits
exactly one formula, so the other two have to be materialised by the release
workflow rather than wished for in config.

## Acceptance Criteria

- **Three formulae in the tap**, and installing one is the whole act of choosing a
  channel: `lisa` (stable), `lisa-nightly`, `lisa-canary`. Someone who has never
  read Lisa's docs can guess all three from the first.
- **`lisa` keeps meaning stable, and stops meaning "newest of anything."** Today
  `publish-prereleases = true` puts release candidates on the one formula. After
  this ticket, an rc reaches `lisa-canary` and never `lisa`. **This is a behaviour
  change for every existing brew install** — say what happens to a box already on
  `lisa` when the next rc ships, and make it the quiet, correct thing.
- **The three cannot be installed at once.** `conflicts_with` between them, so a
  machine has one Lisa and one channel, and `brew` says so rather than PATH order
  deciding.
- **The formulae are generated, not hand-maintained.** cargo-dist writes one; the
  release workflow derives the others from it. A formula that drifts because
  somebody forgot to bump it by hand is the failure this whole story is about.
- **`brew upgrade` alone does the right thing on each channel**, with no Lisa
  command in the path.
- **A verify script covers it, the way `scripts/verify-shell-installer.sh` and
  `scripts/verify-apt-repository.sh` already cover their channels.** Install each
  formula in a throwaway prefix, assert the version it lands on, and assert the
  conflict.

## Notes

- `lisa-canary` publishes on every tag, which is what canary means. `lisa-nightly`
  is the one that must wait — that promotion is `T-069-01-03` and this ticket only
  has to leave a formula for it to write into.
- Worth deciding in review: whether `lisa-nightly` and `lisa-canary` are `keg_only`.
  `conflicts_with` alone may be enough, and `keg_only` would put them off `PATH`,
  which is not what a machine that runs Lisa wants.
- The mini is the first real reader of this. Once these formulae exist, its setup is
  `brew install lisa-nightly` and nothing else — no uninstall, no second install
  method on the box.
