## Context

**Read `S-070-01` first.**

`lisa schedulers` on the `renderer` board, 2026-08-14, in full:

```
1 scheduler is running on this board.

  renderer (renderer-4cd787ad)  — not running
    started 4h ago, stopped stamping 4h ago, zellij server pid 62793
  renderer (renderer-0933474d)  — not running
    started 4h ago, stopped stamping 4h ago, zellij server pid 62793
  renderer-2 (renderer-2-93ea8bf4)  — not running
    started 4h ago, stopped stamping 52m ago, zellij server pid 71809
  renderer-3 (renderer-3-49ded6ab)
    started 45m ago, last seen 87s ago, zellij server pid 15340
```

**The headline says one and the list shows four, three of them marked `not
running` and one marked nothing at all.** The one that is running is
distinguished by the *absence* of a label, which is the hardest difference to
see and the only one that matters.

`head -8` of that output — a reasonable thing to type — shows the count and then
two schedulers that are not running, and nothing else. It reads as a
contradiction, and on the night this was found it cost several minutes of
looking for a fifth entry.

## Why this is worth fixing and not just tolerating

This command is reached for at exactly one moment: something is wrong and an
operator is trying to find out what is holding the board. It is the first thing
`release-seats` tells you to run. **A first line that disagrees with the body is
worst at the moment the command is most used.**

## Acceptance Criteria

- **The running one is marked, not the stopped ones.** Whatever is true of a
  live scheduler is said out loud on its line rather than inferred from a missing
  word.
- **The count and the list agree**, or the count says what it is counting —
  `1 of 4 schedulers is running` is a sentence that survives being read alone.
- **The live one is not last.** An operator truncating the output must see the
  answer, not the history.
- **`--stop <id>` still takes any of them**, running or not: `T-070-01-01` makes
  stopping a dead one the ordinary case, and this output is where the id is read
  from.
- Reproduce it: leave several dead scheduler records on a board, start one, run
  `lisa schedulers | head -8`, and have the first eight lines be true and
  sufficient.

## Notes

- The per-line detail is genuinely good and should not be lost: `started 4h ago,
  stopped stamping 52m ago` tells you the shape of the failure in six words. The
  problem is only the summary above it and the ordering below it.
- `stopped stamping 4h ago` and `last seen 87s ago` are two phrasings of one
  fact. Worth deciding in review whether they should be one.
