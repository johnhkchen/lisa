## Context

Implement Tier 2. When the resolved seal is `journal`, completion gates on the review disposition plus a journal row carrying SHA-256 content-hashes of the ticket file and every artifact under the ticket's work directory (crates/lisa-core/src/completion.rs, crates/lisa-plugin/src/completion_journal.rs). Fail-closed: an artifact that cannot be read and hashed blocks completion with a named reason — the journal seal is a lesser seal, never a lax one. The status flip and work-trail retention reuse the commit path's atomic-publication discipline minus the commit itself. Rows are labeled `seal: journal` per T-049-01-02. Depends on T-049-04-01 to serialize edits in the completion path — one pair of hands in completion.rs at a time.

_Advances: a bare folder finishes its tickets with a fail-closed, tamper-evident, honestly-labeled record — the strongest seal its environment supports, never a wall._

## Acceptance Criteria

- [ ] Fixture tests: journal-sealed completion succeeds in a repo-less project with hashes verifiable against the artifacts; mutating an artifact after sealing makes the recorded hash detectably stale (audit demonstration); an unreadable artifact blocks completion with a named reason.
- [ ] The completion journal row carries `seal: journal` and the hash set; the ticket status flip is atomic under the same hostile-interruption tests the commit path uses.
