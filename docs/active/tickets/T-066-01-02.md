## Context

**Read `S-066-01` first.**

`lisa loop` cannot start without a controlling terminal. Measured, and recorded in
`screen-design`'s `T-014-03`:

```
$ lisa loop --path ~/swe/repos/steer
could not enable raw mode: Os { code: 6, message: "Device not configured" }
Error: zellij exited with status: exit status: 101
```

Every consumer works around it the same way — by owning a pane. `rail loop`,
shipped 2026-08-13, is exactly that workaround made supported: *"ask the strip on
a project to start a run. Needs no terminal."* The strip has a pane, so the loop
gets a terminal.

**That answer runs out on a host with no GUI at all.**

`screen-design`'s `S-016` describes the desk the operator actually has: six
projects across three machines, one of them a GitHub Codespace reached by
`gh codespace ssh`. The reach works, `lisa status --json` reads the board, and
`rail desk` draws it. There is no wezterm there and no pane to spawn into, so
that board can be watched and never worked.

### What is actually needed

Not attaching — `loop_cmd.rs:65` settled that, in writing, and the reasoning
stands. Not a daemon. **A way to run a board where the only thing available is a
process.**

zellij is doing two jobs today: it gives each agent a pane with a terminal, which
agents genuinely need, and it draws a dashboard, which is for a person. On a
headless host the second job has no audience and the first still has to happen
somehow.

## Acceptance Criteria

- **A board runs on a host with no GUI and no wezterm**, started from an SSH
  session, and the agents in it get whatever terminal they actually require.
- **Say what is lost.** The plugin's dashboard is a person's view; on a headless
  host name what replaces it — `lisa status --json` polled from elsewhere is a
  defensible answer if it is stated rather than assumed.
- **One scheduler, still.** Everything `S-063-01` cost applies here and is harder
  to see without a dashboard: `T-065-01-03`'s refusal must hold on a host where
  nobody is looking.
- **It does not become the default anywhere a GUI exists.** The pane-per-agent
  arrangement is good and this is a fallback for hosts that cannot have it, not a
  replacement.
- **Signals and hooks behave identically.** `pane-N.started`, `.alive`,
  `.heartbeat` and the lease markers are what the scheduler runs on; if "pane"
  stops meaning a zellij pane, say what it means and show the hooks still writing.
- Reproduce it somewhere genuinely headless — a container, a Codespace, or
  `ssh -T` with no pty — rather than by unsetting a variable on a Mac.

## Notes

- Medium rather than high: five of the operator's six projects are on machines
  with a GUI, and `rail loop` covers those today. This is the sixth.
- Related to `S-016`'s asymmetry, which named this and did not solve it: a
  Codespace *"can be read and started but never spawned into"*. Half of that
  sentence is currently untrue.
- Worth checking before designing: `agent-exec` already runs Codex and turns its
  output into pane signals without a TUI in the loop. Whether that is the seam
  this wants, or a different one, is the first question.
