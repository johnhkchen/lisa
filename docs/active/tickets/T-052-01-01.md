## Context

Every activity line renders its age as `495696h 11m` — seconds-since-1970 dressed up as a duration. The mechanics: `log_activity` (crates/lisa-plugin/src/lib.rs, ~line 3327) pushes a bare `ActivityEvent` (the core enum carries no time field in any variant — crates/lisa-core/src/types.rs, ~line 976), and the UI conversion hardcodes `let timestamp = Duration::ZERO;` (lib.rs ~9066) into an `ActivityEntry.timestamp` field that has existed and waited all along (crates/lisa-plugin/src/ui.rs, ~line 299). `current_time` is genuine wall-clock (`SystemTime::now()` at lib.rs ~8973 — the WASI-clock pattern used throughout the plugin), so `format_time_since` (ui.rs ~1009) faithfully computes now − 0. Capture wall-clock at the moment `log_activity` runs and carry it through the conversion; where the pair lives (a tuple in the `activity_log` Vec, or a small wrapper struct local to lib.rs) is design's call — the core enum only grows a field if research finds a consumer that needs time inside it. Then replace the `NNNNh MMm` composite with coarse human buckets: "just now" under a minute, then "Nm ago", "Nh ago", "Nd ago". The five-second timer render (lib.rs ~80, ~8637) already recomputes `current_time` each pass, so ages tick with no new plumbing.

_Advances: the feed's clock stops lying — every line answers "how long ago" in words a person uses (P2, P4)._

## Acceptance Criteria

- [ ] Entries record wall-clock at emit; with an injected clock, a fresh entry renders "just now" and reads "1m ago" once the clock passes sixty seconds (unit tests, no sleeps).
- [ ] The feed renders only the four bucket shapes — just now / Nm ago / Nh ago / Nd ago — in both the full and filtered activity renderers; the `NNNNh MMm` composite is gone from the feed.
- [ ] Negative fixture pinned: an entry carrying the epoch-zero timestamp (the exact shape that produced 495696h) renders a bounded fallback such as "—", never an hours figure — the 2026-07 field bug cannot come back unannounced.
- [ ] No new time source: capture uses the same `SystemTime::now()`/`UNIX_EPOCH` pattern the plugin already relies on, and the WASM target builds clean (N4).
- [ ] `just check` green (fmt, clippy, WASM check, workspace tests).
