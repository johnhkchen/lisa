## Context

**Read `S-066-01` first.**

`lisa status --json` says everything about a board except **where it is being
worked**. No session, no pane, no host — not in `run_summary`, not anywhere.

Lisa already has the fact. `second_scheduler_refusal` in
`crates/lisa-cli/src/loop_cmd.rs` computes `running_here` and `current_session`,
and emits them only as prose inside a refusal:

```
look at it with: zellij attach fascinating-drum
```

### Who is asking, and what they do without it

**`rail up`**, shipped 2026-08-13, puts *"a strip beside any loop that has lost
one"*. To find such a loop it must inspect panes and infer which ones are running
a board. If the board named its own session, adoption is a lookup.

**A phone over SSH.** `rail desk` shows 26 boards from a phone; a run worth
looking at can only be reached by guessing a zellij session name, or by `lsof`
across every server — which is what this desk actually did on 2026-08-12 to find
three schedulers.

**Every recovery command.** `release-seats` and `reset-ticket` both refuse while a
run holds a board, and both tell the operator to go find it. Neither can say
where.

This is the same addition as `T-064-01-01`, which put the client and model into
`config` because a consumer was otherwise going around the envelope for a fact
lisa held.

## Acceptance Criteria

- **The envelope says where the run is** when there is one: at minimum the
  session that holds it, and whatever else identifies it on a machine with
  several — this desk has had seven zellij sessions at once.
- **Absent means absent.** A board with no run says so, distinguishably from a
  board whose run cannot be identified. Those are different and today both are
  silence.
- **A finished-but-resident run is not reported as running.** That distinction is
  `T-065-01-01`'s subject and the reason a second scheduler started here on
  2026-08-12; whatever this field says must not reintroduce it.
- **Additive within `schema_version: 1`.** A consumer pinned to the current
  version keeps working. `rail/src/lisa_json.rs:401` already refuses an envelope
  newer than it understands, so the discipline exists on the other side.
- **Nothing that only makes sense on this machine.** A session name is portable
  enough to be useful over `gh codespace ssh`; a pid or a socket path is not. Say
  what travels and what does not.
- The `json-guide` names the new field with the same stability promise as the rest.
- One test with a run, one without, and one where the board is resident but done.

## Notes

- The refusal string keeps working exactly as it does. This is not a replacement
  for prose an operator reads; it is the same fact where a program can reach it.
- Cheapest now, for the same reason `T-064-01-01` was: one consumer,
  `schema_version: 1`, additive. After a second reader it is a negotiation.
- Worth deciding in review: whether this belongs in `run_summary`, which today is
  about what a run *did*, or beside it as something about what a run *is*.
