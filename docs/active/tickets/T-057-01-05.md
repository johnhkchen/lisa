## Context

Lisa's contract document is named after a workflow that no longer exists. RDSPI is
Research-Design-Structure-Plan-Implement; four of those five are gone. Rename it to
`lisa-workflow.md` and rewrite it to describe the system the four tickets before this one built.

**The rename, and the migration that must come with it.** The document is embedded at compile
time from `crates/lisa-cli/data/rdspi-workflow.md` (`crates/lisa-cli/src/templates.rs` ~5–11) and
installed by `plan_owned_template` (`crates/lisa-cli/src/init.rs` ~257–283, called ~386–392),
whose safety rule is the one to preserve exactly:

```rust
Ok(existing) if existing == current       => NoOp,
Ok(existing) if known_prior.contains(...) => UpdateFile,   // an unmodified Lisa template
Ok(_)                                     => SafetySkip,   // the operator's file now
```

`LEGACY_RDSPI_WORKFLOWS` (~15–18) holds the byte-exact prior generations that make the middle arm
work. Renaming the path means a project upgrading from 0.4 has an `rdspi-workflow.md` that init
no longer looks at — leaving a stale document on disk that contradicts the live one and still
matches what old prompts pointed at. Handle it under the same rule and no looser: the current
0.4.4 text joins `LEGACY_RDSPI_WORKFLOWS`, and `docs/knowledge/rdspi-workflow.md` is removed
**only** when its bytes match a known Lisa generation. A modified one is left exactly where it is
— it is the operator's file, and deleting it would be the first thing Lisa ever destroyed that a
person wrote.

**The rewrite.** The outgoing document (`data/rdspi-workflow.md`, 146 lines) is roughly half phase
chapters — ~7–37 specify the four deleted artifacts, ~88–101 are the Phase Rules that justify
them, including Rule 5's promise that artifacts are insurance. All of that goes. What stays is
everything the document already got right, most of it landed by S-056-01 and none of it in scope
to change: the Review disposition schema, the `remedy_owner` vocabulary, the check-execution
contract (~61–69), how to write an `ask` for a bystander (~71–76), the seal-gated completion
boundary, the ticket format, and the concurrency/DAG rules.

Two things need writing rather than deleting:

- **What replaces the insurance.** Rule 5 told the truth: artifacts let a dead session resume at
  the right phase. Commits do that job now in commit-sealed projects, and in journal-sealed ones
  nothing does — a ticket that dies mid-work restarts from the beginning. Say so plainly, in the
  document, where the person it affects will read it. A known limitation stated is operable; the
  same limitation discovered is a bug report.
- **The phase list, four entries long,** and the fact that Lisa still detects `review.md` and
  advances the ticket itself.

Then the surfaces that name the old thing: `README.md`, `CONTRIBUTING.md`, this repository's own
`CLAUDE.md` (the "RDSPI workflow" line at the foot) and `AGENTS.md`, `docs/ROADMAP.md`,
`crates/lisa-cli/src/check_run.rs` ~7 and `crates/lisa-core/src/disposition.rs` ~26 (both doc
comments citing the path, the second pinned against the document by test), and
`crates/lisa-cli/tests/fixtures/live_provider_startup.sh`. `docker/chromebook-test/board/` holds a
fixture board whose tickets use retired phase values — good news, and worth keeping: it is a live
exercise of T-057-01-01's forward mapping. Leave `docs/archive/**` alone; it is history.

**Voice.** This is the document an operator opens to learn what Lisa does. Plain English, no
ceremony, and shorter than 146 lines — the deleted phases were most of its bulk and the
replacement should not quietly refill it.

_Advances: P1 — an operator's modified copy of a Lisa template is never destroyed by a rename.
And P4 — the document is the operable account of the system; leaving it describing a workflow the
code no longer runs is the documentation form of a state that does not mean what it says._
