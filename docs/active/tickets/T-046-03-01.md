## Context

Make the Linux artifact independent of the target's Debian release. Add `x86_64-unknown-linux-musl` and `aarch64-unknown-linux-musl` to dist-workspace.toml targets and make musl what the shell installer serves on Linux (current gnu builds carry a glibc-2.35 floor from ubuntu-22.04 runners — older containers can't even exec them). Move `install-path` from `CARGO_HOME` to `~/.local/bin` so a Rust-less machine stops growing a `~/.cargo`, with plain PATH guidance printed by the installer. The CI build-setup must still embed a verified non-empty WASM plugin in musl builds, and the release build bakes in the managed-runtime sha256 manifest consumed by T-046-02-02.

_Advances: one artifact that runs on unknown-vintage Debian — the machine's age stops being our failure mode; installer stops implying Rust is involved._

## Acceptance Criteria

- [ ] `dist plan` lists both musl targets; a built musl `lisa` runs on a Debian bullseye (glibc 2.31) container and is verified statically linked; fat-LTO link behavior on CI runners confirmed, not assumed.
- [ ] The installer places the binary in `~/.local/bin` and prints a brand-voice PATH note; CI verifies the embedded WASM is non-empty in musl artifacts.
