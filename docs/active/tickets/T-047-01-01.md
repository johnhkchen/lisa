## Context

The landing-probe pair (docs/knowledge/landing-probes/) proved that living inside a loop session teaches an agent the actors but not the benefit — no probe page has ever said "you don't babysit this," because no runtime surface says it. Two changes: (1) the context Lisa injects into agent sessions — the workflow preamble and assignment framing in crates/lisa-cli/src/templates.rs — opens with the purpose paragraph landed by T-046-07-02, reused byte-for-byte, before any workflow mechanics; (2) a post-run narrative: when a loop session ends, and in `lisa status` when the board state makes it true, Lisa states the win plainly with real values — tickets completed, zero manual approvals requested, evidence at .lisa/provenance.jsonl / the completion journal / per-ticket work docs. The summary reports only true state: a run with failures or manual interventions says so, ledger paths are named only when the files exist, and nothing is inferred.

_Advances: the run explains itself in words a nontechnical person would repeat; reporting only — no scheduling, completion, or state-machine behavior changes._
