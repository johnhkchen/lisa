## Context

When even condensed labels exceed the pane, the remaining honest move is a viewport. Vertical already works this way: `scroll_offset` (crates/lisa-plugin/src/lib.rs ~896), j/k and arrows (~8219–8226), skip/take in `print_dashboard` (crates/lisa-plugin/src/ui.rs ~1660), reset on view switch (~8189). Add the horizontal twin for the DAG view only: [h]/[l] (plus Left/Right) shift a column offset clamped to `widest_line − cols`, reset on view switch, inert in other views and whenever the map fits. The hazard that names this ticket: by slice time each line carries injected ANSI (the post-processor wraps ids and, since T-054-01-01, status ink in escape codes), and a naive byte or char slice shears an escape sequence in half — the pan must count *visible* columns and cut cleanly (slice the raw line then re-apply colorization, or an ANSI-aware slicer; design decides, with the rationale in design.md). T-054-01-02's indicator line gains the key names ("[h]/[l] to pan") so the affordance announces itself exactly when it applies.

_Advances: nothing on the board is unreachable — the operator pans to the clipped edge instead of resizing panes or squinting at wrap garbage (P4)._

## Acceptance Criteria

- [ ] On a condensed-but-overflowing fixture: [l]/Right reveals the clipped columns, [h]/Left returns, both clamped at the edges; the offset resets on view switch (mirroring the vertical pattern's behavior).
- [ ] The escape-sequence walk: a fixture pans a fully colored board through every valid offset, asserting each emitted line contains only intact ANSI sequences and the correct visible text — this is the ticket's negative fixture; a naive slicer fails it.
- [ ] Pan keys are inert in Operations/Activity/Present views and on any map that fits (no state changes, verified).
- [ ] The overflow indicator names the pan keys, and only when overflow exists.
- [ ] `just check` green (fmt, clippy, WASM check, workspace tests).
