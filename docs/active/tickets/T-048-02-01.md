## Context

Today an operator discovers why a ticket is parked by reading work-dir JSON full of engineering prose — the "huh? what's all this jargon?" moment, arriving exactly when the system needs the human most. Build the human surface: `lisa status` (and the dashboard's existing line rendering) opens with a **Waiting on you** section when operator-owned parks exist — one line per ticket showing the `ask` verbatim, nothing else; world-owned parks get a one-liner noting Lisa checks on its own. `lisa unblock <id>` resumes a parked ticket: if a `check` exists it runs first (read-only, timeout-bounded) and on failure declines in plain words quoting what it observed ("that didn't work yet — the key link still returns 404"), never a stack trace; on success or no-check it flips status back to open. Copy follows the brand voice: name the action, not the subsystem. Depends on T-046-07-01 to serialize main.rs copy edits.

_Advances: the person who is totally out of the loop reads one sentence and knows what to do — operable at a glance at the exact moment it matters; unblock verifies and resumes, it never remediates._

## Acceptance Criteria

- [ ] Fixture tests: a board with one operator park renders the Waiting-on-you line with the ask verbatim; `lisa unblock` with a failing check declines with the plain-words message and leaves the ticket parked; with a passing or absent check it unparks and the next scheduling pass seats the ticket.
- [ ] Checks run with a timeout and are proven non-mutating (a check attempting a write in a read-only fixture fails safely and is reported plainly); all new user-facing strings are asserted in tests and jargon-free per the brand-voice rule stated in the story.
