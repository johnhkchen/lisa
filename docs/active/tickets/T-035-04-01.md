## Context

S-035-01 made fresh shell delivery bounded and added a positive provider-start signal, but its completed implementation still embeds the assignment as a positional argument inside the attempt launch script and treats process start as the ownership boundary. A running provider is not proof that it received the ticket.

Split fresh assignment into two positively observed stages. Atomically write the full attempt-specific instructions to a private assignment file. Launch bare Codex or Claude with only lifecycle environment, provider flags, and model selection—never the ticket prompt as a CLI positional argument or shell payload. A matching SessionStart moves `Starting` to `ReadyForAssignment`. Lisa then injects a bounded, attempt-tagged chat message telling the provider to read the assignment file and surfaces `Delivering`. Only matching provider-specific prompt submission/acceptance evidence moves the seat to Owned. A missed chat delivery resolves boundedly without misclassifying the provider as an owned hard-silent agent.

_Advances: P2 — State means what it says; P4 — Operable at a glance; P5 — deterministic field-failure regression; E-035_

## Acceptance Criteria

- [ ] Fresh provider launch commands/scripts contain no ticket assignment or prompt argument; their length is bounded by lifecycle identity, provider flags, and model selection. The complete instructions are atomically written under the exact attempt lease.
- [ ] Native state tests prove `Starting → ReadyForAssignment → Delivering → Owned`: matching process start reaches only ReadyForAssignment, Lisa injects a bounded attempt-tagged chat reference, and only matching prompt submission/acceptance evidence reaches Owned.
- [ ] Codex and Claude may use provider-specific hook evidence, but both reject stale ticket/attempt acknowledgements and expose the same scheduler/dashboard states.
- [ ] A missing prompt acknowledgement never reaches Owned. It retries chat delivery or gracefully recycles the started provider within one bounded recovery path; it is not reported as an owned agent timeout and does not loop indefinitely.
- [ ] Existing E-033 acknowledgement, E-034 lease fencing, S-035-01 startup signals, pane naming, and full workspace tests remain green.
