## Context

The DAG view is the only dashboard surface that ignores its pane: `render_dashboard_lines` hands width to the Operations preset but dispatches the DAG view with none at all (crates/lisa-plugin/src/ui.rs ~1253; `render_dag_view`'s signature ~1288 takes no width); `print_dashboard` (~1660) clamps vertically only. Past the pane edge the terminal decides — the 49-ticket field board clipped its deepest rows mid-node. Thread the pane's true `cols` through — noting that renderers today see a pre-clamped `cols.min(100)` (ui.rs ~1669); the DAG fit decision reads the real pane width past that clamp, which stays in place for the text presets — then make the fit decision: render with today's full labels (`format!("{} {}", t.id, status_str)`, ~789), measure the widest raw line before color injection (ANSI must never count as ink), and if it exceeds the pane, re-render once with condensed labels — `T-` prefix and status token shed, `[T-015-04-02 RDY]` → `[15-04-02]`, status carried by T-054-01-01's paint (recolor the id by status, or a one-glyph marker — design decides; pinned: blocked/working/ready distinguishable at a glance, choice recorded in design.md). ascii-dag stays the layout owner (`DAG::from_edges(...).render()`, ~812; the bracket chrome is its, not ours). A board that fits keeps full labels — condensing triggers on overflow only. When even condensed spills, append one plain indicator line stating the overflow in columns; silent clipping retires. Epic-prefix elision on single-epic boards: record as a design option, do not build.

_Advances: the map sheds ceremony before it sheds nodes — six columns of `T-` and ` RDY` per node buy back a third of the board's width exactly when it matters (P4)._
