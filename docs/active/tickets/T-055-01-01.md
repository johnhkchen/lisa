## Context

`TransactionLock::acquire` (`crates/lisa-cli/src/commit_transaction.rs` ~388–406) opens
`.git/lisa-commit.guard` and takes it with a single `guard_file.try_lock_exclusive()`. There is
no retry and no backoff. A second transaction arriving while the first holds the guard gets
`EWOULDBLOCK` and the call converts it straight into an error:

```
commit transaction is temporarily locked by a live holder (guard …): Resource temporarily
unavailable (os error 35)
```

At `max_threads = 1` this is unreachable. At 4 it is a coin flip on every pair of completions
that land together, and the field run lost that flip. The guard is doing its job — it is
serializing — but it serializes by killing the loser instead of queueing it, and a commit
transaction is precisely the operation that should wait a moment rather than fail.

The error text already calls the condition *temporary*. Nothing in the code treats it that way.

Make the acquisition wait: bounded blocking with a timeout, so a transaction that arrives during
another's commit takes its turn rather than dying. The timeout matters — an unbounded wait would
trade a spurious failure for a hang, and N2 asks that this end in a named state either way. When
the wait does expire, that is a genuinely different condition from "someone held it for 40ms"
and should say so.

Two things to leave alone. The marker file (`COMMIT_LOCK_FILE`, ~264) and its ownership record
are a separate mechanism with a separate purpose — this ticket does not touch them. And the
guard must still be exclusive: waiting is the change, not sharing (N4).

_Advances: at-most-one-commit already holds; this stops the mechanism that enforces it from
manufacturing failures under the concurrency the config invites (P1)._

## Acceptance Criteria

- [ ] Acquisition retries on `EWOULDBLOCK` until a bounded timeout, rather than failing on the
      first attempt. The guard remains exclusive throughout.
- [ ] **The concurrency fixture this story is named for:** four commit transactions dispatched
      concurrently against one repository all seal, each producing exactly one commit, with no
      `os error 35` on any path. This fixture is reused by T-055-01-02 and T-055-01-03 and
      should be written to be shared.
- [ ] Timeout expiry is a distinct, named error from a transient collision, and its message says
      how long it waited — an operator reading it can tell "the guard is genuinely wedged" from
      "we were unlucky".
- [ ] A test proves the timeout path: a held guard that is never released produces the timeout
      error within the bound, and does not hang.
- [ ] The marker file and its ownership record are untouched.
- [ ] `just check` green (fmt, clippy, WASM check, workspace tests).
