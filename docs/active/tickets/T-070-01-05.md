## Context

**Read `S-070-01` first.** That story is about runs that died and could not be
put down. This is about telling, at a glance, which ones those are.

A run's session is named after its project, and a taken name is numbered around:
`steer`, then `steer-2`, `steer-3`. `session_name.rs` says why the number
exists:

> *"Zellij refuses a duplicate name outright, and being dead is no exception …
> A crashed run leaves exactly that behind, so a dead taken name never stops the
> loop here: the next free numbered name is used instead."*

**So the number counts the dead, and says nothing else.** `steer-3` means two
sessions of that name came before it and are gone. It does not say when this one
started, and *when* is the only thing a person actually asks.

The operator's proposal, 2026-08-15:

> *"maybe instead of steer-8, lisa-9 or whatnot we can use a MMDD format which
> should help us implement a staleness check?"*

## What made this worth asking

`zellij list-sessions` on the dev desk this morning: **320 EXITED sessions**,
against four live ones. Every one of them was a finished or crashed run, and the
oldest was three months old. They were cleared with `zellij delete-all-sessions`
— which also **resets the counter**, so the next `steer` run is `steer` again
and the number now means something different than it did yesterday.

A name that counts the dead loses its meaning the moment the dead are swept.

Judging staleness today means `zellij list-sessions` and reading a `Created 10h
32m ago` column, or `lisa schedulers` and reading `stopped stamping 13h ago`.
Both are available and neither is in the name — so the name, which is what the
tab shows and what `--stop` takes, is the one place the answer is not.

## Acceptance Criteria

- **A session's name carries when it started.** `steer-0815` at minimum; say
  whether the day is enough.
- **Two runs of one project on one day do not collide.** This is the real
  design question, because it is the ordinary case on this desk — `renderer` had
  **six** sessions on 2026-08-14. `MMDD` alone cannot express that. Say what
  does: a time as well as a day, a number after the date, or something else —
  and say what it costs in width, because the name is read off a terminal tab
  that already truncates.
- **It stays a legal Zellij name and a legal directory.** The constraints this
  module already states hold: ASCII, never empty, no `/`, no leading or trailing
  `-`, and short enough to survive a truncating tab.
- **The project is still the first thing you read.** The name exists because
  three animals told you nothing about which repository was which; a date must
  not push the project name out of the visible part of a tab.
- **Nothing that reads a session name by hand breaks.** `lisa schedulers
  --stop`, `zellij kill-session`, `rail`'s station beacons and `BoardSessions::
  running_here` all take or match these names. Say which ones parse the name for
  meaning rather than treating it as opaque.
- **A staleness check is actually implemented, not merely made possible.** The
  proposal's own reason. Somewhere — `doctor`, `schedulers`, `clean` — should
  say *this session is from a previous day* using the name.
- Reproduce it: start two runs of one project on one day, and have both names
  say when they started and be distinguishable.

## Notes

- **`clean` already knows how to be careful here** and should be the model: it
  removes finished attempt folders and lists what it left alone with a reason.
  A sweep of stale sessions by date would fit beside it.
- Worth deciding in review: whether the date belongs in the session name or in
  the *scheduler id*, which already carries a start time —
  `renderer-5-c1133916` — and is what `--stop` takes. The scheduler id is
  machine-facing and can afford width; the session name is read by a person off
  a tab and cannot. **They may want different answers**, and this ticket should
  say so rather than assume one.
- The counter's dependence on what has been swept is its own small trap: the
  same run is `steer-3` on a desk that has never been cleaned and `steer` on one
  that just was.
