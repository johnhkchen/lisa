## Context

Two closers for the incident. Lock hygiene: the 2026-07-16 stall left `.lisa-commit.lock` in the project root — the commit transaction (crates/lisa-cli/src/commit_transaction.rs) must release its lock on every failure path, and a stale lock from a dead process must be detected and named (age + absent holder) rather than compounding a stall; a live holder is respected. Field replay: build the regression from the preserved journal (docs/active/work/T-046-06-03/cbt-0716-211915-variant-xdg/demo-completion-journal.jsonl) — reconstruct the identity-less environment and assert that under the new policy the same situation produces exactly one bounded retry sequence, one park carrying the identity ask, zero further attempts, and no lock left behind. The 35-rejection churn becomes this epic's permanent regression evidence, per the house rule that a real failure is closed by a reproduction, not a plausible patch.

_Advances: failed transactions clean up after themselves, dead locks are named instead of feared, and the incident that motivated the epic can never quietly return._

## Acceptance Criteria

- [ ] Lock tests: every failure path releases the lock; a stale lock (dead holder) is detected, named in the operator-facing reason, and recovered; a live holder is never stolen.
- [ ] The field-replay regression runs in CI: identity-less environment → one bounded retry sequence, one park with the identity ask, no residual lock; the test cites the preserved journal as its source.
