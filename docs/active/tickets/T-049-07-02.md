## Context

Stronger at the source. The T-046-06-03 reviewer wrote a legacy-format block — bare prose, no structured ask — and every downstream surface had to coerce and compensate. Catch that where it is cheapest: in the reviewer's own pane, before Review ends. Add a CLI check (`lisa check-disposition <ticket-id>`, crates/lisa-cli) that validates the written review-disposition.json against the full contract: schema for all three classes (pass strict, block structured, note with criterion quote + evidence citation per T-049-06-01), the class rules (no work-quality complaints in a note), and the ask floor (a block's ask leads with a plain actionable sentence, per T-049-05-02's rules — shared string source, one place). Failures print pane-visible messages naming the exact fix. The Review phase instructions in docs/knowledge/rdspi-workflow.md direct the reviewer to run the check and correct before finishing (bundled copy stays in sync per templates.rs). The fallback coercion path remains — a reviewer that skips the check still parks safely — but with the check in the ritual, legacy output becomes a rarity instead of the norm the surfaces are built around.

_Advances: dispositions are validated where malformed output costs seconds, not operator context — the guard system's input gets as much care as its output._

## Acceptance Criteria

- [ ] Check tests: well-formed pass/block/note each pass; malformed schema, a note missing citations, a work-complaint note shape, and an ask-floor violation each fail with a message naming the fix; the ask-floor rules live in one source shared with the rendering path, pinned by string tests.
- [ ] The workflow doc's Review section instructs the check before finishing; the bundled-copy sync test passes; the coercion fallback still handles an unchecked legacy block (existing S-049-05 tests unchanged).
