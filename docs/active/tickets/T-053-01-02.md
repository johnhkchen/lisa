## Context

The MarkDone modal understands navigation and confirm/dismiss and nothing else — arrows and their j/k aliases, Enter, Esc/q (crates/lisa-plugin/src/lib.rs ~8150–8182) — there is nowhere to say *why* a ticket should be done, which is half of why the guard can only reject. Give the modal a second step instead of a text box: after ticket selection, a reason step listing the canned catalog from T-053-01-01, with the ticket's current ask (from its Block disposition) displayed in plain language above the choices and a recommended default preselected — decide with context, sign with Enter, back out with Esc at either step. The rejection dead-end goes away: [d] on an override-eligible ticket flows into the reason step (what the guard would have said becomes context above the choices, not a wall), so every ticket the modal lists leads somewhere — straight-through completion when the disposition already authorizes it, the reason step when it doesn't. Choices, not essays: no free-text input is added, deliberately — the catalog is the vocabulary, and an operator who needs a sentence the catalog can't say is holding a send-back, not a note.

_Advances: the advertised lever works — four keypresses from "attention needed" to sealed-with-receipt, and the UI stops promising a transition the state machine refuses (P4; N3's specimen retired)._

## Acceptance Criteria

- [ ] Happy path is ≤4 keypresses from the Operations view: [d] → ticket → Enter on the recommended reason → sealed; each step Esc-reversible; the key sequence demonstrated in progress notes.
- [ ] The reason step shows the block's ask verbatim above the catalog; on fail-closed tickets it says plainly that no review is on file — never a raw parse error or rejection dump.
- [ ] No dead ends: every ticket `open_mark_done_modal` lists either completes, enters the reason flow, or explains itself in one plain sentence — the old rejection-modal dead end is gone from the [d] path (the modal state machine's arms are unit-tested).
- [ ] No free-text input exists anywhere in the flow (S-049-06 discipline: catalog or send-back).
- [ ] `just check` green (fmt, clippy, WASM check, workspace tests).
