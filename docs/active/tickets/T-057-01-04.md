## Context

Where both halves of this story land in the same string. `ticket_prompt`
(`crates/lisa-plugin/src/lib.rs` ~120–172) is the text every agent receives, and it currently
says:

```
Read the ticket at {path}, {context}, and docs/knowledge/rdspi-workflow.md.
Your job: start from the current phase in the ticket frontmatter and work through ALL
remaining phases (Research, Design, Structure, Plan, Implement, Review) without stopping
between phases. For each phase, write the artifact to {artifact_dir}/ then immediately
continue to the next phase. ...
```

`{context}` is `AgentClient::context_file()` (`crates/lisa-core/src/client.rs` ~62–68) — literally
`"CLAUDE.md"` or `"AGENTS.md"`, selected by client and injected by
`ClaudeAdapter::assignment_text` / the Codex adapter (`crates/lisa-plugin/src/adapter.rs`
~298–305).

**Why that clause is worth deleting even though it is harmless.** Claude Code reads `CLAUDE.md`
without being told; Codex reads `AGENTS.md` without being told. The sentence conveys nothing the
client did not already do — so what it actually communicates is that these files are part of
Lisa's apparatus. They are not. Remove `context_file()` from `AgentClient`, remove the `{context}`
substitution, and let each client's native context loading be exactly as native as it was.
The three adapter tests pinning this (`adapter.rs` ~795–805) and the two prompt tests
(`lib.rs` ~13365, ~13409–13417) invert: they now assert the prompt names *no* context file, for
either client. That inversion is the point — a passing test that says "Codex's prompt does not
mention CLAUDE.md" is weaker than one that says "neither prompt mentions either file."

**The phase recital goes with it.** With four phases there is no march to narrate. What the agent
needs to know is what has not changed and is still checkable:

- Do the work on the ticket.
- Commit each meaningful ticket-owned unit with `lisa commit-ticket` and exact
  repository-relative `--include` paths — never ordinary `git add`/`git commit`, never leave
  ticket-owned files staged or untracked.
- Finish by writing `review.md` and `review-disposition.json` to the private attempt directory,
  and run `lisa check-disposition`.
- Do not edit `phase` or `status`. Do not publish completion. Stop and wait.

Also in this file: `PURPOSE_PARAGRAPH`, and the Review recovery clause (~134–141), which already
says the right thing but references `docs/knowledge/rdspi-workflow.md` — a path T-057-01-05
renames. Update the path here; that ticket owns the document itself.

**Write the prompt shorter than the one it replaces.** The outgoing version is ~25 lines of
instruction, much of it explaining a phase sequence that no longer exists. A capable model handed
a well-specified ticket does not need to be told how to think; it needs to be told the four things
above, because those are Lisa's contract and it cannot infer them. Every sentence that survives
should be one an agent would get wrong without it.

_Advances: P3 — provider parity at the contract boundary: after this, Claude and Codex receive the
same assignment text with no per-client context substitution, and parity is asserted directly
rather than per-client. And N1 — parity here is genuine sameness, not a forced handshake; the
adapters keep their distinct launch, reset, and completion-exit semantics._

      `AGENTS.md` as a value.
- [ ] **The parity assertion this ticket is named for:** one test asserts that for *both* clients
      the assignment text contains neither `CLAUDE.md` nor `AGENTS.md`, replacing the three
      one-sided tests at `adapter.rs` ~795–805.

      `lib.rs` ~13365 and ~13409–13417 are rewritten against the new text, not deleted.

      with exact `--include`, the two Review artifacts, `lisa check-disposition`, and the
      stop-and-wait boundary with no self-published completion and no frontmatter edits.

- [ ] The rendered prompt for a ticket in Implement is shorter than the 0.4.4 prompt for the same
      ticket. Assert the property, not a magic number — e.g. it is under a stated line budget with
      the budget's rationale in the design.
