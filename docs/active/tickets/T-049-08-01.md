## Context

Stable-0.4.4 blocker, confirmed at HEAD by the release audit. Doctor's `IdentityMissing` remedy ends "Or rerun `lisa init` and accept the history offer" — but `IdentityMissing` only fires when a repository exists, and in both existing-repo states the offer cures nothing: a born repo gets no offer (crates/lisa-cli/src/init.rs, the Born → no-action arm), and an unborn repo's accepted offer births the initial commit with env-scoped identity only, never writing `user.email` — the probe fails again immediately. Two fixes, one boundary. (1) Accepting the offer on an **unborn** repo writes the project-local `Lisa (project history)` identity exactly as the bare-folder path does — the operator's explicit acceptance already sanctions mutating that repo (it creates the initial commit); born repos remain untouched, full stop. (2) Remedies match their variant: `format_preflight_failure` (crates/lisa-cli/src/completion_seal.rs) currently appends the identity remedies to every `CommitSealUnavailable` kind — `RepositoryMissing` should lead with the init remedy, `IdentityMissing` with the two `git config` lines (including the init line only for states init actually cures), `TransactionUnavailable` with the dependency remedy. Doctor's copy follows the same table. The plugin's `HISTORY_IDENTITY_ASK` (crates/lisa-plugin/src/lib.rs) is reconciled to the same source or pinned by a byte-sync test — the audit found it already paraphrase-drifting.

_Advances: every remedy Lisa prints cures the state that made it print — the operator's first attempt works, instead of looping them back to the same doctor line._

## Acceptance Criteria

- [ ] Fixture tests: unborn repo + accepted offer → local `user.email`/`user.name` resolve, a completion commit succeeds, doctor silent; born repo without identity → doctor prints only remedies that work there (the config lines), asserted verbatim; bare folder unchanged; born-repo byte-snapshot fixtures still pass (no writes of any kind).
- [ ] Per-variant remedy tests: each `CommitSealUnavailable` kind maps to its own remedy set, no blanket append; the CLI and plugin remedy strings proven single-source or byte-synced; the end-to-end stall-to-cure path (doctor names → printed remedy runs → completion succeeds) passes for each variant.
