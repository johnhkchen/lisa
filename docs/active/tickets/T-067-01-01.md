## Context

**Read `S-067-01` first.**

`begin_startup_recovery` types a shell-readiness probe into a pane whose startup
was not observed. Against a live agent it has exactly two outcomes and lisa's own
source names the first as a defect:

> *"a dead end against a live TUI: a `--dangerously-skip-permissions` session
> executes the probe command on the scheduler's behalf and **forges the readiness
> proof**"* — `lib.rs:4776`

The second outcome was measured on 2026-08-13. The agent refused:

> *"That's lisa's attempt-2 ready signal, not something I should write — rail and
> its agents never write into `.lisa/signals/`; lisa owns that file. Running it
> from here would tell the scheduler a pane is ready when it isn't."*

No `.shell-ready` arrived, the seat was never recovered, and a pane with a working
agent in it died. **Two seats, twelve minutes into their attempts, both lost.**

### Why refusal is the correct behaviour and must stay correct

The consuming project's invariants forbid it: *"Never write a signal, a lease, a
ledger entry or anything else under `.lisa/` … a monitor that can perturb what it
monitors is not one."* An agent that obeys is one lisa cannot recover. An agent
that disobeys forges proof.

**A scheduler must not have a path whose success depends on an agent breaking the
rule it was given.**

## Acceptance Criteria

- **No recovery path asks the pane's occupant to write a lisa signal.** Whatever
  replaces the probe must be answerable by lisa, by a hook, or by observation —
  not by the agent's cooperation.
- **The non-resident leg gets the treatment the resident leg already has.**
  `test_unobserved_startup_on_a_resident_pane_re_exits_instead_of_probing` covers
  the case where residency is proven. Say what happens when a pane is occupied and
  cannot prove it, which is the case that failed here.
- **A live agent mid-attempt is not reset on unobserved startup alone.** Both
  panes were producing output and their session had been running twelve minutes.
  Say what evidence distinguishes *never started* from *started and unproven*, and
  prefer waiting to resetting when they cannot be told apart —
  `refuse-rather-than-guess` in the scheduler's own terms.
- **A refused probe is reported, not silently fatal.** Today it produces a dead
  pane and no line anywhere saying why. The agent's refusal is a fact lisa could
  read from its own `.ack` stream.
- **The probe is removed or its remaining uses are justified in writing.** If it is
  still right for a genuinely empty pane, say how one is identified before typing
  into it.
- Reproduce it: a live agent that refuses the probe, and assert the seat survives
  or fails loudly rather than dying quietly.

## Notes

- **The trigger was a terminal crash, not an agent fault.** WezTerm died; the
  zellij server, both agents and the scheduler all survived and kept working. Only
  the recovery lost anything.
- This is the fourth appearance of the shell probe in this repository's failures —
  `T-062-01-04`'s correction, `S-063-01`, `T-065-01-01`, and now this. Each time it
  has been a symptom of a different cause and the same mechanism.
- Worth deciding in review: whether `claude` panes should ever be probed. The
  client is known at launch, the probe assumes a shell, and lisa has never had a
  case where a `claude` pane answered one honestly.
