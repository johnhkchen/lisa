## Context

A runtime resolver decides which Zellij binary `lisa loop` execs, in precedence order: explicit path pin in `.lisa.toml` (`[runtime] zellij = "/path"`), `"system"` opt-in (PATH lookup, must pass the declared range check), and the default `"managed"` (a per-version path under `$XDG_DATA_HOME/lisa/runtime/zellij-<version>/`, `~/.local/share/lisa/...` fallback). `lisa loop` execs the resolved path rather than bare `zellij` from PATH, and `lisa doctor` reports which Zellij is in effect: mode, version, path. Config parsing follows the existing `.lisa.toml` conventions (unknown keys warn, never fail).

_Advances: Zellij stops being the user's homework — the tool owns its runtime choice and says which one it made; smallest contract, no change to how panes are driven._

## Acceptance Criteria

- [ ] Unit tests cover all three modes and their precedence, including system-mode rejection of a below-floor binary with the named error from T-046-01-02.
- [ ] In managed/pinned modes `lisa loop` execs the resolved absolute path; doctor names mode, version, and path in its report.
