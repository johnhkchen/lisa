## Context

The live 0.4.0-rc.6 E-035 loop reproduced a failed first launch that left zsh at `dquote>` before Codex existed. Ordinary hard-silence handling later treated Lisa's delivery failure as an agent timeout, permanently fenced the pane, and consumed a spare. T-035-04-01 removes the full prompt from provider launch, but the launch boundary still requires explicit recovery for truncated legacy input or any malformed short launcher. A provider `/exit` is invalid when no provider exists: it becomes more text inside the unfinished shell quote.

Implement bounded same-pane recovery for `Starting` with no matching provider-start signal. Interrupt incomplete shell input, positively establish that the pane returned to a shell-ready boundary, revoke the failed lease and mint a strictly newer attempt, clear or reject prior-attempt lifecycle state, and retry T-035-04-01's bare-provider launcher exactly once in the same pane. The replacement must still pass both process-start and in-chat assignment acknowledgement before Owned. Retain graceful `/exit` for an actually started provider and permanent fencing when reset/retry cannot be proven or an owned provider is genuinely unresponsive.

_Advances: P2 — State means what it says; P4 — Operable at a glance; P5 — deterministic field-failure regression; E-035_

## Acceptance Criteria

- [ ] Native tests distinguish incomplete-shell `Starting`, started `ReadyForAssignment`/`Delivering`, and hard-silent Owned states; only the first receives the shell interrupt, started providers use bounded chat retry or graceful `/exit`, and owned unresponsive providers retain E-034 fencing.
- [ ] Recovery escapes zsh `dquote>` and waits for positive attempt-scoped shell-readiness evidence; a fixed sleep, blind Ctrl-C, or unconditional `/exit` is not accepted as proof.
- [ ] The failed lease is revoked before retry, the retry uses a strictly newer lease, and stale start/ack/heartbeat/artifact signals cannot publish ownership, advance phases, or complete the replacement.
- [ ] At most one same-pane relaunch occurs. The replacement reaches Owned only after matching process-start and chat-assignment acknowledgements; missing reset, start, or assignment evidence ends in a named actionable failure and may fence only after bounded recovery is exhausted.
- [ ] A real-Zellij stub fault leaves zsh at `dquote>`, then proves recovery in the same physical pane without consuming a spare, residual partial input, phantom Owned state, or unbounded relaunch.
- [ ] E-033 acknowledgement, E-034 lease fencing, Claude parity, pane naming, and full workspace tests remain green.
