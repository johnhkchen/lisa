## Context

Make the plugin compile against the four-variant `Phase` and, in doing so, delete the machinery
that only ever served the removed phases. This is subtraction: no scheduling decision changes,
because the only phase edge that carried one is `review.md`, and it survives untouched.

Three sites in `crates/lisa-plugin/src/lib.rs`:

**The artifact detector, ~5980–6070.** Two blocks here go away. The first (~5981–5998) admits
`progress.md` for durability when `current_phase == Phase::Implement`; with the artifact retired
there is nothing to admit. The second is the special case immediately after it (~6000–6008):

```rust
// Determine which artifact signals completion of this phase.
// Implement uses review.md instead of progress.md (living doc).
let artifact_name = if current_phase == Phase::Implement {
    "review.md"
} else {
    match current_phase.artifact_filename() { ... }
};
```

That branch exists only because `Implement.artifact_filename()` returned the wrong thing.
T-057-01-01 makes it return `None`, so the special case collapses — but note the shape carefully:
Implement must still advance when `review.md` appears, and after the collapse `Implement` has no
artifact of its own. The straight `artifact_filename()` lookup would `continue` past Implement and
strand every ticket there forever. Whatever replaces this branch must keep the property that
**`review.md` appearing is what moves a ticket off Implement**, and that property deserves a test
that fails if someone later "simplifies" it back into the generic lookup.

**The idle-signal handler, ~6625–6631.** The match arm

```rust
Phase::Research | Phase::Design | Phase::Structure | Phase::Plan | Phase::Review => { ... }
```

loses four of its five patterns and becomes `Phase::Review`. The body is unchanged.

**The label fallback, ~9864** — `t.current_phase.artifact_filename().unwrap_or("artifact.md")` —
now takes the fallback for a ticket in Implement. Decide deliberately what an operator should read
there rather than letting `"artifact.md"` leak into the dashboard for the phase tickets spend most
of their life in.

Then `crates/lisa-plugin/src/ui.rs`: any per-phase rendering — column headers, progress pips,
phase labels — that enumerates six phases. P4 is the bar: a person supervising several panes
should still be able to see, at a glance, which tickets are working and which are in review. A
four-phase board has fewer states to draw, and the dashboard should read as *simpler*, not as a
six-phase widget with holes in it.

Leave the assignment prompt (~120–172) alone. It carries this change *and* the context-file change
and is handled once, in T-057-01-04.

_Advances: P4 — operable at a glance, with a phase display that shows only states the scheduler
can actually be in. And N3 — the UI reports state and never substitutes for the transition; this
ticket removes display arms without touching a single transition rule._

## Acceptance Criteria

- [ ] **The regression this ticket is named for:** a ticket at `phase: implement` whose attempt
      writes `review.md` advances to `Review`. A test asserts it, and is written so that
      re-deriving the artifact name from `Phase::Implement.artifact_filename()` alone makes it
      fail.
- [ ] The `progress.md` admission block is removed. No code path writes or publishes
      `progress.md`; a test shows an attempt directory containing one is not published to
      `docs/active/work/{id}/`.
- [ ] The idle-signal match arm is `Phase::Review` alone, with its body unchanged. An existing
      idle-driven Review→Done test still passes without modification.
- [ ] No `unwrap_or("artifact.md")` reaches an operator-visible surface for a ticket in Implement;
      whatever label is shown is asserted by test.
- [ ] `crates/lisa-plugin/src/ui.rs` renders the four-phase board with no dead arms and no gap
      where a removed phase used to sit. A snapshot or string test covers a board holding one
      ticket in each of the four phases.
- [ ] The plugin's phase-transition activity log (`log_phase_transition`) emits only transitions
      that exist in the new chain.
- [ ] `just check` green (fmt, clippy, WASM check, workspace tests).
