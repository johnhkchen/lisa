## Evidence-admission boundary

The admission check sits before any shared file mutation.

It accepts a run only when all required facts can be read from supplied
artifacts or independently verified without reconstructive guessing.

Required fields:

- generated HTML bytes;
- run date;
- method;
- model;
- agent CLI and version;
- exact Lisa executable version;
- candidate source/release revision;
- fixture/container identity;
- prompt identity;
- confirmation of hands-off or a list of interventions;
- enough post-run output to evaluate whether context/reporting reached the
  experience.

An absent optional checksum is not a block.

An absent HTML file is a block.

An unknown model, method, or surface is a block because the README requires
those values alongside every run.

A page that fails the rubric is still admissible evidence; it changes the
publication and follow-up outcome, not the authenticity of the run.

## Scoring component boundary

Scoring reads only the generated HTML as rendered content plus its document
order.

The scorer may use text extraction and source inspection.

The scorer does not add missing wording to the page.

The four outputs are:

- `actors: yes|no`;
- `benefit: yes|no`;
- `evidence: yes|no`;
- `order: yes|no`.

Supporting notes identify the exact page location used for each yes or no.

The source implementation is not scored as if it were page content.

Run metadata is not scored as if it were page content.

The final summary capture can explain why a concept was available to the agent,
but only the page establishes whether the concept came through.

## Version component boundary

Three identifiers may coexist and must not be collapsed:

- release-train intent: `0.4.1-rc` from the ticket;
- current workspace package version: `0.4.0-rc.8`;
- current installed executable version: `0.4.0-rc.8`.

The future row reports what actually ran.

If an unreleased source revision is used, the row reports the package version
and abbreviated commit or an explicit local-RC qualifier.

If the operator first installs a later candidate, that actual candidate version
replaces the current observation.

This prevents the benchmark archive from attributing a result to a surface it
did not exercise.
