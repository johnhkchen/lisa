## Apt repository mechanics

APT consumes package indexes beneath `dists/<suite>/<component>/binary-<arch>`.

Each architecture has a `Packages` index and commonly a compressed copy.

Package payloads can live under a shared `pool` hierarchy.

The `Filename` fields in Packages connect indexes to those payloads.

A suite-level `Release` file contains checksums for index files.

An `InRelease` file is a clear-signed form of the Release metadata.

A `Release.gpg` file is a detached signature for clients that use that form.

`apt-ftparchive` can generate package indexes and Release checksums.

GnuPG can create both signature forms.

APT's `signed-by` option constrains a source to the specified keyring.

The pinned keyring can be installed outside the global trusted key set.

An armored public key must be dearmored before use as a binary keyring.

The private signing key must never be committed to the repository or Pages artifact.
