Lisa turns tickets into a schedulable DAG

Lisa scaffolds the project, validates the workflow, and schedules tickets in dependency order. This page is a landing page for the tool, built from real CLI output and the actual Lisa-managed project under /home/tester/lisa-tour-project.

Version seen: lisa 0.3.0 Project path: /home/tester/lisa-tour-project Ticket chain: capture → build → synthesize
See real output Inspect the ticket chain

Why Lisa exists

Creates the project skeleton

It generates CLAUDE.md, .lisa.toml, hooks, a workflow doc, and the active/archive directories.

Validates the setup

It checks that the expected files exist, the config parses, and the ticket graph is sane.

Schedules by dependency

It reads ticket frontmatter, builds a DAG, and shows which tickets are ready to run in parallel.

What ships

Command What it does
lisa doctor Checks dependencies like zellij and claude.
lisa init Scaffolds the Lisa project structure in the target directory.
lisa validate Verifies the scaffold and ticket DAG.
lisa status Prints the DAG state, waves, and what is ready now.
lisa setup-guide Prints a longer, LLM-friendly walkthrough for the current project.
lisa loop Launches the interactive scheduler experience inside zellij.

The ticket chain

The actual Lisa project uses three tickets. The last one is the synthesis pass that reads the work docs and explains the whole setup back to a newcomer.

---
id: S-001
title: lisa-landing-page
tickets: [T-001-01, T-001-02, T-001-03]
---

T-001-01  capture-lisa-basics     ready
T-001-02  build-lisa-landing-page  depends on T-001-01
T-001-03  synthesize-work-docs     depends on T-001-01, T-001-02

The last ticket is not just a sign-off. It exists to read the work docs, pull the evidence together, and explain what Lisa did and why the tool exists.

The end result is not just a landing page. It is a small, documented workflow that explains what Lisa did, what it is for, and how its DAG model keeps the work organized.

What to remember

  • Run lisa init first; the scaffold matters.
  • Use lisa doctor before a session if you want dependency checks up front.
  • Keep ticket frontmatter accurate: Lisa schedules from the DAG, not from prose.
  • lisa status is the quickest way to see what can run now.
  • lisa loop is interactive and launches zellij, so it is the least transcript-friendly command.
