# Structure: orient and separate help

## Change set overview

The implementation changes two repository source files:

1. `crates/lisa-cli/src/main.rs`
2. `crates/lisa-cli/tests/help_surface.rs`

No source file is created or deleted.
No dependency or lockfile change is required.
No runtime module outside the CLI entry point is involved.

The attempt also gains the required workflow artifacts under:

`.lisa/attempts/T-044-01-01/1/work/`

Those artifacts are private attempt state and are not included in the agent's
ticket-owned source commits. Lisa handles their admission and publication.

## `crates/lisa-cli/src/main.rs`

### Existing responsibility

This file owns:

- Clap's top-level parser declaration;
- the enum of all CLI commands;
- command argument definitions;
- command dispatch;
- path resolution for command implementations.

Only the first two metadata areas are in scope. Dispatch and argument payloads
remain byte-for-byte unchanged.

### Top-level `Cli` metadata

Extend the existing `#[command(...)]` attribute on `Cli`.

Current keys:

- `name = "lisa"`
- `about = "Runs your coding agents through a project's tickets."`
- `version`

Add:

- `before_help` for the everyday path;
- `after_help` for the plumbing footer.

The `before_help` value is a single line:

`Everyday path: init → validate → status → loop`

The `after_help` value is a multiline string with:

- the heading `Plumbing commands (called by Lisa and agent hooks):`;
- one aligned row for `agent-exec`;
- one aligned row for `capture-usage`;
- one aligned row for `commit-ticket`;
- one aligned row for `complete-ticket`.

The rows repeat the current short summaries attached to the corresponding
variants. They do not include argument details; direct `<command> --help`
continues to own those.

Clap places `before_help` before its standard about/usage sections and
`after_help` after its standard command/options sections. That yields this
top-level order:

1. everyday-path orientation;
2. product about line;
3. usage;
4. generated command list;
5. generated options;
6. curated plumbing section.

### Plumbing variant metadata

Modify the command attributes for exactly four variants:

- `AgentExec`
- `CaptureUsage`
- `CommitTicket`
- `CompleteTicket`

Each retains its current `display_order` and gains `hide = true`.

Keeping `display_order` is harmless while hidden and preserves the intended
ordering metadata if future help rendering consumes the variants differently.
It also keeps this ticket narrowly additive to the established annotations.

The variant documentation, fields, argument attributes, and match arms do not
change.

### Operator variant metadata

No operator variant metadata needs to change for this ticket.

- `Init` remains order 0.
- `Validate` remains order 1.
- `Status` remains order 2.
- `Doctor` remains order 3.
- `Loop` remains order 4.

Their summary copy and command-specific help are reserved for the dependent
ticket. The built-in `help` subcommand continues to render after them.

### Hidden internal variants

No changes are made to:

- `SetupGuide`
- `HooksGuide`
- `Version`

Their existing `hide = true` annotations remain the model for help-only
visibility changes.

### Public and runtime interfaces

There are no Rust public-interface changes.

The external CLI parser interface is preserved:

- all existing command spellings remain valid;
- all existing arguments remain valid;
- all direct command help remains available;
- exit behavior remains generated by Clap;
- dispatch targets remain unchanged.

Only top-level help presentation changes.

## `crates/lisa-cli/tests/help_surface.rs`

### Existing responsibility

This black-box integration test already owns CLI help-surface regressions. It
contains:

- command category constants;
- helpers to execute the real binary and capture help;
- a complete direct-resolution test;
- an ordering/visibility test;
- a jargon test.

The new snapshot belongs here rather than in a new integration test because the
fixture setup and semantic constants already exist here.

### Snapshot constant

Add a module-level `TOP_LEVEL_HELP_SNAPSHOT: &str` raw string.

It contains the exact non-interactive stdout emitted by:

`lisa --help`

The snapshot includes the final newline. It is kept inline so:

- no dependency is added;
- no fixture-path I/O is needed;
- review shows the expected screen and assertion together;
- Rust's ordinary diff displays help changes directly.

### Snapshot test

Add `top_level_help_matches_snapshot`.

Its sequence is:

1. call `help_stdout(&["--help"])`;
2. compare returned stdout to `TOP_LEVEL_HELP_SNAPSHOT` using `assert_eq!`.

The test name and failure diff identify the whole top-level surface as the
regression boundary.

### Section boundary constant

Represent the exact footer heading once as a module constant if doing so keeps
the structural split readable:

`PLUMBING_HEADING`

The value matches the heading in source and snapshot. This is test vocabulary,
not a production API.

### Grouping test update

Rename or rewrite `hook_commands_are_set_apart_and_internal_hidden` to reflect
the new stronger invariant.

The test first splits full help at the plumbing heading.

The text before the split is the primary operator surface. The text after the
split is the plumbing footer.

For every `OPERATOR_COMMANDS` value:

- require a generated listing anchor in the primary surface.

For every `HOOK_COMMANDS` value:

- reject a generated listing anchor in the primary surface;
- require a row anchor in the plumbing footer.

For every `HIDDEN_COMMANDS` value:

- reject a listing anchor in the entire top-level help.

This replaces the old weaker rule that only compared plumbing offsets with
`loop`.

The existing `listing_offset` helper remains usable because it receives a
section slice rather than undifferentiated full output.

### About-line test update

The orientation becomes the first nonempty line, invalidating the existing
selection logic.

Replace `find(first nonempty)` with a search for the known about sentence or a
stable semantic predicate containing `coding agents`.

Retain:

- the positive `coding agents` anchor;
- the banned-jargon assertion;
- all direct operator-help jargon checks.

The test should not classify the new orientation as the about line.

### Resolution test

Leave `all_twelve_subcommands_resolve` unchanged.

It is an important counterweight to `hide = true`: it proves the four plumbing
commands were visually demoted rather than removed.
