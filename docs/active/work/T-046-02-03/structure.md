# Structure: XDG-aware Zellij pre-grant and cache

## Change summary

- Modify the CLI dependency manifest.
- Update the workspace lockfile as generated by Cargo.
- Modify the Zellij cache resolver in `doctor.rs`.
- Extend the existing `doctor.rs` unit-test module.
- Do not create a new production module.
- Do not change loop orchestration.
- Do not change plugin code.
- Do not change public command surfaces.

## File: `crates/lisa-cli/Cargo.toml`

### Role before the change

- Defines the native Lisa CLI package.
- Declares runtime libraries used by CLI modules.
- Does not directly declare the directory-resolution library.

### Modification

- Add `directories = "5"` under `[dependencies]`.
- Keep dependency ordering consistent with the existing compact manifest style.
- Do not add features; default features are sufficient.
- Do not add a test-only directory dependency.

### Resulting boundary

- The CLI owns a direct compile-time relationship to `directories` major 5.
- The dependency is used only to mirror Zellij 0.43 cache resolution.
- No type from the dependency crosses a public Lisa API.

## File: `Cargo.lock`

### Role before the change

- Pins workspace dependency resolution.
- Already contains `directories` 5.0.1 transitively.
- Does not list it as a dependency of the `lisa-cli` package entry.

### Modification

- Regenerate or update through Cargo after the manifest change.
- Expect the `lisa-cli` dependency list to gain `directories`.
- Expect no new package stanza if the current resolution remains reusable.
- Review for unrelated resolver churn before commit.

### Resulting boundary

- Reproducible builds retain the same concrete `directories` release.
- Direct dependency ownership is represented in package metadata.

## File: `crates/lisa-cli/src/doctor.rs`

### Existing production responsibilities

- Dependency and version health checks.
- Zellij plugin cache cleanup.
- Zellij plugin permission pre-grant.
- Codex trust pre-grant.
- Doctor command reporting.
- Package-local unit tests for each responsibility.

### Import modification

- Add `use directories::ProjectDirs;` near other external-crate imports.
- Retain `Path` and `PathBuf` imports.
- Avoid importing platform-specific path helpers.

### Resolver modification

- Retain the function name `zellij_cache_dir`.
- Retain its private visibility.
- Retain its `Option<PathBuf>` return type.
- Replace direct `HOME` access.
- Remove the compile-time macOS/non-macOS branch.
- Construct `ProjectDirs` with Zellij's exact tuple.
- Convert `cache_dir()` from borrowed `&Path` to owned `PathBuf`.
- Keep the resolver free of filesystem writes.

### Resolver pseudocode

```text
ProjectDirs::from(
    "org",
    "Zellij Contributors",
    "Zellij",
)
.map(project_dirs.cache_dir().to_path_buf())
```

### Existing consumers retained

- `clean_zellij_plugin_cache` calls the resolver.
- `pregrant_plugin_permissions` calls the resolver.
- `run_doctor` calls the resolver for cleanup reporting.
- No consumer needs signature or control-flow changes.

### Existing inner seams retained

- `clean_zellij_plugin_cache_in(&Path) -> usize` stays unchanged.
- `pregrant_plugin_permissions_in(&Path, &Path) -> bool` stays unchanged.
- Their direct unit tests stay unchanged.
- The permission constant stays unchanged.

## Test-module structure

### Environment synchronization

- Add a static mutex scoped to the test module.
- The mutex protects the new tests that mutate directory variables.
- Recover from poison to keep a failed test from masking later results.

### Environment restoration type

- Introduce a small test-only guard or helper.
- Capture `HOME` and `XDG_CACHE_HOME` as `Option<OsString>`.
- Apply controlled values for a test case.
- Restore both variables on drop.
- Keep it private to the test module.
- Use `var_os` so non-Unicode values can be restored losslessly.

### Expected-path helper

- Keep platform-specific expected-path spelling in test-only code.
- On macOS, append the bundle-ID cache suffix under controlled home.
- On Linux/other Unix, use XDG root when configured.
- Otherwise append `.cache/zellij` under controlled home.
- The helper documents the acceptance expectations independently.
- It must not be called by production code.

### Shared routing assertion helper

- A helper may run both operations for one expected cache root.
- It creates a deep Lisa plugin fixture beneath the expected root.
- It calls the environment-resolving cleanup wrapper.
- It verifies the matching fixture is gone.
- It calls the environment-resolving permission wrapper.
- It verifies `permissions.kdl` at the expected root.
- It verifies the fake WASM path appears in that file.
- It can also assert an alternate candidate root remains untouched.

### Regression test: configured cache environment

- Create an isolated temporary root.
- Set `HOME` to `<temp>/home`.
- Set `XDG_CACHE_HOME` to absolute `<temp>/xdg-cache`.
- Compute the platform-expected Zellij root.
- Exercise cleanup through `clean_zellij_plugin_cache`.
- Exercise pre-grant through `pregrant_plugin_permissions`.
- On Linux, assert both actions occur under `<temp>/xdg-cache/zellij`.
- On macOS, assert both actions remain under the bundle-ID home cache.
- Assert the non-selected candidate does not receive permissions.

### Regression test: unconfigured cache environment

- Create a separate isolated temporary root.
- Set `HOME` to `<temp>/home`.
- Remove `XDG_CACHE_HOME`.
- Compute the platform-expected Zellij root.
- Exercise cleanup through `clean_zellij_plugin_cache`.
- Exercise pre-grant through `pregrant_plugin_permissions`.
- On Linux, assert both actions occur under `<temp>/home/.cache/zellij`.
- On macOS, assert both actions occur under the existing bundle-ID path.

### Optional resolver assertions

- Directly assert `zellij_cache_dir()` equals the expected path in each case.
- This makes a path mismatch easier to diagnose than a missing file alone.
- Wrapper assertions remain necessary to cover consumer routing.

## No new files under `crates/lisa-cli/tests`

- Private helper access is useful for the regression.
- Unit tests avoid invoking external binaries.
- The behavior is module-level rather than a CLI-output contract.
- Existing project convention already locates these tests in `doctor.rs`.

## No changes to `loop_cmd.rs`

- It already calls cleanup and pre-grant wrappers.
- Their order is correct and unrelated to the directory bug.
- Changing call sites would duplicate path resolution or widen scope.
- Correcting the shared resolver automatically changes loop behavior.

## No changes to `lisa-plugin`

- The plugin requests the same permissions that Lisa writes.
- The plugin does not choose the host cache directory.
- Cache location is resolved by the native Zellij host.
- The ticket is therefore fully owned by CLI host preparation.

## Internal API stability

- No `pub` or `pub(crate)` signatures change.
- No serialized format changes.
- No command flags change.
- No config fields change.
- No environment variables are introduced by Lisa.
- Existing callers continue to observe best-effort `()` wrappers.

## Error and fallback structure

- `ProjectDirs::from` may return `None`.
- `zellij_cache_dir` propagates that absence.
- Cleanup wrappers do no work on `None`.
- Pre-grant wrappers do no work on `None`.
- Doctor retains its existing inability diagnostic.
- Filesystem inner functions retain their current tolerant error policy.

## Commit unit

- The production resolver, direct dependency, lockfile update, and regression tests form one meaningful unit.
- They should be committed together because the source will not compile without the manifest.
- The test regression is inseparable from the behavioral change.
- Exact includes:
  - `Cargo.lock`
  - `crates/lisa-cli/Cargo.toml`
  - `crates/lisa-cli/src/doctor.rs`
- Attempt-private artifacts are not included in the ticket source commit.

## Validation structure

- Format the workspace after editing.
- Run targeted doctor cache tests.
- Run all `lisa-cli` tests.
- Run workspace checks.
- Inspect status for only expected ticket-owned source changes.
- Use Lisa's isolated commit transaction.
- Inspect status again to confirm ticket-owned source cleanliness.

## Final architecture

```text
directories::ProjectDirs (Zellij 0.43 tuple)
                 |
                 v
        zellij_cache_dir()
          /      |       \
         v       v        v
 loop cleanup  pre-grant  doctor cleanup/report
         |       |
         v       v
 clean_*_in   pregrant_*_in
```

- One resolver remains the path-selection authority.
- Existing injected inner functions remain filesystem-operation authorities.
- The test module covers both layers together for environment routing.
