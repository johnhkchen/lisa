# T-035-01-01 Structure — process-start signal producer

## Modified source files

### `crates/lisa-cli/src/templates.rs`

Add public template constant:

```text
ON_START_HOOK: &str
```

Responsibilities:

- implement the provider-neutral POSIX producer;
- validate pane, ticket, and attempt launch identity;
- compare identity with `pane-<id>.lease`;
- atomically publish `pane-<id>.started`;
- leave no output on rejection.

Add private legacy list:

```text
LEGACY_ON_START_HOOKS: &[&str]
```

This participates in the same owned-template upgrade mechanism as other hook scripts.

Change `settings_local_json()`:

- keep `SessionStart[clear] -> on-clear.sh`;
- add `SessionStart[startup] -> on-start.sh`.

Change `codex_hooks_json()` identically at the normalized boundary.

Change `merge_hooks()` and `merge_codex_hooks()`:

- call `ensure_hook` for event `SessionStart`, matcher `startup`, start command;
- preserve current `clear` merge behavior;
- rely on matcher-specific deduplication for idempotency.

Extend template tests:

- content contract for `ON_START_HOOK`;
- generated Claude startup binding;
- generated Codex startup binding;
- merge preservation and idempotency;
- executable shell fixture cases.

Test helper organization:

- write the constant to a temporary executable script;
- create fixture `.lisa/signals` roots;
- execute with controlled working directory and environment;
- read or assert absence of `pane-<id>.started`.

## New runtime file

`lisa init` will create:

```text
.lisa/hooks/on-start.sh
```

This repository's checked-in `.lisa` runtime files are not ticket-owned source and are not
manually regenerated by this implementation. The behavior is tested through templates and
temporary init roots.

## Signal layout after this change

```text
.lisa/signals/
  pane-<id>.lease       scheduler-owned current authority
  pane-<id>.started     startup hook copy after exact launch identity match
  pane-<id>.heartbeat   post-tool hook copy of lease
  pane-<id>.cleared     reset handshake
  pane-<id>.stopped     turn completion
  pane-<id>.ack         Codex recycled-prompt acknowledgment
```

## Interface boundaries

- Core `AttemptLease` schema remains unchanged.
- The start hook serializes the existing schema; it introduces no new Rust signal type.
- The scheduler does not read `.started` in this ticket.
- Provider adapters differ only in launch command construction; hook production is shared.
- Init remains the sole owner of generated project hook files and JSON configuration.

## Change ordering

1. Add template constant and fixture tests.
2. Add generated/merged startup bindings.
3. Add init materialization and validation.
4. Thread attempt ID through spawn context and both provider launch commands.
5. Update exact tests and run focused suites.

This order keeps compilation failures localized: template behavior can be validated before
changing adapter interfaces, then all `SpawnContext`/helper call sites are updated as one
source unit.
