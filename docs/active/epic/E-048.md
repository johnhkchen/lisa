## Intent — the bigger-picture play

Field incident, 2026-07-16: two tickets sat in Review with block dispositions whose remedies were outside the repo — one waiting on a release being published, one waiting on human-operated test runs. The scheduler re-seated both forever; with `max_threads=2` they occupied every seat, re-reviewed, re-blocked, and starved all workable tickets until an operator hand-edited `status: blocked` into their frontmatter. Worse, the unblock experience failed the person it was addressed to: the block reasons were dense engineering prose ("no stable Pages artifact has been deployed... verify publish-apt-repository succeeds") — accurate, and useless to a nontechnical operator, who experiences "huh? what's all this jargon?" at exactly the moment the system needs them most. Lisa's 0.4.x gates are working — states now mean what they say — but a block is currently a dead end wearing a paragraph, when it should be three answerable questions: **who owns the remedy** (the agent can retry / a human must act / the world must change), **what exactly is the ask** (one sentence a person who didn't do the work can act on), and **how would Lisa know it's done** (a machine-runnable check, so that when no human judgment is truly needed, no human is asked). The play: extend the block contract with those fields, make the scheduler park operator- and world-owned blocks (the `status: blocked` exclusion at dag.rs:197 already exists — formalize what today was done by hand), auto-recheck parked tickets so world-owned blocks clear themselves, and surface a **Waiting on you** queue in `lisa status` and the dashboard written in the brand voice. Applied to today's incident: the release-gated ticket would have parked silently and self-cleared the moment the apt key URL returned 200 — zero human involvement; the evidence-gated ticket would have shown one line: "Lisa needs you to run the two baseline tests in the runbook, then run `lisa unblock T-046-06-02`."

## Value to the design

Advances P2 — a block stops being a mislabeled busy-loop; parked-waiting-on-operator and parked-waiting-on-world become real, visible states that correspond to durable reality, and re-review churn stops masquerading as progress. Advances P4 — the operator supervising panes sees "Waiting on you: 1 — publish the release" instead of reverse-engineering dispositions out of work-dir JSON. Advances P5 — the 2026-07-16 starvation incident becomes a regression scenario: a board with an operator-owned block must keep scheduling other work and must never re-seat the parked ticket. Honors the standing non-goal that recovery is bounded and ends in a named actionable state — this epic is that non-goal's missing second half: bounded across attempts, not just within one.

## Done looks like

A review block authored by an agent carries remedy owner, a one-sentence plain-language ask, optional concrete steps, and (when checkable) a shell-runnable check. Agent-owned blocks get bounded re-attempts then park. Operator- and world-owned blocks park immediately: seats stay free, and `lisa status` opens with a Waiting-on-you section whose lines pass the same low-end reader test as the install path — a person (or weak agent) with no context can read the ask and correctly do it. `lisa unblock <id>` resumes a parked ticket, runs the check first when one exists, and declines in plain words when the world isn't ready ("that didn't work yet — the key link still returns 404"). Parked world-owned tickets self-clear when their check passes at loop start or on the recheck timer. Provenance records park/unpark transitions with durations, so "how often do we strand humans, and for how long" becomes a queryable number. Replaying the 2026-07-16 board under the new contract shows: no starvation, no re-review churn, one human sentence.

## Context & constraints

Grounds against crates/lisa-core/src/disposition.rs (fail-closed parse stays fail-closed: a malformed or unstructured block is treated as operator-owned with the raw reason as the ask, flagged unstructured — never dropped, never retried unbounded), the scheduler's seat logic in crates/lisa-plugin/src/scheduler.rs, the `status: blocked` scheduling exclusion in crates/lisa-core/src/dag.rs:197, and the Review-phase instructions injected via crates/lisa-cli/src/templates.rs. PREREQUISITES (name, don't absorb): serialize file-level edits with in-flight work — main.rs copy edits land with T-046-07-01, templates.rs canonical purpose copy with T-047-01-01; ticket dependencies below encode that. NON-GOALS honored: no rewrite of the completion contract or lease machinery — parking is a scheduling-visibility state, never a substitute for real transitions, and Lisa alone still writes Done; asks report state, they never invent it; checks are read-only probes, never remediation scripts. The ask copy follows the brand voice: name the action, not the subsystem; the 2026-07-16 block reasons are the canonical counter-examples. Right-sized as two stories: the contract and scheduler policy (S-048-01), then the human surface (S-048-02).

Decomposition artifact rule: children spell constraints plainly — malformed blocks fail closed to parked-with-raw-reason; parked tickets are excluded from seats but never from the dashboard; checks run read-only with a timeout; every ask is one sentence a person who didn't do the work can act on.
