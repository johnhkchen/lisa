## Intent — the bigger-picture play

Close two lifecycle boundaries where Lisa currently reports success it did not earn. (1) The completion transaction treats review.md existence as a pass: T-039-06-02 wrote a BLOCKING Review because the field pass crossed an unexplained mid-run lifecycle hotfix, yet Lisa committed the ticket, emitted authoritative Done provenance, and advanced the DAG anyway. Make the Review agent emit a structured, machine-readable disposition (pass | block + reason) alongside review.md, and gate the completion transaction on an explicit pass — a blocked Review stays assigned, visible, and operator-actionable without ever preparing Done or unblocking dependents. (2) Pre-ownership failures vanish: the rc.6 Codex reuse-prompt miss left no durable failed/timed-out row and no retained scheduler/provider error, so the incident was only reconstructable from a 1,029-second scheduling gap and the rc.7 hotfix timestamp. Persist attempt-scoped assignment-transition evidence (reservation → reset/exit → launch → delivery → ack → bounded retry → named failure) so a human can see why a ticket never started. This is the truthful-terminal-state play; it does not decompose the work.

## Value to the design

Realizes an honest completion contract at both the Review gate and the pre-ownership window. Advances P2 (published Done/blocked/failed states correspond to durable reality; failure stays visible and recoverable, never mislabeled as success), P1 (a blocked ticket is never committed, so no rejected work leaks into the repo or another ticket's commit), P4 (a supervising operator can read ownership, a blocked Review, and why-a-ticket-didn't-start without reverse-engineering pane contents or timestamp gaps), and P5 (the T-039-06-02 and rc.6 incidents become deterministic regressions that prove the exact lifecycle boundary that failed).

## Done looks like

A Review that blocks leaves the ticket assigned/visible/actionable with its reason surfaced, Done is never prepared, and dependents stay blocked; a Review that passes still completes atomically as before; malformed, missing, or contradictory dispositions are rejected safely rather than defaulting to success. Separately, a ticket that dies before ownership leaves a durable, attempt-scoped failure row carrying ticket/attempt/pane/provider/state/reason/timestamps, retrievable through a CLI/reporting surface, with no fabricated successful run and no duplicated authoritative outcome. An RC rebuild plus an authorized Codex-seat field report close the loop against real evidence.
