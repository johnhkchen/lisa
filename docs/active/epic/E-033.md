_Proposed by Vend's `propose-epic` play._

## Intent — the bigger-picture play

Make the Codex seat's ticket-to-ticket handoff trustworthy in real vend loops. Today the recycled-Codex path is an open-loop, fire-and-forget sequence — /clear -> cleared-hook -> prompt injection -> delayed Enter — with no signal back that Codex actually took the new ticket; it intermittently stalls during or after that handoff while Claude sails through the same transition. T-029-02 already removed one premature-Enter timer race, so the play here is NOT another timing tweak: it is to convert the handoff into a positively-acknowledged handshake so the scheduler never marks a new ticket as owned until Codex demonstrably accepted it, makes that in-flight handoff observable to an operator, bounds the wait, and self-recovers into a safe fresh-session fallback when acknowledgment never arrives. This matters now because Codex is only a viable second seat if consecutive reuse is as reliable as Claude's.

## Value to the design

Realizes provider parity at the contract boundary (P3): Codex reuse gains the acknowledged-assignment guarantee Claude already enjoys, without being forced through Claude's exact handshake. Makes the transient handoff state legible at a glance so an operator can see 'assigned-pending-ack' vs 'owned' vs 'recovering' (P4). And turns an intermittent field stall into standing regression evidence by proving repeated consecutive reuse in a live-style harness and preserving a deterministic reproduction of the failure (P5).

## Done looks like

In a live-style harness that drives several consecutive Codex ticket reuses back-to-back, every recycled assignment resolves to exactly one of two observable outcomes: Codex positively acknowledges the new ticket before the scheduler records ownership, OR the bounded wait expires and the seat transitions into a named actionable state that triggers a safe fresh-session fallback — never a silent stall and never a ticket displayed as owned while Codex has not accepted it. Claude's transition behavior is unchanged across the same harness, and a deterministic reproduction of the original stall exists as a committed regression.

## Context & constraints

Grounds against the existing Codex line: T-029-02 (premature-Enter timer race — already fixed; do not merely re-patch timing), the `/clear` -> cleared-hook -> prompt -> delayed-Enter handoff in `crates/lisa-plugin/src/lib.rs`, and the scheduler's ownership transition for a recycled seat. The vend E-069 run supplies a captured happy path: T-069-01-04 received its prompt and began producing artifacts after reuse, but lisa had no positive ticket-acceptance event separating that success from the reported stalls. T-029-01 (codex-runbook-live-run) is the live-run harness precedent. Respects N1: the acknowledgment mechanism must be Codex-appropriate, not Claude's identical handshake bolted on. Respects N2: recovery is bounded and terminates in a named state (feeding the fresh-session fallback), never infinite retries or silent babysitting. Respects N4: the smallest contract around the recycled-Codex seat boundary — no broad scheduler rewrite, and the Claude path stays untouched. Out of scope: decomposition into stories/tickets (DecomposeEpic's job), non-Codex pane work, and pane-naming/observability beyond surfacing the handoff state (E-032 owns general pane lifecycle names).
