## Intent — the bigger-picture play

Field incident, July 2026: a nontechnical client on a Chromebook (Crostini, Debian container, 35GB) asked their coding agent to set up Lisa. The agent ended up installing Rust, the wasm target, and building Zellij from source — on a machine that could barely afford it — even though prebuilt Lisa binaries for that exact hardware already ship on every release. Investigation found four compounding causes. (1) **An undeclared, unenforced Zellij floor with a silent failure mode:** Lisa's pane-driving calls (`write_chars_to_pane_id`/`write_to_pane_id`, crates/lisa-plugin/src/lib.rs) require Zellij ≥ 0.41.0 and the pinned zellij-tile targets 0.43.x, but `lisa doctor` only echoes `zellij --version` without parsing it, and on a 0.40 host Lisa starts, renders, and simply never types into any pane — no error anywhere. (2) **No trivial Zellij supply on the target OS:** Zellij is packaged in no Debian suite at all (ITP #1073803 open since 2024, ~100 crates from landing), and Crostini's default container is still bookworm; the only concrete Zellij command in our tree is `cargo install zellij` (doctor.rs:82) — the worst possible path on that hardware. (3) **Agent-readable text that steers toward source builds:** repo CLAUDE.md/AGENTS.md open with cargo build commands; the stale docs/knowledge/lisa-loop-setup-guide.md teaches a manual build against an obsolete target name; the `lisa loop` embedded-WASM error recommends `git clone … && just release`; the installer drops the binary in `~/.cargo/bin`, implying Rust. (4) **Channel skew and a glibc floor:** `releases/latest` serves v0.3.0 (pre-E-045, Codex leg broken) while the brew tap serves rc.8, and our Linux artifacts are glibc-2.35 builds that won't run on older containers.

The play: **Lisa owns its runtime.** A pinned, no-web, static-musl Zellij — checksum baked into the release — is fetched into Lisa's own data dir and used by default (the Playwright/Jellyfin model; Zellij's own launch script and mise already manage per-version Zellij binaries this way). System Zellij becomes an opt-in judged against a *declared* floor that doctor and loop preflight actually enforce, loudly. Lisa's Linux artifacts go static-musl so the Debian release stops mattering. Every string an agent can read — README, AGENTS.md, doctor hints, error remedies — converges on one blessed install path. Debian gets a native signed apt channel. And the incident becomes a standing, human-operated acceptance protocol: the **Chromebook test** — a low-end agent (Haiku-class, mini-class) in a stock bookworm container, driven only by the README, must produce a doctor-green Lisa without ever touching a compiler.

## Value to the design

Advances **P2 — state means what it says:** an out-of-range Zellij becomes a named, remedied preflight refusal instead of a dashboard that looks alive but drives nothing; doctor stops passing binaries that carry an empty placeholder WASM. Advances **P4 — operable at a glance:** the install surface (README, doctor output, failure strings) tells a supervisor — or their agent — exactly what to run next, with the everyday path separated from the contributor path. Advances **P5 — field evidence becomes regression evidence:** the Chromebook incident is preserved as a deterministic fixture and manual protocol with a recorded failing baseline, and no future release should regress it. The weak agent is the honest proxy for the nontechnical operator: a path a low-end model can walk is a path a person can walk.

## Done looks like

In a stock Debian bookworm container standing in for Crostini — only curl, sudo, node, and the claude/codex CLIs present; no git, no Rust, no build tools — a low-end agent handed the README's install section produces, hands-off, a Lisa where `lisa doctor` exits 0 and `lisa loop --dry-run` succeeds in a scaffolded project, within 10 minutes and ~200MB of disk, with the negative assertions holding: no rustc/cargo/rustup on the machine afterward, no compiler ever invoked. Zellij never surfaces as a user-facing concern (managed runtime resolved, fetched, verified, and used silently; version and provenance visible in doctor output). A deliberately seeded Zellij 0.40 on PATH produces a loud preflight error naming the detected version, the required floor, and the working remedy — never a silent dead session. `releases/latest` serves a current stable with the E-045 claim path. `apt install lisa` from the signed repo works on bookworm and installs the pinned runtime alongside. The failing baseline run (against today's README) and the passing closing run are both recorded in docs/knowledge/chromebook-install-test.md.

## Context & constraints

Grounded in the 2026-07-16 survey: coupling facts (zellij-tile pin crates/lisa-plugin/Cargo.toml:14; hard 0.41 floor via WriteToPaneId protobuf absence in 0.40 hosts; layout alias floor 0.40; permissions.kdl path stable 0.38→0.44 but Lisa ignores `XDG_CACHE_HOME` while Zellij honors it — a live pregrant bug), supply facts (no Debian/Ubuntu Zellij anywhere; Crostini = bookworm per Chromium source; Zellij ships ~14MB no-web static-musl tarballs with sha256 for both Chromebook arches), and pipeline facts (cargo-dist upstream active but no deb support planned — the route is nfpm repackaging dist's tarballs plus a signed vendor apt repo; Jellyfin's `jellyfin-ffmpeg` companion-package model is the precedent for shipping the pinned runtime; vendor debs bundling pinned binaries are normal outside the Debian archive, which is a non-goal).

PREREQUISITES (name, don't absorb): the E-045 claim-path line must be releasable before the stable-channel repair makes sense; cutting the stable release itself is John's call — stories deliver the pipeline and the checklist, not an autonomous publish. NON-GOALS honored: no substrate swap — Zellij stays; tmux/headless alternatives are a different epic (smallest contract that removes the failure mode). Recovery stays bounded: a failed or offline runtime download ends in one named actionable state that prints the exact URL and expected sha256 — no retry loops, no silent fallback to an unvetted system binary. The Chromebook test is honest about being manual: it spends real agent tokens, is operated by a human (John), and its results are evidence documents — it is never a default cargo test. Right-sizing: this is several 2-hour blocks; decomposed into seven stories (S-046-01 … S-046-07) with the test story gating epic close. S-046-07 (purpose-first copy) was added 2026-07-16 from tour-probe field evidence: the installed surface taught an agent mechanism ("schedulable DAG") and never purpose ("runs your coding agents so you don't babysit them").

Decomposition artifact rule: child stories and tickets spell constraints in plain language rather than citing charter codes — refusal-not-silence for out-of-range runtimes; bounded, named failure states for downloads; the smallest change that removes the failure mode, not a scheduler or substrate rewrite; and copy in user-facing surfaces follows the brand voice (plain kitchen-table English, verb-forward).
