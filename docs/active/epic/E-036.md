## Intent — the bigger-picture play

The `--help` surface is the first thing a new operator meets, and it has quietly rotted as the CLI grew to fourteen subcommands. `lisa --help` now prints one undifferentiated wall that mixes the five commands a person actually runs (init, validate, status, doctor, loop) with hook/plumbing internals the machinery calls on its own (agent-exec, capture-usage, commit-ticket, complete-ticket) — and leads with a category label, 'DAG-driven concurrent task scheduling', rather than a plain sentence anyone could act on. The play is to make the CLI's own help output legible and operator-first: a top-level about-line and command descriptions in plain, verb-forward English, with operator commands foregrounded and internal/hook commands visibly set apart (a help heading, or moved out of the primary listing) so nobody mistakes a hook shim for something to type. This is the CLI reading like a labeled shelf instead of a parts bin — the cheapest, highest-traffic legibility win Lisa has, and it warrants clearing now that the command count has crossed the point where a flat list stops orienting anyone.

## Value to the design

Realizes operable-at-a-glance for the very first contact surface (P4): the help screen itself tells a supervisor what Lisa is for, which capacity/commands are theirs, and the one command that starts a run — without reverse-engineering the subcommand list or reading `main.rs`. It also lands the brand's plain kitchen-table voice on the copy operators see most, turning category jargon into action-forward labels.

## Done looks like

Running `lisa --help` on a fresh install, a person who has never used Lisa can, from that one screen alone, name what Lisa does, tell the operator commands apart from the internal/hook plumbing, and identify the single command that launches a run. Each operator-facing subcommand's `--help` describes its action in plain English rather than a category term. No behavior, flags, or command names change; only the help text and its grouping/ordering do.

## Context & constraints

Grounds against crates/lisa-cli/src/main.rs, where clap derives all help from the `#[command(about=...)]` string and the `///` doc comments on the `Commands` enum. The work is copy and clap grouping/ordering (e.g. help headings or hiding internal commands from the primary listing) — not a CLI redesign, so it honors N4 (isolate the smallest change; do not restructure the command set). Non-goal to respect: this must not silently drop or rename any command or flag that hooks and the loop launcher depend on (agent-exec, capture-usage, commit-ticket, complete-ticket are invoked by the machinery — reword and regroup their help, do not remove them). Brand-voice constraint from user-global CLAUDE.md applies: plain, verb-forward, no 'orchestration'/'DAG-driven'-style jargon in anything a visitor reads. Out of scope and left to DecomposeEpic: the specific ticket breakdown, and any generated man page / README / long-form docs beyond the CLI's built-in `--help`. Prerequisite: none — this stands alone on the existing clap surface. Right-sized as one ~2-hour block; if a decompose finds the internal/operator split needs a clap structural change (subcommand nesting), that is a distinct follow-on, not hidden scope here.
