## Intent — the bigger-picture play

Someone new to a pane pulls `--help` to answer 'what can this do and where do I start?' Today Clap prints an auto-generated, alphabetized wall of subcommands with terse one-liners; the operator-facing commands (init → validate → status → loop) sit undifferentiated next to internal plumbing (agent-exec, capture-usage, commit-ticket, complete-ticket, some hidden, some not). The play is to make `lisa --help` and each `lisa <cmd> --help` read like a shelf label: a short top-of-help orientation to the normal path through a run, brand-voiced descriptions that say what you'd DO with each command, and a clean separation of the everyday operator commands from the machine-called plumbing — so the help itself is the at-a-glance operability surface P4 asks for, not a dump the operator has to reverse-engineer.

## Value to the design

Realizes discoverable, self-explaining operability at the CLI boundary — the first thing an operator touches. Directly advances P4 (operable at a glance) by making ownership of the workflow legible from help text alone, lowering the floor for a supervisor to know which command to run next and what it will do.

## Done looks like

Running `lisa --help` shows a short orientation to the everyday path (init → validate → status → loop) with the internal/agent-invoked commands visibly demoted or grouped away from operator commands; every operator-facing command's help line is plain-English and verb-forward (no jargon), and `lisa <cmd> --help` for each operator command states its purpose and a usage example. An operator who has never seen Lisa can identify, from help output alone, which command to run first and what a run does.

## Context & constraints

Grounded in crates/lisa-cli/src/main.rs: the CLI is Clap-derive with per-command `about` strings and derived `--version`, so `--help` already emits — this epic curates and organizes that surface, it does not add the flag. Operator commands (Init/Validate/Status/Loop/Doctor) already carry `display_order`; plumbing commands (AgentExec, CaptureUsage, CommitTicket, CompleteTicket) and guides (SetupGuide, HooksGuide, Version) are agent- or hook-invoked, some already `hide = true` — the grouping/demotion work builds on those existing knobs. Copy must follow the project brand voice (plain kitchen-table English, verb-forward labels). Out of scope and left to DecomposeEpic: the specific wording of each line, whether to add `after_help`/`help_template` vs. more `hide`/`display_order`, and any man-page or shell-completion generation. Respects N3 — help text reports state and orients; it does not stand in for correct scheduler transitions. No prerequisite epic; the Clap wiring needed is already present. Right-sized to ~one 2-hour block.
