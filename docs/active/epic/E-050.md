## Intent — the bigger-picture play

The expected Lisa user is a solo product owner who delegates work to coding agents, often on modest or hostile hardware, and measures Lisa by momentum — not by how faithfully it asks permission. Against that user, the board's recent epics have quietly grown a thicket: `lisa init` on a fresh folder now *errors* until you choose `--with-history` or `--no-history` (the install path's first command became a flag question — the 0.4.4 release audit caught the README teaching a command the release breaks, and the Chromebook runbook had to adopt the flag); `[guards]` and `[triage]` exist but are upserted nowhere and were undocumented until hand-fixed; re-running init never adds new config sections to old projects (the memorized upsert gap — old boards simply never learn about new knobs); a machine with only Codex installed still defaults to Claude and fails doctor; an empty `lisa notes` prints nothing at all. Each knob was locally justified. Together they are the annoyance this epic removes.

The governing principle extends the one this codebase already proved twice (managed Zellij, the seal ladder): *an unconfigured default must never resolve to a requirement the environment cannot satisfy* — now stated positively: **the default is a decision, not a question.** Where the expected user would overwhelmingly choose one way, Lisa chooses it, says so in one plain line, and keeps the flag as an override. Asking — or erroring — is reserved for choices that are genuinely destructive or irreversible (P1 draws that line). Concretely: fresh-folder init keeps project history when the machine can and falls to the journal when it can't, announcing either way, no flag required; init keeps old configs current with commented stubs; the agent client is detected, not demanded; no operator surface is ever silently empty; and a standing audit holds every future flag to the same bar.

## Value to the design

Advances P4 — the operator learns what Lisa decided from one line at the moment it decides, instead of from a flags table; empty surfaces say what empty means. Advances P1 — the decide-don't-ask rule is bounded by preservation: nothing auto-decided may touch an existing repository, identity, or config value, so the defaults get bolder while the safety rules do not move. Advances P5 — this session's friction list (the runbook's forced flag adoption, the undiscoverable guards/triage keys, the upsert gap) becomes the fixture set; the flag audit turns "we noticed proliferation" into a standing bar every new knob must clear.

## Done looks like

A nontechnical operator on a fresh Chromebook types `lisa init` and it works: history kept if the machine supports it, journal otherwise, one sentence saying which. An old project re-runs init and its `.lisa.toml` gains the new sections as commented, plainly-described stubs with every existing value untouched. A Codex-only machine runs `lisa loop` with zero client config. `lisa notes` on an empty queue says "Nothing to read." Any command run before init names the one command to run. And the knowledge base holds a flag audit where every flag, prompt, and config key either shows its working default or its one-line justification for asking — with a CI-synced config table so no future knob ships undescribed.

## Context & constraints

Grounds against init.rs (offer, upsert, scaffolding), config.rs/types.rs (knob parsing), detect.rs (client detection), doctor.rs/status.rs (announcement surfaces), and the README config table. Sequencing: 0.4.4-rc.1 ships the ask-flag init contract; T-050-01-01 deliberately supersedes it — if it lands before stable 0.4.4, the README and runbook simplify back to bare `lisa init`; either way the RC's flags remain as overrides forever. Any stable-0.4.4 hotfix ticket touching init.rs must serialize with T-050-01-01/T-050-02-01 by dependency edge at minting time (one pair of hands in init.rs). NON-GOALS honored: N2 — deciding is not babysitting; a default that cannot be satisfied still ends in a named, actionable state, never a retry loop; N1 — client detection respects provider differences, it does not flatten them; N4 — each ticket isolates the smallest surface that removes its friction; no init or config rewrite. Hard rule inherited from the stance memory: flags and config stay available for the fintech-grade operator — this epic demotes them from requirements to overrides, it never removes control. Copy on every new line follows the brand voice.

Decomposition artifact rule: children spell the constraints plainly — auto-decisions never modify existing repos, identities, or config values; every decision announces itself in one plain line; asking is justified in writing or eliminated; empty is always a sentence, never a blank.
