## Intent — the bigger-picture play

Field incident, 2026-07-16, hours after v0.4.3 shipped: in the tour-rematch demo, the first ticket finished its work, wrote a valid `pass` disposition — and sat in Review while the completion machinery rejected it **35 consecutive times at diagnosis (80 by the time the journal was preserved)**. Root cause, corrected against the journal rows (2026-07-17 forensic pass): the demo folder had an unborn branch and no git identity, and the fatal step fired *before* identity was ever consulted — the prior-completion-key lookup (`git log --grep` in commit_transaction.rs) exits 128 on a branch with no commits yet and is treated as fatal, when empty history should simply mean "no prior completion". Behind it sits a wall: the commit builder always parents on HEAD, so a repository with zero commits can never complete a ticket at all. The rejection surfaced as `authority Attempt(AttemptLease { … }) (Artifact, exit Some(1))` on a dashboard watched by exactly the audience Lisa courts. A leftover `.lisa-commit.lock` marked where the failed transaction leaked its lock. The guard was right; the stance was wrong. The session already proved the governing principle twice — managed Zellij on Linux, system mode on macOS: **an unconfigured default must never resolve to a requirement the environment cannot satisfy.** Apply it to guards. Completion seals become a declared ladder: **Tier 1, commit-sealed** — today's atomic commit with the completion-key trailer, the full audit chain, unchanged and un-weakened; **Tier 2, journal-sealed** — where git is absent or cannot commit, completion gates on the disposition plus a journal row carrying content-hashes of the ticket and its work artifacts — still fail-closed, still tamper-evident, just not version-controlled; **never a silent nothing** — doctor, status, and every ledger row state which seal is in effect. And the move that keeps Tier 1 the common case without ever saying "git" to a nontechnical user: the Zellij play again — Lisa *brings* history rather than demanding it. `lisa init` in a repo-less folder offers project history in kitchen-table terms (undo, plus a record of what the agents did), creating the repo and a project-local identity itself, touching nothing that already exists. Completion failures that only an operator can fix stop retrying into the void: bounded attempts, then the E-048 park with a plain, forwardable ask. And no completion state may be one an operator cannot leave: the 2026-07-17 forensic pass found that a completion whose 60-second reconciliation deadline expires lands in `Rejected{ActionRequired}` — masked from Done, refusing even operator MarkDone with a hex-laden reason, with no reset path anywhere in the CLI or UI. That dead-end parks and asks like every other operator-owned failure.

## Value to the design

Advances P2 — a completion seal always corresponds to durable reality, the tier is recorded in the ledger so an auditor can never mistake journal-sealed work for commit-sealed work, and a mid-project seal degradation parks loudly instead of silently switching; the 35-rejection churn becomes a parked state with one honest sentence. Advances P4 — the active tier is visible at a glance in doctor and status, and when completion needs a human, the dashboard says what and why in words a bystander can act on. Advances P5 — the stalled demo's completion journal (80 identical rejections, preserved from the field container) becomes the regression fixture; no future release may reproduce that churn.

## Done looks like

In a bare folder with no git anywhere: `lisa init` offers history, a declining user still runs to completion journal-sealed with hash-stamped rows, and doctor says "history: journal-only" in plain words. In the same folder accepting the offer: commits land under a project-local "Lisa (project history)" identity the user never had to configure, and the full Tier 1 chain holds. In a real repo with the operator's own identity: nothing changes from today. With `[guards] completion = "commit"` set explicitly: an unsatisfiable environment is a hard, named failure — the fintech stance, enforced. A completion-commit failure that needs a human parks after bounded attempts with a forwardable ask, the commit lock is always released, and replaying the 2026-07-16 demo journal under the new stance shows: one park, one plain ask, zero churn.

## Context & constraints

Grounds against the completion contract (crates/lisa-core/src/completion.rs, crates/lisa-cli/src/commit_transaction.rs), the journal (crates/lisa-plugin/src/completion_journal.rs), init/doctor surfaces (crates/lisa-cli/src/init.rs, doctor.rs), and E-048's parking/ask machinery, which this epic reuses rather than reinvents. Field evidence: the demo project's completion journal and lock leak, preserved under docs/active/work/T-046-06-03/cbt-0716-211915-variant-xdg/. NON-GOALS honored: Tier 1 is not weakened, renamed, or made harder to choose — it remains the default wherever the environment supports it and the enforced mode for anyone who asks; journal-sealed is a labeled lesser seal, never a synonym for unguarded; no silent tier switches mid-project — degradation is a parked, asked state; no broad scheduler or lease rewrite — the smallest contract is the seal-resolution seam plus the completion-failure path. Copy on every new surface follows the brand voice; "git" appears in operator-facing copy only where the operator already chose git. Right-sized as four stories: the ladder itself (S-049-01), history-that-comes-along (S-049-02), the journal seal (S-049-03), and the incident's park-and-ask fix (S-049-04, deliberately dependency-light so it can land first).

Decomposition artifact rule: children spell constraints plainly — seals are labeled in every record they touch; downgrades park and ask, never switch silently; bounded retries end in a named operator state; existing repos and identities are never modified; enforce-mode failures name the missing requirement and the two-line remedy.
