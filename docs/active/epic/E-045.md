## Intent — the bigger-picture play

Keep the native interactive Codex TUI, but move ownership proof off the fragile UserPromptSubmit hook that today conflates 'bytes written / Enter accepted / turn created / hook dispatched' into one exact acknowledgement. On 2026-07-13, rc.8 regenerated correct recovery assignments for T-014-03-01 and T-015-02-01, yet both exhausted bounded retry into delivery-failed with zero pane signals while their Review artifacts sat untouched — a false failure at the correctness-critical assignment boundary. The play: give each Codex ticket a fresh interactive codex process reached through a short, Lisa-owned launcher; Zellij injects only that launcher, never the full assignment. The launcher builds argv with no shell/composer interpolation and starts codex against a bounded, attempt-tagged reference to an atomically written assignment file. The agent's FIRST action is to claim the exact ticket+attempt+nonce via a Lisa command — that claim, not the hook, is the ownership proof. A matching UserPromptSubmit is treated as supplemental fast evidence; a valid current-attempt private artifact is bounded fallback evidence. Missing hook evidence while the TUI is alive becomes 'delivered-awaiting-claim' and must NOT re-inject the prompt. At the ticket boundary, exit the TUI, revoke the attempt, and launch a clean TUI for the next ticket. This matters now because E-035 closed on stub-acknowledgement tests while its real-Codex review reported Codex-first acceptance unmet — the failure is live and mislabels correct work as failed.

## Value to the design

Realizes a provider-neutral, evidence-tiered assignment/claim contract for Codex that removes the single-point UserPromptSubmit dependency (P3 parity with Claude's mechanism, P2 states matching durable reality). Ownership is asserted by an agent-issued claim under E-034 lease fencing, so 'delivered' and 'owned' stop being conflated, and a slow first turn no longer masquerades as delivery-failure. Closing it on real-Codex + real-Zellij field tests turns the 2026-07-13 incident into durable regression evidence (P5).

## Done looks like

With actual installed Codex and actual Zellij (hooks disabled), starting Lisa into existing Review tickets: each Codex ticket launches a fresh TUI via the Lisa-owned launcher, the agent claims ticket+attempt+nonce as its first action, and that claim alone establishes ownership. A first response slower than the old ack timeout yields 'delivered-awaiting-claim' with NO duplicate prompt injection. A stale/prior-attempt claim is rejected. At the ticket boundary the TUI exits cleanly, the attempt is revoked, and the next ticket launches its own clean TUI — with exactly one authoritative completion per ticket and Claude behavior plus E-034 lease fencing unchanged. Any real-Codex behavior that can't be explained is marked blocking rather than closed.
