## Intent — the bigger-picture play

E-041 delivered a pure, exhaustively-typed completion reducer that provably converges an admitted passing Review on exactly one Done in isolation — but nothing in production calls it yet. The livelock that started this (a Codex attempt wrote a good review.md and stopped, the ticket sat in phase:review, a ~10-min timeout re-injected finish-up over the existing artifact, `[d]one` failed, and only a hand-relaunched `lisa complete-ticket` closed it) is still live in the real scheduler. Two more Arcade tickets then reproduced it simultaneously and exposed the concrete launch defect: the plugin used the nested Lisa project cwd (`arcade/games/midsummer`) as `--path` while passing `docs/...` paths that the isolated Git transaction later interpreted relative to the enclosing Git root (`arcade`). The transaction safely restored Review, but could never stage the intended `games/midsummer/docs/...` paths. The play NOW is convergence: make the reducer the ONE production completion path, normalize completion commands against the discovered Git root, and prove the fix on real hardware. That means (1) folding every scattered `request_completion` entry — artifact/poll, stopped, idle, timeout/reload reconciliation, externally-observed Done, and manual UI — into typed events, with the plugin adapter as the only executor of returned effects and eligibility re-derived level-triggered on every poll and plugin load; (2) making the transaction durable and idempotent so a replay after reload, lost result, duplicate stop, or timeout discovers the prior commit instead of writing a second; (3) reworking `[d]one` into explicit, auditable operator authority that still cannot bypass a blocked Review; and (4) driving the REAL plugin adapter (not just lisa-core) through the recorded hostile ordering and nested-monorepo topology, then through one disposable live Codex-seat field run bound to a freshly rebuilt CLI+WASM. This is deliberately the runtime counterpart to E-041's domain contract — the card that turns a proven-in-a-test-harness reducer into observed field reality.

## Value to the design

Realizes the transition from 'completion contract exists' to 'completion contract IS the production path.' Removing/quarantining the old boolean path so tests prove a single production completion gateway means published Done state corresponds to durable reality with no surviving edge-triggered escape hatch (P2, N3-respecting). A completion-generation/idempotency newtype bound to ticket+attempt, passed to `lisa complete-ticket` over Lisa's existing atomic-publication patterns, makes at-most-one-commit hold across reload/lost-result/duplicate-stop rather than only at compile time (P1). Every named rejection and correlation identity surfaced in the activity/dashboard state, plus `[d]one` as auditable operator authority, lets a supervisor see ownership, obligation, and failure without reverse-engineering panes (P4). And a hostile-order regression against the real adapter plus a live disposable-seat field report turns the original incident into deterministic AND field-observed regression evidence — a real failure closed by a proven lifecycle boundary, not a plausible patch (P5). Claude and Codex clear through the same reducer-backed gateway without an identical handshake being forced (N1).

## Done looks like

There is exactly one production completion gateway: all completion entry points feed typed events into E-041's reducer, the plugin adapter alone executes returned effects, and tests fail if a second boolean completion path resurfaces. The adapter retains both Lisa project root and discovered Git root, sets `complete-ticket --path` to the Git root, and converts ticket/work paths to Git-root-relative paths; a two-level nested-project regression proves the generated Arcade-shaped command selects `games/midsummer/docs/...`, never root-level `docs/...`. Eligibility is re-derived on every poll and plugin load from current-attempt admission plus E-040's pass/block disposition, and an eligible passing Review with neither pending nor confirmed state converges into the transaction. Driven through the real plugin adapter over the recorded T-009-01-01 hostile sequence (private review present before/through Implement→Review, stop during a slot transition, timeout/reload, delayed-or-duplicated command result, attempted `[d]one`), a PASSING Review yields exactly one effect, one completion commit, one authoritative Done row, seat release, and dependent scheduling; a BLOCKED Review yields none. Replaying after reload/lost-result/duplicate-stop converges on the prior commit instead of a second one, and CommandInFlight ends in a named retryable/action-required state under a bounded deadline. `[d]one` always emits explicit OperatorRequested authority (never silently borrowing the attempt lease), still cannot pass a blocked Review, and keeps the modal open or shows durable confirmation until accepted/rejected with named reason + correlation. Review timeout never sends a finish-up prompt when the current Review artifact already exists and completion is pending or has a named actionable rejection. Finally, one isolated disposable live Codex-seat run in a nested monorepo fixture, bound to a freshly rebuilt CLI+embedded WASM, exercises normal artifact completion AND `[d]one` recovery, records correlations/journal/provenance/commit-tree, tears the fixture down, and marks any unexplained behavior BLOCKING; `cargo test --workspace` passes and release WASM stays within budget.

## Context & constraints

Grounds against the lisa-core (pure domain: types/ticket/dag + E-041's completion reducer) vs lisa-plugin (scheduler.rs/ui.rs, the Zellij/WASM effect adapter) split — the adapter, journal wiring, and operator command live in lisa-plugin; the reducer stays untouched domain in lisa-core. PREREQUISITES, not hidden scope: E-041 (the typed reducer + aggregate) must be cleared and merged first — this epic is its runtime consumer, not a re-implementation; and E-040's structured Review pass/block gate and explicit pass disposition remain the eligibility input that operator authority must never bypass. Respects N4 (isolate the completion contract and its adapter/journal; do NOT rewrite the scheduler, commit isolation, or attempt fencing — preserve exact-path isolated commits, attempt fencing, bounded retries, and backward-compatible provenance), N2 (CommandInFlight reconciliation is bounded, carries a correlation ID, and ends in a named actionable state — no infinite retries or silent babysitting), and N1 (no forced identical Claude/Codex handshake). Crate discipline: standard Rust enums/newtypes/exhaustive matches over E-041's reducer; `thiserror` only for typed error display/source; proptest/proptest-state-machine dev-only; NO macro-generated FSM and NO subscriber-only `tracing` island — if structured tracing is evaluated it must adapt into Lisa's existing durable/operator-visible activity model and stay optional, with correctness never depending on a subscriber. Measure release WASM and reject any dependency that materially grows it without demonstrated value. PE-7 / right-sizing: this is materially LARGER than a single ~2-hour feature block — the signal itself names four story-shaped thrusts (A effect-adapter + level-triggered reconciliation, B durable journal + idempotency, C operator-recovery command, D hostile-order regression + live field gate) and corresponds to the (b)–(e) follow-on epics E-041 explicitly deferred. It is pulled deliberately as ONE convergence epic with a final live barrier; splitting it into those four stories (and their tickets) is DecomposeEpic's job, not this card's — this card fixes the intent, invariants, and the single epic-level done-signal (livelock closed end to end, on a live seat, as observable regression evidence). Out of scope: any change to E-041's domain contract, broad scheduler rewrites, and macro-FSM or subscriber-only-tracing approaches.
