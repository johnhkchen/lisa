## Intent — the bigger-picture play

Close the Codex timeout/retry split-brain that T-031-02 exposed. Today, when a Codex execution attempt goes silent and times out, lisa releases the logical slot without terminating or fencing the old process, then may reschedule the same ticket onto a fresh pane. If prompt injection into that replacement misses, the scheduler still records the replacement as assigned while the original pane is free to wake back up, write the ticket's shared artifacts, and appear to complete work under the replacement's scheduler/provenance identity — two panes silently contending for one ticket's identity and outputs. The play is to make ticket execution single-writer per attempt: mint an attempt-scoped lease when a ticket is dispatched, and revoke-and-fence the prior attempt (terminate/disqualify the old pane and invalidate its lease) BEFORE the ticket is handed to any replacement. Every acknowledgement, liveness signal, artifact write, and completion transition must carry and be checked against the current attempt's lease; anything stamped with a stale prior-attempt lease is rejected, cannot advance or complete the replacement, and cannot masquerade as the owner. The system publishes exactly one authoritative outcome/provenance record per ticket. This matters now because the completion-atomicity work (E-031/T-031-02) only guarantees a done transition is durably committed — it does not stop the WRONG attempt from being the one that commits it; without a lease boundary, atomic completion can still atomically record a lie.

## Value to the design

Realizes the single-writer guarantee that makes concurrent, artifact-driven agent work safe under the real failure mode field-caught in T-031-02. Preserves the repository (P1): one attempt's resumed writes can no longer bleed into another attempt's shared artifacts or completion. Makes published state mean what it says (P2): 'assigned', 'owned', and 'done' correspond to the attempt that actually holds the lease, and a fenced attempt's late activity stays visibly stale rather than being relabeled as the replacement's success. Delivers provider parity at the contract boundary (P3): the lease is a scheduler-side ownership fence, equivalent for Claude and Codex from the assignment/liveness/completion/recovery perspective, without forcing Codex through Claude's identical handshake (N1). And it converts a live split-brain into standing regression evidence (P5) by proving the fenced boundary the failure crossed.

## Done looks like

In a deterministic T-031-02-shaped regression (an old attempt that is slow/silent, a timeout, a replacement whose prompt injection misses, then the old pane resuming) plus a fresh-loop live proof, the timed-out attempt is revoked and fenced before its ticket is rescheduled; the resumed old pane's acknowledgements, lifecycle signals, and artifact writes are all rejected as stale prior-attempt activity and cannot advance or complete the replacement; the replacement attempt never completes on the old attempt's artifacts; and each ticket yields exactly one authoritative outcome/provenance record. Observably: no duplicate ownership, no cross-pane artifact attribution, and recovery ends in a bounded, named, actionable state rather than a silent double-assignment. Claude's assignment/completion behavior is unchanged across the same harness, and the reproduction is committed as a regression.

## Context & constraints

Grounds against the T-031-02 field report: automatic completion and slot release currently fire without a per-attempt ownership fence, and the E-068 vend run left Codex tickets in exactly the ambiguous state this epic closes. Boundaries and reuse: PRESERVE, do not duplicate, E-033's acknowledged Codex handoff and its bounded fresh-session fallback — the lease consumes those as the acknowledgement and recovery signals it binds to attempt identity, it does not re-implement a second handshake or a second recovery path (N1, N4). PREREQUISITES (name them as such, not hidden scope): E-031/T-031-01's isolated commit transaction and T-031-02's single completion state machine are the commit boundary the lease check must gate; E-033's positive-acknowledgement handshake is the signal the lease binds. Respects N2: fencing terminates in a bounded named actionable state, never infinite retries or silent babysitting. Respects N4: the smallest contract is the attempt-scoped lease around dispatch/ack/liveness/artifact-write/completion — no broad scheduler rewrite, and the Claude path's behavior is held constant. Out of scope: decomposition into stories/tickets (DecomposeEpic's job), general pane-naming/observability (E-032), and any change to how completion itself is committed beyond gating it on the current lease. Sizing note (PE-7): this is at the upper edge of one ~2-hour feature block — the lease-mint/revoke-fence core is one epic, but if the acknowledgement-binding and the stale-rejection-on-every-signal surfaces each prove large in decomposition, this may warrant splitting into a 'mint + fence' epic and a 'bind + reject stale' epic; flag at decompose time rather than inflating this card.
