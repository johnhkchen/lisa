## Intent — the bigger-picture play

With E-037 (provider-aware bootstrap) landed, the current build is a release candidate that nobody has measured or hardened. This epic is a single, non-destructive tightening pass: first establish reproducible baselines (CLI + embedded WASM size, launch/startup timing where it is deterministically measurable, and honest idle/active memory-footprint observations that do NOT pretend host-process RSS is exact plugin-heap attribution); then get cargo fmt, workspace tests, WASM checks, and clippy clean; then inventory the repetitive scheduler/adapter/harness code and recurring writing patterns and land only the small, well-tested cleanups whose value is actually demonstrated — leaving harmless repetition alone. It closes with a concise release-readiness report and a dogfood of the freshly built CLI/WASM through deterministic local fixtures. The point is a trustworthy 'this is ready' with the numbers to back it, not new behavior.

## Value to the design

Realizes release-readiness as verifiable state rather than assertion: measured before/after baselines and a passing fmt/test/check/clippy gate make the RC's quality correspond to durable reality (P2); the release-readiness report lets an operator see size, timing, footprint, and residual risk at a glance (P4); and turning the measurements + deterministic fixtures into repeatable baselines makes any future regression detectable against recorded evidence (P5). Demonstrated-value-only cleanups improve maintainability without touching stable contracts.

## Done looks like

A concise release-readiness report exists carrying before/after numbers for CLI and embedded-WASM size, startup/launch timing where deterministically measurable, and clearly-caveated idle/active memory observations (no RSS-as-heap overclaim), plus remaining risks and the exact commands to reproduce every measurement. cargo fmt, workspace tests, WASM checks, and clippy all run clean. Only small, individually test-backed cleanups have landed; the repetition deliberately left alone is named in the report. The latest CLI and WASM are rebuilt and dogfooded through deterministic local fixtures with observed results recorded. E-034 lease fencing, E-035 two-stage assignment + dquote recovery, E-037 provider-aware bootstrap, installer ownership safety, and the public CLI surface all still hold — no behavior was changed to hit a number.

## Context & constraints

Grounds against the post-E-037 RC in this repo (lisa-core / lisa-plugin / lisa-cli; WASM embedded into the CLI via build.rs). Prerequisite: E-037 must be landed — it is the RC this pass measures and hardens; do not start against a moving base. Preserve, do not modify: E-034 lease fencing, E-035 two-stage assignment and dquote recovery, E-037 provider-aware bootstrap, installer ownership safety, and the public CLI surface (clap commands). Non-goals honored (N4, N2): no dependency churn, no broad rewrite, no destructive cleanup, no history rewriting, no speculative optimization; recovery/lint work stays bounded and observable. Explicit honesty constraint: memory-footprint numbers must be framed as host-process observations, not exact plugin-heap attribution — an overclaimed or unrepeatable measurement leaves the epic incomplete, as do failing fmt/lints. Right-size caveat (PE-7): the measurement + lint-gate + report + dogfood core is one ~2-hour block; if the repetition inventory surfaces cleanups larger than small demonstrated ones, those are OUT of scope here and should be pulled as their own future epic(s) rather than inflating this card. Decomposition into stories/tickets is DecomposeEpic's job, not this card's.
