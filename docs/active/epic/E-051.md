## Intent — the bigger-picture play

The 0.4.4 release train was seven candidates in a day, and it taught one lesson three ways: a signal that can lie costs more than the defect it hides. `just check` showed green on a tree that CI then failed on a clippy warning — the local gate and the remote gate answer different questions, so agents commit "verified" work that bounces. The `bounded_runner` timeout test failed three separate gate runs on wall-clock pressure alone — the code was right every time, so the humans watching CI learned to retry once, and a retry habit is a hole a real regression walks through. And when native Claude moved to the per-ticket fresh-process boundary (the rc.8 flip that fixed stale ticket identity in reused panes), the scheduler kept its whole in-place `/clear` reuse apparatus — states, timeout fallbacks, delivery arms — now unreachable by any shipped adapter but still reading as live, down to a test asserting "Claude must retain its clear handshake."

This epic makes the three signals truthful again, in the charter's own words: state means what it says (P2), and a real failure becomes a fixture, not a habit (P5). The local gate runs what CI runs. The flaky test fails only when the bounded runner is actually broken. The unreachable machinery is removed once the field record confirms nothing needs it — evidence first, deletion second, per the same discipline that gated the seal ladder.

## Value to the design

Advances P2 — a green `just check` becomes a commitment CI honors, and no scheduler state can be read (by a person or a test) that no code path can reach. Advances P5 — the rc train's two recurring gate failures stop being lore ("retry once, it's just the flake") and become pinned fixtures; the removal ticket is explicitly gated on field evidence from ExitThenFresh legs, so deletion is a conclusion, not a guess.

## Done looks like

An agent runs `just check`, sees green, commits — and CI agrees, clippy included. `cargo test --workspace` under full parallel load passes twenty times in a row with no retry folklore, and a deliberately broken kill path still turns the timeout test red. Nobody reading the scheduler finds a transition state, fallback, or prompt arm that cannot execute; the reuse seam that remains is a documented decision, not leftovers.

## Context & constraints

Grounds against the justfile (`check` recipe), crates/lisa-cli/src/triage_agent.rs (the timing test), and crates/lisa-plugin/src/lib.rs + adapter.rs (the in-place reuse machinery: `TransitionState::WaitingForStop`/`WaitingForClear`, the stop/clear timeout fallbacks in `check_transition_timeouts`, the `/clear` reuse arm in `schedule_ready_tickets`, `handle_cleared_signal`'s prompt delivery). Sequencing: the removal story is deliberately last-in-spirit — its research phase must cite an ExitThenFresh field leg (0.4.4-rc.8 or later, multiple consecutive Claude tickets on one pane, sealed clean) before any deletion; if that evidence does not exist yet, the ticket parks early with a plain note naming the one thing to run, never a jargon wall. NON-GOALS honored: N4 — each ticket isolates its own surface (a recipe line, one test, one machinery family); no scheduler rewrite rides along. N2 — de-flaking must not become auto-retry; the fix makes the test load-immune, not self-forgiving. Hooks that emit `.cleared` stay where a shipped adapter still consumes them.

Decomposition artifact rule: children spell the constraints plainly — negative fixtures prove each gate still catches what it must; every deleted test maps to a successor or to the removed path it covered; field-evidence citations name their source runs.
