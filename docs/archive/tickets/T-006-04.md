## Context

During a live run, the dashboard shows a summary view of threads and activity. But
when diagnosing scheduling stalls or unexpected behavior, we need the full internal
state: every thread entry, every slot assignment, the complete DAG, health statuses,
and the activity log. This state isn't accessible without adding code to dump it.

## Objective

Add a key-triggered state snapshot that writes the plugin's full internal state to a
file. This gives operators a detailed capture they can inspect offline and include in
bug reports.

## Acceptance Criteria

- [ ] Pressing 'd' (dump) writes a state snapshot to `/host/.lisa-state-dump.txt`
- [ ] Snapshot includes: timestamp, config, ticket list with phases, DAG edges, thread entries with statuses, slot assignments, last health check times, recent activity events (last 50)
- [ ] Format is human-readable plain text (not JSON/YAML — optimized for quick scanning)
- [ ] Snapshot overwrites previous dump (single file, not accumulating)
- [ ] Log an `Info` event when snapshot is written ("State snapshot written to .lisa-state-dump.txt")
- [ ] Key event handled in the plugin's `update()` via zellij Key event
- [ ] Tests for snapshot content with known state (threads, slots, DAG)
