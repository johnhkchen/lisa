## Idle-Aware Phase Advancement

### Problem

The plugin polls for artifacts every 5 seconds but has two gaps:
- **Implement → Review**: No artifact triggers this. The agent must edit
  YAML frontmatter, which it never does.
- **Earlier phases**: Artifact detection works but has latency and can
  misfire if the agent writes artifacts in unexpected locations.

### Solution

Add idle signal detection to `poll_tick`. When the plugin sees a
`.lisa/signals/{ticket_id}.idle` file, it knows that ticket's agent just
went idle. Combined with the current phase, this is enough to decide the
next action.

### Phase Advancement Rules

| Current Phase | Idle Signal | Artifact Exists? | Action |
|---|---|---|---|
| Research | yes | yes (`research.md`) | Advance to Design |
| Research | yes | no | Alert: agent idle without artifact |
| Design | yes | yes (`design.md`) | Advance to Structure |
| Structure | yes | yes (`structure.md`) | Advance to Plan |
| Plan | yes | yes (`plan.md`) | Advance to Implement |
| **Implement** | **yes** | **n/a** | **Advance to Review, park thread** |
| Review | yes | n/a | No action (already parked) |

The key insight: for Implement, the idle signal alone IS the completion
signal. The agent finished coding and is waiting — that means it's done.

### Requirements

1. **Signal scanning** — In `poll_tick` (or `check_artifact_advances`),
   scan `.lisa/signals/` for `*.idle` files. Parse ticket ID from filename.

2. **Phase evaluation** — Apply the rules above. For Implement phase,
   advance to Review and park the thread (existing `park_thread` logic).

3. **Signal cleanup** — Delete the signal file after processing to avoid
   re-triggering on the next poll.

4. **Alert on idle-without-artifact** — If the agent goes idle during
   Research/Design/Structure/Plan but the expected artifact doesn't exist,
   add an alert to `state.alerts` so it surfaces in the attention banner.

5. **Coexist with existing detection** — The existing artifact-based
   advancement continues to work. Idle signals are an additional trigger,
   not a replacement.

### Acceptance Criteria

- Implement → Review advances automatically when idle signal detected
- Earlier phases advance when idle signal + artifact both present
- Alert surfaces when idle signal arrives but artifact is missing
- Signal files are cleaned up after processing
- Existing artifact-based detection still works independently
- All existing tests continue to pass
