## Context

The dashboard shows active threads and parked threads, but not the state of
agent slots themselves. Operators can't tell whether slots are idle, occupied,
or how many total slots exist. This makes it impossible to diagnose scheduling
stalls from the UI alone.

## Acceptance Criteria

- `to_ui_state()` includes slot information: total slots, idle count, occupied
  list (ticket_id + pane_id for each occupied slot)
- New `ui::SlotInfo` struct with `pane_id`, `ticket_id: Option<String>`,
  `has_session: bool`
- Dashboard renders a compact "Slots" section (e.g., between status line and
  DAG), showing: `Slots: 2 total, 1 idle, 1 occupied (T-003-01 #5)`
- Status line updated to include slot count: "Slots: 1/2 | Active: 1 | ..."
- When all slots are occupied and ready tickets are waiting, show a yellow
  warning: "N tickets waiting for slots"
- Tests for slot rendering with various states (all idle, all occupied, mixed)

## Files to Modify

- `crates/lisa-plugin/src/lib.rs` — `to_ui_state()` to include slot data
- `crates/lisa-plugin/src/ui.rs` — new SlotInfo type, render_slots section,
  updated status line
