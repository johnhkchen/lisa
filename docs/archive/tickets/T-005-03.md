## Context

`rebuild_dag()` detects phase changes by comparing the current DAG against
`self.last_phases`. But this comparison only fires when the ticket already
has an entry in `last_phases`:

```rust
if let Some(&old_phase) = self.last_phases.get(&ticket.id) {
    if old_phase != ticket.phase {
        changed = true;
    }
}
```

If `last_phases` is empty (first rebuild) or a ticket appears for the first
time, no change is detected. More critically, `poll_tick()` gates slot release
and thread completion inside `if changed { ... }`, so when change detection
fails, slots are never freed and downstream tickets never get scheduled.

## Acceptance Criteria

- `rebuild_dag()` also detects changes when a ticket has NO prior entry in
  `last_phases` but is in a non-default state (e.g., phase != Ready). On
  first load this seeds `last_phases` correctly; on subsequent rebuilds it
  catches tickets that appeared or changed since the snapshot.
- `poll_tick()` unconditionally checks for done tickets and releases slots,
  not just inside `if changed`. The `if changed` block can remain for phase
  sync logging, but the critical "find done tickets → release slots" logic
  must run every tick.
- Add a safety sweep: after scheduling, verify that no slot has a `ticket_id`
  pointing to a ticket that is Done in the DAG. If found, release the slot
  and log a warning ("Slot #{pane_id} held stale ticket {id}, releasing").
- Tests for:
  - First poll with tickets already at phase=done → slots not stuck
  - Ticket transitions to done between polls → detected and released
  - Safety sweep catches stale slot assignment

## Files to Modify

- `crates/lisa-plugin/src/lib.rs` — `rebuild_dag()`, `poll_tick()`, new
  `sweep_stale_slots()` method
