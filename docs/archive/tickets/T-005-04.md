## Context

`schedule_ready_tickets()` skips any ticket that has an entry in
`self.threads`:

```rust
if self.threads.contains_key(&ticket_id) {
    continue;
}
```

But completed threads are never removed from `self.threads` — they stay with
`status: Completed`. If a ticket was incorrectly left as "Running" after its
agent exited (e.g., the phase change detection in T-005-03 failed), the
thread blocks that ticket from ever being rescheduled.

## Acceptance Criteria

- After marking threads as Completed in `poll_tick()`, remove them from
  `self.threads` (or move to a separate `completed_threads` set for history)
- `schedule_ready_tickets()` has a secondary guard: if a thread exists but
  has `status == Completed`, remove it and proceed with scheduling (defensive)
- Failed threads (from `detect_stale_threads()`) are already removed — verify
  this path works and add a test
- Add a periodic thread audit in `poll_tick()`: log warning if any thread's
  ticket_id doesn't match an active (non-done) ticket in the DAG
- Clean up `last_health` entries when threads are removed (already partially
  done in `evaluate_health`, verify coverage)
- Tests for:
  - Completed thread removed, dependent ticket gets scheduled
  - Stale Running thread for a Done ticket gets cleaned up
  - Thread audit detects orphaned thread entries
