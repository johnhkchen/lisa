## Hook Infrastructure for Idle Signal

### Problem

The plugin has no way to know when a Claude Code session finishes its work
and returns to "Awaiting User Input". Phase transitions depend on artifact
detection (fragile) or manual frontmatter editing (never happens).

### Solution

Use Claude Code's `idle_prompt` notification hook to write a signal file
that the plugin can detect.

### Requirements

1. **Hook config generation** — `lisa init` generates (or updates)
   `.claude/settings.local.json` with a `Notification` hook:
   ```json
   {
     "hooks": {
       "Notification": [
         {
           "matcher": "idle_prompt",
           "hooks": [
             {
               "type": "command",
               "command": ".lisa/hooks/on-idle.sh"
             }
           ]
         }
       ]
     }
   }
   ```

2. **Signal script** — `lisa init` generates `.lisa/hooks/on-idle.sh` that:
   - Reads `LISA_TICKET_ID` from environment
   - Writes `.lisa/signals/{ticket_id}.idle` (touch or write timestamp)
   - Exits 0 (non-blocking, observational only)

3. **Env var injection** — Wrap the Claude spawn command so each session
   has `LISA_TICKET_ID` set. Since Zellij's `CommandToRun` has no `env`
   field, spawn through `sh -c "LISA_TICKET_ID={id} claude ..."`.

4. **Gitignore** — Ensure `.lisa/signals/` is in `.gitignore`.

### Acceptance Criteria

- `lisa init` creates `.claude/settings.local.json` with idle_prompt hook
- `lisa init` creates `.lisa/hooks/on-idle.sh` (executable)
- `.lisa/signals/` is gitignored
- Plugin's spawn command sets `LISA_TICKET_ID` env var per session
- Signal script writes correct file when invoked with env var set
