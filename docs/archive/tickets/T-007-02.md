## Context

`lisa validate` currently checks CLAUDE.md existence, ticket parsing, and DAG
validity. But it doesn't check everything needed before `lisa loop`: whether zellij
and claude are installed, whether there's at least one ready ticket, or whether
docs/rdspi-workflow.md exists. The `loop` command has its own prerequisite checks
but they're not accessible as a standalone validation step.

After an LLM follows `lisa setup-guide`, it needs a single command that confirms
everything is ready. `lisa validate` should be that command.

## Objective

Enhance `lisa validate` to be the comprehensive pre-loop readiness check. It should
cover everything `lisa loop` needs so that if `validate` passes, `loop` will start
successfully.

## Acceptance Criteria

- [ ] `lisa validate` checks all of the following:
  - CLAUDE.md exists at project root
  - docs/rdspi-workflow.md exists (error, not just warning)
  - Ticket directory exists and contains at least one .md file
  - All tickets parse without errors
  - DAG is acyclic with no missing dependencies
  - At least one ticket has `phase: ready` and all deps satisfied
  - All tickets have an `## Acceptance Criteria` section (warning)
  - .lisa.toml is valid if present
- [ ] Optional `--check-tools` flag adds tool checks:
  - `zellij` is on PATH
  - `claude` is on PATH
- [ ] Output is grouped: errors first, then warnings, then summary
- [ ] Exit code 0 if no errors, 1 if any errors
- [ ] Summary line at end: "Ready for `lisa loop`" or "N errors must be fixed"
- [ ] Tests for each validation case (missing CLAUDE.md, no ready tickets, etc.)
