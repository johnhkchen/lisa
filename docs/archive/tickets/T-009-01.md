## Bug Sweep and Dead Code Cleanup

### Problems

1. **`--print` in spawn command breaks idle hooks.** The spawn command in
   `scheduler.rs:build_claude_command()` uses `--print`, which runs Claude
   Code in non-interactive mode — it processes the prompt and exits. The
   session never reaches "Awaiting User Input", so the `idle_prompt`
   notification hook (added in S-008) never fires. Sessions must run
   interactively for idle signal detection to work.

2. **Double state transitions in `poll_tick`.** `check_artifact_advances()`
   advances a phase and updates the thread's `current_phase`. Then
   `rebuild_dag()` re-reads the ticket from disk, and the phase sync block
   (lib.rs ~line 818) catches the same change again, resetting
   `last_phase_change` and potentially logging duplicate events. Not harmful
   (idempotent) but sloppy — creates confusing activity log entries.

3. **13 dead code warnings in plugin crate.** Unused constants (`BG_RED`,
   etc.), unused struct fields (`has_session`, `selected_ticket`), unused
   function (`status_indicator`), unused enum variant (`ThreadParked`),
   unused field (`stories_dir`). These clutter build output and signal
   unfinished work to a new contributor.

### Changes

#### 1. Remove `--print` from spawn command
In `scheduler.rs:build_claude_command()`, switch from `--print "prompt"` to
`-p "prompt"` (or `--prompt`) for interactive mode with an initial prompt.
The session will process the prompt and then remain active, reaching
"Awaiting User Input" when done.

Verify: the `sh -c "LISA_TICKET_ID=... claude ..."` wrapper from S-008
still works correctly with the flag change.

#### 2. Fix double state transition
In `poll_tick`, track which tickets were already advanced by
`check_artifact_advances()` and `check_idle_signals()` in the current cycle.
Skip the phase sync block for those tickets. Simplest approach: collect
ticket IDs that were advanced, then check membership in the sync loop.

#### 3. Clean up dead code
Remove or `#[allow(dead_code)]` the 13 warnings. Prefer removal for
genuinely unused code. Use `#[allow]` only for code that's part of a planned
feature (e.g., `stories_dir` if story support is coming).

### Acceptance Criteria

- Spawn command does NOT use `--print`; sessions run interactively
- `build_claude_command` test updated to reflect new flag
- No duplicate phase-change log entries in a single poll cycle
- `cargo check -p lisa-plugin --target wasm32-wasip1` produces zero warnings
  (excluding upstream dependency warnings)
- `cargo test --workspace` passes
