## Context

When the plugin loads in zellij, it silently scans tickets and builds the DAG. If
something goes wrong — tickets don't parse, config is missing, the DAG has issues —
the only signal is that nothing happens. S-005 added scheduling decision logging, but
there's no initial "here's what I loaded" summary.

## Objective

Add a startup diagnostic phase to the plugin's `load()` that logs a clear summary of
what was found and what the plugin plans to do. This gives the operator immediate
confidence (or alarm) that the plugin loaded correctly.

## Acceptance Criteria

- [ ] On load, plugin logs an `Info` event with: ticket count, DAG edge count, ready ticket count, configured max_threads
- [ ] If ticket scan finds parse errors, each is logged as an `Error` event with the filename and error
- [ ] If DAG has cycles, log `Error` with the cycle path
- [ ] If no tickets found, log a clear `Warning` (not silent)
- [ ] Config values are logged: ticket directory, max_threads, commit lock path
- [ ] All diagnostic messages visible in dashboard activity log on first render
- [ ] Tests for: clean load, load with parse errors, load with cycles, load with no tickets
