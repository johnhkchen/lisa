## Context

Setting up a new project for lisa requires reading a 450-line setup guide and
manually creating directories, CLAUDE.md, tickets, and config. The `lisa init`
command scaffolds boilerplate, but the real work — writing a meaningful CLAUDE.md,
creating tickets with good acceptance criteria, and modeling dependencies — needs
intelligence that a template can't provide.

An LLM (e.g., Claude Code) can do this setup if given clear instructions. The
missing piece is a command that outputs those instructions, contextual to the
detected project.

## Objective

Add a `lisa setup-guide` subcommand that detects the project type and outputs
step-by-step LLM-friendly instructions for setting up the project for lisa. The
output should be self-contained — an LLM reading it should be able to set up the
project without any other documentation.

## Acceptance Criteria

- [ ] `lisa setup-guide` subcommand added to clap CLI
- [ ] Detects project type (reuse existing `detect.rs` logic)
- [ ] Outputs to stdout (can be piped or read by an LLM)
- [ ] Guide includes:
  - Directory structure to create (with exact mkdir commands)
  - CLAUDE.md template with detected build/test/lint commands pre-filled
  - RDSPI workflow content (embedded, not "go find this file")
  - .lisa.toml default config
  - Ticket format: required frontmatter fields, body structure, dependency rules
  - Story format: when and how to use stories
  - Dependency modeling rules (the "if two tickets modify the same files" rule)
  - Archiving convention
  - Clear "when done, run `lisa validate`" instruction at the end
- [ ] Guide is structured as numbered steps, not prose documentation
- [ ] Accepts `--path` flag (default: `.`) for project root
- [ ] If `lisa init` has already been run (directories exist), guide skips those steps and focuses on content (tickets, CLAUDE.md content)
- [ ] Tests for guide output with various project types (Rust, Node, unknown)
