## Reliable Phase Transitions via Idle Detection

Phase transitions are the weakest link in the loop. Tickets get stuck in
Implement (no completion signal), Review (requires manual 'd' press), and
sometimes earlier phases when artifact detection misfires. The root cause:
the plugin has no reliable way to know when an agent has finished its current
work.

Claude Code's `idle_prompt` notification hook solves this. When a session
finishes working and returns to "Awaiting User Input", the `Notification`
event fires with type `idle_prompt`. A hook script can write a signal file
that the plugin detects on its next poll, telling it exactly which ticket's
agent just went idle.

This replaces the broken model where agents must edit YAML frontmatter or
the human must notice and press 'd'. Instead: agent goes idle → plugin
detects → phase advances automatically.

**T-008-01 — Hook infrastructure**: Generate the `.claude/settings.local.json`
hook config and signal script during `lisa init`. Wrap the Claude spawn
command to set `LISA_TICKET_ID` env var so the hook knows which ticket the
idle signal belongs to.

**T-008-02 — Idle-aware phase advancement**: Plugin scans for signal files
during `poll_tick`. When an idle signal arrives for a ticket in Implement →
advance to Review. For earlier phases → verify artifact, advance if present.
No artifact → surface alert.

**T-008-03 — Dogfood**: Run lisa on itself with the new idle hooks. Verify
phase transitions fire without manual intervention.
