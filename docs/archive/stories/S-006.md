## Dogfood Integration Testing

Lisa has never been tested end-to-end in a live zellij session with real scheduling
pressure. Sprint 5 added scheduling reliability fixes and observability logging, but
we don't know if the full pipeline actually works: ticket parsing → DAG computation →
session spawning → phase detection → slot release → dependent scheduling.

This sprint adds diagnostic tooling and runs lisa on itself. The goal is not feature
completeness — it's information capture. Every ticket is designed to make the live
run more observable so we can identify what breaks and file targeted bug fixes.

**Track A — CLI Diagnostics** (T-006-01 → T-006-03): Add `lisa status` for offline
DAG inspection, then audit the exact session launch commands the plugin sends.

**Track B — Plugin Diagnostics** (T-006-02 → T-006-04): Add startup diagnostic
logging, then add a runtime state snapshot dump for capturing plugin state mid-run.

DAG for 2-agent concurrency:
```
Wave 1: T-006-01 + T-006-02  (independent, parallel)
Wave 2: T-006-03 + T-006-04  (both unblocked after wave 1)
```
