## Scheduling Observability & Reliability

After running the execution loop on Stories S-001 through S-004, a consistent
pattern emerged: agents complete their ticket work but the plugin fails to
assign new tasks to freed slots. The root causes are (1) phase-change detection
gaps in `rebuild_dag()` that prevent slot release, (2) stale thread entries in
`self.threads` that block rescheduling, and (3) zero logging throughout the
scheduling pipeline making the problem invisible from the dashboard.

This story has two parallel tracks designed for concurrent execution:

**Track A — Observability** (T-005-01 → T-005-02): Add scheduling decision
logging and surface slot status on the dashboard so operators can see exactly
why a ready ticket isn't being scheduled.

**Track B — Reliability** (T-005-03 → T-005-04): Fix the phase-change detection
to always catch done transitions, and clean up completed threads so slots are
properly freed and dependents are scheduled.

DAG for 2-agent concurrency:
```
Wave 1: T-005-01 + T-005-03  (independent, parallel)
Wave 2: T-005-02 + T-005-04  (both unblocked after wave 1)
```
