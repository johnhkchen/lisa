## Module Boundaries

The flake is entirely self-contained. It does not modify any Rust source code, Cargo.toml files, or the justfile. The build steps replicate what the justfile does:

| justfile recipe | flake equivalent |
|---|---|
| `just build` | `preBuild` step in buildPackage |
| `just build-cli` | `cargoBuildCommand` in buildPackage |
| `just test` | `cargoTestCommand` in buildPackage |
| `just check` | `checks.lisa-clippy` + build |
| `just lint` | `checks.lisa-clippy` |
| `just fmt-check` | `checks.lisa-fmt` |

## Key Implementation Details

### Source Filtering

Use `craneLib.cleanCargoSource` to filter the source tree so only Rust-relevant files are included in the derivation. This prevents rebuilds when non-Rust files change. Additionally include:
- `docs/knowledge/rdspi-workflow.md` — embedded via `include_str!` in templates.rs
- `crates/lisa-cli/data/` — contains the rdspi-workflow.md copy used by include_str!

Need to verify the exact path used by `include_str!`. The source says:
```rust
include_str!("../data/rdspi-workflow.md")
```
So `crates/lisa-cli/data/rdspi-workflow.md` must be in the filtered source.

### WASM Build in preBuild

The `preBuild` hook runs before crane's cargo build command:
```bash
cargo build -p lisa-plugin --target wasm32-wasip1 --release
```

This puts the WASM at `target/wasm32-wasip1/release/lisa.wasm`, which is where `build.rs` looks for it. The cargo target directory inside a Nix build is at the default location relative to the workspace root, so no path fixup is needed.

### Runtime Wrapping

```nix
postInstall = ''
  wrapProgram $out/bin/lisa \
    --prefix PATH : ${pkgs.zellij}/bin
'';
```

This ensures `zellij` is found when `lisa loop` runs `exec zellij`, without polluting the user's profile.

### Version Extraction

Read version from `Cargo.toml` workspace section (`0.1.6`) using `craneLib.crateNameFromCargoToml` or hardcode and keep in sync. Prefer reading from Cargo.toml.
