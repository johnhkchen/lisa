# T-016-01 Structure: Create Homebrew tap

## Changes Overview

This ticket involves changes in two repositories and one configuration:
1. **`johnhkchen/lisa`** (this repo) — cargo-dist config + release workflow regeneration
2. **`johnhkchen/homebrew-lisa`** (new repo) — Homebrew tap with formula
3. **GitHub Settings** — PAT secret for cross-repo push

## File Changes in `johnhkchen/lisa`

### Modified: `dist-workspace.toml`
Add Homebrew installer config:
```toml
[dist]
installers = ["shell", "homebrew"]  # was: ["shell"]
tap = "johnhkchen/homebrew-lisa"     # new
formula = "lisa"                      # new (override default "lisa-cli")
publish-jobs = ["homebrew"]           # new
```
All other fields remain unchanged.

### Regenerated: `.github/workflows/release.yml`
Run `dist generate-ci` after updating dist-workspace.toml. This will:
- Add a Homebrew publish job to the release workflow
- The job commits and pushes the generated formula to the tap repo
- Uses `HOMEBREW_TAP_TOKEN` secret for authentication

### Modified: `README.md`
Add Homebrew install option to the Install section, between the shell installer and crates.io sections:
```markdown
### Homebrew (macOS)

```bash
brew install johnhkchen/lisa/lisa
```
```
Keep it minimal — one command. The `brew tap` + `brew install` two-step is equivalent but longer.

## New Repository: `johnhkchen/homebrew-lisa`

### Structure
```
homebrew-lisa/
  README.md              # Brief description of the tap
  Formula/
    lisa.rb              # Generated by cargo-dist on first release
```

### `README.md`
Brief text explaining: this is the Homebrew tap for Lisa, install with `brew install johnhkchen/lisa/lisa`.

### `Formula/lisa.rb`
Initial placeholder or empty — cargo-dist will generate and push the actual formula on the first release. The generated formula will include:
- Per-platform download URLs pointing to GitHub Release archives
- SHA256 checksums
- Platform detection (x86_64 vs aarch64, macOS vs Linux)
- Binary installation

After first generation, manually add:
```ruby
depends_on "zellij"

def caveats
  <<~EOS
    Lisa requires Claude Code to be installed separately.
    See: https://docs.anthropic.com/en/docs/claude-code
  EOS
end
```

## GitHub Configuration

### Secret: `HOMEBREW_TAP_TOKEN`
- Type: Fine-grained Personal Access Token
- Scope: `johnhkchen/homebrew-lisa` repo, `contents: write` permission
- Set as: Repository secret on `johnhkchen/lisa`
- Used by: The Homebrew publish job in release.yml

## Module Boundaries

No Rust code changes. This is purely infrastructure:
- dist-workspace.toml (cargo-dist config)
- release.yml (CI workflow, auto-generated)
- README.md (documentation)
- External tap repo (GitHub)

## Ordering

1. Create `homebrew-lisa` repo on GitHub (must exist before CI tries to push)
2. Update dist-workspace.toml with Homebrew config
3. Regenerate release.yml with `dist generate-ci`
4. Create PAT and add as secret
5. Tag and release to trigger the workflow
6. After first formula generation, add zellij dep + Claude Code caveat
