## cargo-dist Homebrew Support

### Built-in Homebrew Installer
cargo-dist has first-class Homebrew support. Key facts:
- `"homebrew"` is a valid installer type in the `installers` array
- cargo-dist generates a Ruby formula from a built-in template
- Formula handles multi-architecture (x86_64/aarch64, macOS/Linux)
- Includes SHA256 checksums, platform detection, binary installation
- Used by cargo-dist itself: `installers = ["shell", "powershell", "npm", "homebrew"]`

### Configuration Required
Two additions to `dist-workspace.toml`:
1. Add `"homebrew"` to `installers` array
2. Set `tap = "johnhkchen/homebrew-tap"` (or `homebrew-lisa`)
3. Add `publish-jobs = ["homebrew"]` for CI automation
4. Optional: `formula = "lisa"` to override default name (defaults to package name `lisa-cli`)

### Tap Repository Convention
- Must be named with `homebrew-` prefix: `johnhkchen/homebrew-lisa` or `johnhkchen/homebrew-tap`
- Contains a `Formula/` directory with `.rb` formula files
- The ticket says `johnhkchen/homebrew-lisa` — this maps to `brew tap johnhkchen/lisa`
- cargo-dist's own tap is `axodotdev/homebrew-tap` → `brew install axodotdev/tap/<name>`

### Tap Naming Impact on User Experience
- Repo `homebrew-lisa` → `brew tap johnhkchen/lisa` → `brew install johnhkchen/lisa/lisa`
- Repo `homebrew-tap` → `brew tap johnhkchen/tap` → `brew install johnhkchen/tap/lisa`
- The ticket specifies `brew tap johnhkchen/lisa` which requires repo name `homebrew-lisa`

### Formula Generation
cargo-dist generates the formula automatically during CI:
- Per-architecture download URLs and SHA256 checksums
- Platform detection using `Hardware::CPU` and `OS`
- Binary installation to Homebrew's `bin` directory
- License metadata (MIT → `:mit` in Ruby)
- Only publishes for stable (non-prerelease) versions by default

### CI Automation
When `"homebrew"` is in `publish-jobs`:
- The release CI commits and pushes the generated formula to the tap repo
- Requires a GitHub token with write access to the tap repository
- For cross-repo pushes, a Personal Access Token (PAT) or fine-grained token is needed
- The default `GITHUB_TOKEN` only has access to the current repo

## Zellij Dependency

### Homebrew Dependency Declaration
- Zellij is available in Homebrew core: `brew install zellij`
- Can declare with `depends_on "zellij"` in the formula
- cargo-dist may or may not detect this automatically — likely needs manual addition
- If using cargo-dist's auto-generated formula, may need post-generation customization

### Claude Code Dependency
- Claude Code is NOT in Homebrew — cannot be expressed as `depends_on`
- Ticket says: "Claude Code can't be expressed as a Homebrew dependency — add a caveat instead"
- Homebrew supports `caveats` blocks in formulas for this purpose
