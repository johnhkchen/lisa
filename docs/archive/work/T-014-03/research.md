### Workflow Jobs

The release workflow has 5 jobs:
1. **plan** — runs `dist plan` or `dist host --steps=create`, outputs manifest
2. **build-local-artifacts** — matrix build across 4 targets, injects WASM build via build-setup.yml
3. **build-global-artifacts** — generates installer script, checksums
4. **host** — uploads artifacts, creates GitHub Release
5. **announce** — post-release step (currently no-op)

### PR Run Mode

The workflow also runs on `pull_request` events in plan-only mode — this means we can test the plan step via a PR without needing a tag.

### What Needs Testing

1. **Tag trigger** — Push a `v0.2.0-rc.1` tag, verify workflow triggers
2. **WASM build in CI** — The build-setup.yml injects WASM compilation before the dist build. This is the riskiest part — if the WASM binary isn't available when `build.rs` runs, the CLI build will fail
3. **Cross-platform matrix** — All 4 targets must build successfully
4. **Artifact packaging** — Archives contain the `lisa` binary, not `lisa-cli`
5. **Installer script** — Platform detection, download, install to `~/.cargo/bin/`
6. **Checksums** — SHA256 files present and valid
7. **GitHub Release** — Created with correct title, prerelease flag for RC tags

### Constraints

- This is a chore ticket — the work is verification, not code changes
- We're testing infrastructure, so failures are expected and informative
- The prerelease tag (`-rc.1`) ensures the release is marked as prerelease on GitHub
- We should not bump the workspace version for this test — use a prerelease suffix instead
- Testing the installer requires the release to actually exist on GitHub

### Risk Areas

1. **WASM build ordering** — `build.rs` expects the WASM binary at a specific path. The build-setup steps run before `dist build`, but the paths may differ from local builds
2. **aarch64-linux cross-compilation** — This target typically uses a container with cross-compilation tools. Container availability and Rust toolchain setup are potential failure points
3. **Binary naming** — cargo-dist should produce a binary named `lisa` (from `[[bin]] name = "lisa"`), not `lisa-cli`
4. **First release ever** — No prior release exists, so `latest` download URLs won't work until the first non-prerelease is published
