# T-014-01 Structure: Integrate cargo-dist

## Files Created

### `dist-workspace.toml` (repo root)

cargo-dist workspace configuration. Key sections:

```toml
[workspace]
members = ["cargo:."]

[dist]
cargo-dist-version = "0.30.4"
ci = "github"
installers = ["shell"]
targets = [
    "x86_64-apple-darwin",
    "aarch64-apple-darwin",
    "x86_64-unknown-linux-gnu",
    "aarch64-unknown-linux-gnu",
]
packages = ["lisa-cli"]
github-build-setup = ".github/build-setup.yml"
install-path = "CARGO_HOME"
```

### `.github/build-setup.yml`

Custom steps injected before `dist build` in CI. Two steps:

1. `rustup target add wasm32-wasip1` — Ensure WASM target is available
2. `cargo build -p lisa-plugin --target wasm32-wasip1 --release` — Build the WASM plugin

This file is NOT a workflow — it's a YAML fragment referenced by the generated workflow.

### `.github/workflows/release.yml` (replaced)

cargo-dist generates this entirely. We do not write it manually. Generated by running `cargo dist generate-ci` (or `cargo dist init`). Contains:

- plan, build-local-artifacts, build-global-artifacts, host, publish, announce jobs
- Triggered on version tags and PRs (plan-only mode)

## Files Modified

### `Cargo.toml` (workspace root)

Add after `[profile.release]`:

```toml
[profile.dist]
inherits = "release"
```

No need to specify `lto` — inherits `lto = true` from release profile. The `[profile.dist]` section is how cargo-dist detects that the project has been initialized.

## Files Removed

### `.github/workflows/release.yml` (old version)

The hand-rolled workflow is replaced by the cargo-dist generated one. Back it up first (move to `.github/workflows/release.yml.bak`), then let `cargo dist generate-ci` overwrite.

## Module Boundaries

No new Rust modules. This ticket is entirely CI/config infrastructure. The only Rust-visible change is the new `[profile.dist]` in Cargo.toml, which Cargo uses automatically when `--profile dist` is specified.

## Ordering

1. Create `.github/build-setup.yml` first (no dependencies)
2. Add `[profile.dist]` to `Cargo.toml` (no dependencies)
3. Create `dist-workspace.toml` (no dependencies)
4. Back up old `release.yml`
5. Generate new `release.yml` via `cargo dist generate-ci`
6. Verify with `cargo dist plan`

Steps 1-3 can happen in any order. Steps 4-5 must be sequential.
