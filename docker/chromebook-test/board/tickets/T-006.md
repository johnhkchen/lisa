## Context

Write a short, plain-language "how it works" section. Per the T-002 brief,
this is where the page can start to sketch the actual mechanism (breaking
work into tracked steps, running it without hand-holding every action,
producing a reviewable trail) but still without naming internal protocol
terms or workflow phase names as if the visitor already knows them. Deeper
technical explanation is explicitly out of scope for this page (see S-001
non-goals) and belongs in linked docs, not here.

## Acceptance Criteria

- The section explains the mechanism in 3-5 short steps or beats, each in
  a sentence or two, understandable to someone who has never used a coding
  agent.
- No step uses unexplained internal terminology (protocol/phase names,
  DAG, git sealing, Zellij) — if a concept from those needs to appear, it is
  described functionally ("it keeps a record you can check," not "the
  completion journal").
- Section includes a link or pointer to where a more technical reader can
  go for the full workflow detail, consistent with T-003's "for the
  curious" marker.
- Copy is reviewed against T-003's outline to confirm it does not overlap
  with T-005 (benefits) or T-007 (FAQ/trust).
