## Context

With the audience and bottom-line message defined in T-002, decide the
page's section order and purpose for each section. The ordering itself is
the deliverable: bottom-line-first means the visitor's core question ("why
would I, a non-technical person building something, want this?") is answered
before anything else, and every section after that either builds trust or
answers the next most likely question — never introduces protocol detail
before the visitor has a reason to care.

## Acceptance Criteria

- A written outline lists each planned section in order, with: its purpose,
  the one question it answers for the visitor, and which part of the T-002
  brief it draws from.
- The outline places all deferred technical detail (workflow phases, DAG
  scheduling, git sealing, CLI commands) at or below a clearly marked
  "for the curious / more technical" point, never above it.
- Each section in the outline has a single owning ticket (T-004 through
  T-007) referenced by name, so copy work can proceed in parallel without
  overlap.
- The outline is reviewed against the T-002 bottom-line message: the
  first section must directly state or restate that message in plain
  language.
