## Context

Write the copy for the "why this matters to your project" section that
follows the hero. This section carries the supporting reasons from T-002's
brief — control, not babysitting every step, not losing work, working
alongside tools the visitor may already use — translated into benefits
stated from the visitor's point of view, not Lisa's internals.

## Acceptance Criteria

- Each supporting reason from the T-002 brief has a corresponding benefit
  statement, written as an outcome for the visitor (what changes for them),
  not a description of a mechanism.
- No benefit statement requires the reader to already know what an "agent,"
  "ticket," or "coding session" is — each stands on its own or defines the
  term inline in plain language on first use.
- Copy is reviewed against T-003's outline to confirm section placement and
  that it does not overlap with T-006 (how it works) or T-007 (FAQ/trust).
- At least one benefit directly addresses a likely worry for a non-technical
  builder (e.g., "what if it breaks something" / "what if I can't undo it"),
  matching a concern identified in the T-002 brief.
